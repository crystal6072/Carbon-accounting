# 报告生成业务 PRD（报告管理 · 报告编制）

> **【模块归属声明 · 2026-10-14】**：报告生成（产品碳足迹报告）归属「**前台业务平台 · 报告管理**」分组，子项名为「**报告编制**」，与「企业信息维护 / 敏感性分析 / 数据质量评价」并列；菜单与路由 `/report/prepare`。本模块**不改变核算主链**——核算项目步骤①~④、报告管理其它子项均为**只读引用**。
>
> **【核心口径声明 · 本版最高优先，全文适用】**：本模块报告**零人工编辑（唯一例外 = 企业信息）**。报告正文的**每一个字符都来自两类来源**：① **前序环节数据自动装配**（核算项目 / 敏感性分析 / 数据质量评价 / 企业信息维护 / 产品主数据）；② **模板固定文案**（标准条款、说明性文字、评分依据）。报告正文**不提供任何输入框 / 富文本编辑 / 图片上传**；**企业信息（封面报告主体 / 基本信息表企业名称·地址 / 表 1 生产者信息）读取『企业信息维护』并允许编辑、缺失允许现场录入**（R-104 例外）。与旧版《06生成报告/报告生成业务PRD》的「封面可补充 + 说明性章节可编辑」口径**相反**，冲突处以本文为准。
>
> **【编制页交互声明 · 2026-10-19，全文优先】**：
> 1. **报告信息不展示**：报告管理与运行字段（报告编号 / 模板 / 来源项目 / 状态 / 下载文件名等）**不在编制页平铺**；仅在面包屑与副标题保留「报告编号」作为系统内部标识（不打印，见 R-106）。
> 2. **封面与概况系统自动取值**：封面与概况信息（产品名称 / 规格 / 报告生成 / 核算周期 / 系统边界 / 生命周期边界 / 报告单位 / 标准依据 / 结论等）由系统按核算数据自动取值生成，**不在编制页提供手动录入**。
> 3. **仅保留企业信息可编辑**：编制页仅保留「企业信息」卡片（生产者名称 / 企业地址 / 统一社会信用代码 / 法定代表人 / 联系方式），可编辑 / 可补录（R-104 例外）。
> 4. **两步向导**：「编制中」报告详情页采用 **两步向导**——① 企业信息补充 ② 预览与生成报告（R-126）。
> 5. **报告日期自动**：报告日期由系统在「生成正式报告」时**自动取生成当日**，不手动填写（R-129）。
> 6. **底部冻结操作栏**：编制页与查看页均使用底部冻结操作栏（返回 / 上一步 / 下一步 / 生成；查看页：返回 / 重新生成 / 下载 / 查看报告），与「数据质量评价」页交互一致（R-130）。
>
> **【模板声明 · 2026-10-14】**：本模块报告版式依据业务提供的《**ZB13002 整竹砧板碳足迹评价报告.docx**》（口径：`ISO 14067:2018` / `GB/T 24067-2024` / `LY/T 3436-2025 竹木产品碳足迹评价指南`）转换为系统模板，结构见《报告模板定义（ZB13002 整竹砧板 V1）》。**旧模板（系统预置 V1 · 六章 GB/T 24067 结构）作废**。
>
> **【文档定位】**：报告生成模块的**业务规则真相源**，定义报告对象、生成准入、装配规则、状态机、动作矩阵、预览 / 下载口径、数据缺口依赖与验收标准。章节结构、变量、表格与数据映射见《报告模板定义（ZB13002 整竹砧板 V1）》，页面控件见《报告生成_Demo》（V0.2），字段表见《报告生成字段清单》（V0.2）。
>

## 1. 需求概述

### 1.1 需求背景

核算主链产出的是**结构化的结果数据**（总量 / 四口径 / 阶段 / 数据项 / 明细），它可查询、可导出表格，但**不是一份可以对外披露的标准文件**。客户、采购方、第三方核查方要的是一份**版式固定、内容可追溯、依据标准声明**的产品碳足迹报告。

```text
核算项目（步骤④ 已核算，结果版本 v_n）
    ├── 项目 / 产品信息
    ├── 核算结果
    ├── 敏感性分析
    ├── 数据质量评价
    └── 企业信息（报告管理 · 企业信息维护）
                ↓ 只读引用（不修改上游）
        报告（报告管理 · 报告编制）
            └── 按模板 `ZB13002` 装配 = 封面 + 基本信息表 + 目录 + 一~七章 + 附录
                ↓ 编制中：两步向导（①企业信息补充 ②预览与生成报告）
                ↓ 查看态：只读 + 查看报告（Drawer 全屏预览）/ 下载（docx）
```

**没有这一步，核算数据只是"内部表格"，无法形成可对外披露、可追溯、符合标准披露项的标准报告。**

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :-: | :--- | :--- |

## 2. 用户与使用场景

| 场景ID | 场景 | 类型 | 说明 |

## 4. 核心业务规则

> 编号承接数据质量评价业务 PRD（R-083 ~ R-100），本模块从 **R-101** 起。R-101~R-124 沿用 V0.3，**新增 R-125~R-131** 承接编制页交互重构。

| 规则ID | 规则 | 依据 |
| :--- | :--- | :--- |
| R-101 | **[创建准入]** 仅「**已核算**」的核算项目可作为报告数据来源 | 核算 PRD R-042 |
| R-102 | **[生成准入]** 生成报告须同时满足：① 项目「已核算」且存在核算结果版本；② 核算结果**无未处置阻断项**；③ 存在可用报告模板。任一不满足 → 不可用并给出人话原因。**企业信息不作为准入阻断项**（R-104） | 方案 §5.5 |
| R-103 | **[阻断即不生成]** 存在未处置阻断项时不产出报告，**直接阻断**并提示先完成核算 | 本版核心口径 |
| R-104 | **[零人工编辑（企业信息例外）]** 报告正文**不提供任何编辑入口**；内容 = 上游数据装配 + 模板固定文案。**唯一例外 = 企业信息**：读取『企业信息维护』并**允许编辑**；无记录 / 字段缺失时允许**现场录入** | 本版核心口径 |
| R-105 | **[单一版本 / 重新生成覆盖]** 报告不设多版本；「重新生成」**直接覆盖**当前报告正文（含结论），不保留历史报告；覆盖后回到「编制中」 | 对齐敏感性 / 数据质量口径 |
| R-106 | **[报告编号]** 系统内部标识按 `PCF-R-YYYYMMDDNNN` 生成，全局唯一、只读；**默认不在报告正文打印**（面包屑/副标题保留展示，仅作内部标识） | 沿用旧规则 |
| R-107 | **[模板固定]** 本期仅系统预置 **1 个**模板（`ZB13002 V1`） | 模板定义 §1 |
| R-108 | **[装配来源唯一]** 报告每个字段必须可追溯到唯一上游来源；缺来源时按「空值 / 未开展 / 待补录」呈现，**除企业信息外不允许用户补录** | 模板定义 §6 |
| R-109 | **[口径一致]** 报告结果值、单位、阶段划分、四口径取值与**核算结果页面完全一致** | 核算 PRD R-060 |
| R-110 | **[加载时快照]** 生成报告时对上游数据**取快照装配**，生成后不再随上游自动改写；上游变化按 R-114 转「待更新」 | 对齐敏感性 R-068 |
| R-111 | **[数据质量评价章留白]** 报告「六、数据质量评价」与「附录」：存在对应单时装配结论；**不存在时输出「本项目未开展数据质量评价」** | 数据质量 PRD |
| R-112 | **[敏感性分析章留白]** 报告「五、敏感性分析」：存在时装配情景与变化率；**不存在时输出「本项目未开展敏感性分析」** | 敏感性 PRD |
| R-113 | **[无碳储量 / 无分配原则]** 报告模板**不含**「干基含水率 / 含碳率 / 碳储量 / 净碳储量」字段与「分配原则」章节 | 业务裁定 |
| R-114 | **[上游变更即待更新]** 报告「已生成」后，上游发生以下任一变化 → 转「**待更新**」：① 核算新结果版本；② 关联敏感性更新；③ 关联数据质量更新；④ 企业信息更新。可「重新生成」同步 | 对齐敏感性 R-078 |
| R-115 | **[关联口径]** 报告与敏感性 / 数据质量的关联 = **同一核算项目**下**最近一次**单；多单时取最近一份 | 敏感性 / 数据质量 PRD |
| R-116 | **[下载不受状态限制]** 「查看 / 下载」仅在「已生成」或「待更新」时可用 | 对齐敏感性 Q4 |
| R-117 | **[下载文件名]** `{产品名称}_产品碳足迹报告_{YYYYMMDD}.docx` | 沿用旧规则 |
| R-118 | **[不污染主链]** 报告的生成 / 重新生成 / 删除**均不写回**核算项目与其它子项 | 骨架 §2 |
| R-119 | **[权限]** 核算人员可创建 / 生成 / 重新生成 / 删除本组织报告；组织管理员只读；跨组织不可见 | 《角色可见范围 v1.0》 |
| R-120 | **[删除边界]** 删除报告需二次确认 | 对齐骨架 S-006 |
| R-121 | **[生成失败]** 生成异常 → 提示失败，不产出半成品 | 方案 §5.2 |
| R-122 | **[概念不外露]** 界面不出现公式 DSL、因子绑定、计算引擎、快照、异常编号 | 骨架 S-007 |
| R-123 | **[图 2 占位]** 图 2 本期渲染**占位区** | 沿用旧裁定 |
| R-124 | **[模板作废]** 旧版《06生成报告/报告生成业务PRD》的「模板可选 / 章节装配可编辑 / 封面补充 / 确认完成锁定」口径**全部作废** | 本文声明 |
| **R-125** | **[编制中草稿]** 新增报告**直接创建「编制中」（`reportEditing`）草稿**，系统自动继承上游字段（产品 / 封面概况），不单独呈现「生成中」过渡态（`reportGenerating` 保留于类型但本期不进入主流程） | V0.4 裁定 |
| **R-126** | **[两步向导]** 「编制中」报告详情页采用**两步向导**：① **企业信息补充**（可编辑 / 可补录）② **预览与生成报告**（内联只读预览）；步骤间可回退，下一步前校验企业信息必填项（生产者名称） | V0.4 裁定 |
| **R-127** | **[报告信息不展示]** 报告管理与运行字段（报告编号 / 模板 / 来源项目 / 状态 / 下载文件名等）**不在编制页平铺**；仅面包屑与副标题保留「报告编号」作为系统内部标识（不打印，见 R-106） | V0.4 裁定 |
| **R-128** | **[封面概况自动取值]** 封面与概况信息（产品名称 / 规格 / 报告生成 / 核算周期 / 系统边界 / 生命周期边界 / 报告单位 / 标准依据 / 结论等）由系统按核算数据**自动取值生成**，**不在编制页提供手动录入**（编制页仅保留「企业信息」） | V0.4 裁定 |
| **R-129** | **[报告日期自动]** 报告日期由系统在「生成正式报告」时**自动取生成当日**（`YYYY-MM-DD`），不手动填写；预览与正式报告封面均按此取值 | V0.4 裁定 |
| **R-130** | **[底部冻结操作栏]** 编制页与查看页均采用**底部冻结操作栏**（编制中：返回 / 上一步 / 下一步：预览与生成 / 生成正式报告；查看态：返回 / 重新生成 / 下载 / 查看报告），与「数据质量评价」页交互一致 | V0.4 裁定 |
| **R-131** | **[企业信息库引用]** 编制页步骤①支持「从企业信息库引用」（`Select` + 引用按钮）：选中『企业信息维护』记录后自动带入企业字段，引用后仍可继续手动修改，仅影响本报告（R-104 例外）；未引用则显「未引用企业信息库」 | V0.4 裁定 |

## 5. 状态与动作

### 5.1 报告状态流转

```mermaid
stateDiagram-v2
    [*] --> 编制中: 新增报告（选已核算项目）→ 创建草稿
    编制中 --> 已生成: 生成正式报告（报告日期自动取生成当日）
    已生成 --> 待更新: 上游变更（核算新版本 / 敏感性 / 数据质量 / 企业信息）
    待更新 --> 编制中: 重新生成（覆盖，回到编制态补录）
    已生成 --> [*]: 删除报告
    待更新 --> [*]: 删除报告
```

> **报告状态**（`reportEditing / reportReady / reportStale`）为本模块内部口径；`reportGenerating` 保留于类型（预留），本期新增报告**直接落「编制中」**，不单独呈现生成中过渡态。

### 5.2 报告状态 → 界面表现

| 报告状态 | 列表文案 | 详情页表现 | 可执行动作 |
| :--- | :--- | :--- | :--- |
| `reportEditing`（编制中） | 编制中（黄点） | **两步向导**：① 企业信息补充（引用/补录）② 预览与生成报告；顶部 Alert「编制中草稿：请补充企业信息，再预览并生成正式报告」 | 下一步 / 生成正式报告 / 返回 |
| `reportReady`（已生成） | 已生成（绿点） | 只读「企业信息」卡 + 「查看报告」Drawer 预览 + 动作区 | 查看报告 / 下载 / 重新生成 / 返回 |
| `reportStale`（待更新） | 待更新（橙点） | 顶部 Alert「上游数据已更新…」+ 原报告只读 | 查看报告 / 下载 / 重新生成 / 返回 |

> **列表排序**：默认按「报告生成时间」倒序（编制中草稿按创建时间参与排序）。

### 5.3 动作能力矩阵

| 动作 | 编制中 | 已生成 | 待更新 | 只读角色（`?mode=view`） |
| :--- | :-: | :-: | :-: | :-: |
| 生成正式报告 | ✅（步骤②） | ❌ | ❌ | ❌ |
| 重新生成（覆盖 → 编制中） | ❌ | ✅ | ✅ | ❌ |
| 查看报告 | ❌（走内联预览） | ✅ | ✅ | ✅ |
| 下载 | ❌ | ✅ | ✅ | ✅ |
| 删除报告 | ✅ | ✅ | ✅ | ❌ |

> **红线**：不可用动作直接不展示，不渲染 disabled 假入口。
> **无编辑动作**：矩阵中**不存在**任何「编辑正文 / 补充信息 / 保存」动作（R-104）；企业信息编辑仅在「编制中」步骤①进行。

## 6. 报告生成规则

### 6.1 生成准入清单

| # | 准入条件 | 不满足时的表现 |
| :-: | :--- | :--- |
| 1 | 项目状态 = 「已核算」，存在核算结果版本 | 「生成报告」不可用，提示「请先完成核算」 |
| 2 | 核算结果无未处置阻断项 | 「生成报告」不可用，提示「核算存在未处置问题，暂不可生成报告」（R-103） |
| 3 | 存在可用报告模板 | 「生成报告」不可用，提示「暂无可用报告模板」 |

> **企业信息不作为准入阻断项**：读取『企业信息维护』（允许编辑）；无记录 / 字段缺失时允许现场录入，报告相应位置先显「未引用企业信息库 / 待补录」（R-104 / R-131）。

### 6.2 创建草稿与编制流程

```text
报告管理 → 报告编制 →「新增报告」
  ① 选择「已核算」核算项目（弹窗，仅列已核算项目）
  ② 生成准入校验（§6.1）→ 通过
  ③ 创建「编制中（reportEditing）」草稿：
       · 生成报告编号 PCF-R-YYYYMMDDNNN（内部标识，不打印）
       · 快照上游数据（项目 / 产品 / 核算结果 / 敏感性 / 数据质量 / 企业信息）
       · 按模板 ZB13002 V1 装配正文（封面 + 基本信息表 + 目录 + 一~七章 + 附录）
       · 封面与概况自动取值；报告日期暂置空（于「生成正式报告」时取生成当日）
       · 提示「报告草稿已创建，请完善企业信息后生成正式报告」
  ④ 进入详情页「两步向导」：
       步骤① 企业信息补充
           - 从企业信息库引用（Select + 引用）或现场编辑 5 个企业字段
           - 校验生产者名称必填 → 「下一步：预览与生成」
       步骤② 预览与生成报告
           - 内联只读预览（按草稿封面装配，报告日期 = 生成当日预览值）
           - 「生成正式报告」→ 报告日期自动取生成当日 → 置「已生成（reportReady）」
```

## 9. 边界与异常处理

| 场景 | 系统行为 |
| :--- | :--- |
| 未核算即新增报告 | 选择列表不含该项目；无已核算项目时提示「暂无可生成报告的核算项目，请先完成核算」 |

| 来源核算项目被删除 | 报告保留（快照），「核算项目」链接置灰标注「来源已删除」；可查看 / 下载 / 但不可重新生成 |

## 12. 附录

### 12.1 对象结构（概要）

> 完整字段表见《报告生成字段清单》（V0.2），本节仅给对象关系。

```text
报告（PcfFootprintReport） 1
   ├── 1 封面与基本信息（ReportCover）        ← 企业信息（可编辑）+ 系统自动取值（封面概况）
   ├── N 报告章节（ReportSection）              ← 封面 / 基本信息表 / 目录 / 一~七章 / 附录
   │        ├── N 报告表格（ReportTable） ← 表 1~表 12
   │        └── N 报告图（ReportFigure）  ← 图 1 产品图片 / 图 2 分布图（占位）
   └── 1 装配快照（ReportSnapshot）      ← 生成时锁定的上游数据快照
```
