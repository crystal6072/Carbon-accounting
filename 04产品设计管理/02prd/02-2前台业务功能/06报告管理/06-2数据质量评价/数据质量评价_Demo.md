# 数据质量评价_Demo（报告管理）

> **文档定位**：数据质量评价前端原型的输入文档，聚焦页面结构、控件类型、交互行为与 Mock 规格。
> **字段定义**：枚举、必填性、字段级约束见《数据质量评价字段清单》，本文件只写页面呈现规则，**不重复定义**。
> **业务规则**：状态机、动作矩阵、DQR 计算口径见《数据质量评价业务PRD》§4（R-083 ~ R-100）、§6。
> **UI 框架**：**tdesign-react**（腾讯 TDesign React 版），见 §一「技术接入方案」（与《敏感性分析_Demo》V0.2 同框架）。
> **版本**：V0.1 | 2026-10-14
> **落地位置**：原型 `/report/quality`（列表）、`/report/quality/:id`（详情 · 三步向导）；替换 `App.tsx` `PLACEHOLDERS` 中的 `report/quality` 占位配置。

> **【布局口径声明 · 2026-10-14】**：本模块**保留竞品的「① 定性 → ② 定量 → ③ 结果」三步向导形态**（业务 PRD 明确要求对齐竞品），但**控件全部 tdesign 化**（`t-steps` / `t-table` / `t-textarea` / `t-radio-group` 等），不复用 `pcf-*` 私有样式类。与《敏感性分析_Demo》V0.2 的差异：敏感性分析脱离竞品布局改标准列表页，本模块因业务要求保留向导布局。

## 一、技术接入方案（tdesign-react）

### 1.1 依赖引入

原型当前**未引入任何 UI 组件库**（`package.json` 仅 react / react-dom / react-router-dom）。若《敏感性分析_Demo》为 tdesign 首个落地模块，本模块**复用同一依赖**，无需重复接入：

```bash
npm i tdesign-react@^1.18.3 tdesign-icons-react
```

| 项 | 内容 |
| :--- | :--- |
| `tdesign-react` | React 组件库（Stable 1.18.x，**兼容 React 18**，与项目 `react@^18.3.1` 匹配） |
| `tdesign-icons-react` | 官方图标库 |
| 样式引入 | `import 'tdesign-react/es/style/index.css'`（在 `main.tsx` 一次性引入） |
| 全局 reset | `import 'tdesign-react/dist/reset.css'`（按需引入，避免影响既有页面盒模型） |

### 1.2 主题与既有设计令牌的关系

| 项 | 方案 |
| :--- | :--- |
| 主色 | `ConfigProvider` 注入主题令牌，与现有 `design-tokens` 主色对齐（竞品截图主色为青绿 `#00b4a0` 系） |
| 既有 `pcf-*` 私有类 | **本模块不复用**；容器统一由 tdesign `Card` / `Descriptions` / `Table` 承载 |
| 混用约束 | 新旧模块样式隔离（tdesign `t-` 前缀命名空间，不与 `pcf-` 冲突） |
| 暗色 / 响应式 | 本期不做（跟随现有约定） |

### 1.3 本模块使用的 tdesign 组件清单

| 用途 | 组件 |
| :--- | :--- |
| 容器 | `Card`、`Descriptions` / `DescriptionsItem`、`Divider`、`Space` |
| 步骤 | `Steps` / `Step`（三步向导，`theme="dot"` 或默认） |
| 表单 | `Form`、`FormItem`、`Input`、`Textarea`、`Select`、`RadioGroup` / `Radio`（五维评分） |
| 数据 | `Table`、`BaseTable`（展开行）、`Pagination`、`Tag`、`Statistic`、`Progress`、`Empty`、`Tooltip` |

| 操作 | `Button`、`Link` |

| 图标 | `tdesign-icons-react`（`ChevronLeftIcon` / `ChevronRightIcon` / `EditIcon` / `DeleteIcon` / `DownloadIcon` 等） |

## 二、页面概述

| 页面 | 路由 / 容器 | 页面目标 | 页面模式 |
| :--- | :--- | :--- | :--- |
| 数据质量评价列表 | `/report/quality` | 定位评价单、查看状态、新增 / 删除评价 | 标准列表页（筛选表单 + 表格 + 分页） |
| 数据质量评价详情 | `/report/quality/:id` | 三步向导：定性 → 定量 → 结果 | 单页（步骤条 + 步骤内容区 + 底部操作栏） |
| 新增数据质量评价 | 列表页内弹窗 | 选择「已核算」项目创建评价 | `Dialog` |

**主流程**

```text
列表页 ──「新增数据质量评价」──▶ 选择已核算项目 ──▶ 详情页（步骤① 定性，自动初稿）
                                                        │
                    编辑 / 复核三项覆盖范围 ──「下一步」──▶ 步骤② 定量
                                                        │
                    批量评估 / 单项评分 ──「下一步」──▶ 步骤③ 结果（整体 DQR + 分布 + 结论）
                                                        │
                                             「导出结果」/「上一步」改分重算
```

**批量评估**

| 项 | 规格 |
| :--- | :--- |
| 触发 | 步骤② 右上方「批量评估」 |
| 行为 | 按默认启发式口径（业务 PRD §6.4）为全部数据项生成五维初值；`scoreSource = batch` |
| 已有评分 | 若无任何评分 → 直接执行；若已存在评分 → `Dialog` 二次确认「将覆盖全部已评分项，确认重新批量评估？」，确认后覆盖 |
| 反馈 | `MessagePlugin.success('已批量评估 {N} 项数据')`；表格 `dqrCell` 全部刷新 |

> **「下一步」前置**：全部数据项已评分；否则阻断并 `MessagePlugin.warning('还有 {N} 项数据未评估')`，定位首个未评行。进入步骤③ 后生成结果（`status` 按 C08 派生为「已完成」）。

```text
│ 按阶段分布                        │ 按数据项分布（DQR 降序）                  │

│ 能源        DQR 1.4 · 贡献 38%    │ 原竹 DQR 1.6 良 · 贡献 62%               │
├──────────────────────────────────┴──────────────────────────────────────────┤
│ 结论（可编辑，选填）                                                          │
│ [数据质量整体为「良」，不确定度主要来自「胶水」的因子背景数据（技术相关性偏低）。] │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 五、校验与错误展示

| 检查 | 触发时机 | 失败反馈 |
| :--- | :--- | :--- |
| 未选核算项目创建 | 弹窗确定 | 「确定」保持不可点 + 表单级提示「请选择核算项目」 |
| 无已核算项目 | 打开新增弹窗 | `Select` 禁用 + `Alert` 提示 |
| 步骤② 存在未评分项 | 点「下一步」 | 阻断 + `MessagePlugin.warning('还有 {N} 项数据未评估')`，定位首个未评行 |
| 批量评估覆盖 | 已有评分时点「批量评估」 | `Dialog` 二次确认；取消则不覆盖 |
| 评分取值 | `RadioGroup` 单选 1–5 | 组件天然限制，无自由输入 |
| 总排放为 0 | 步骤③ 生成结果 | 整体 DQR 按算术平均，`Tooltip`「清单合计排放为 0，按算术平均计算」 |
| 贡献率为 0 的数据项 | 步骤③ 分布 | 明细正常展示，标注「贡献 0%」，不参与加权 |
| 评价不存在 | 加载详情 | `MessagePlugin.error('数据质量评价不存在或已被删除')` → 返回列表 |
| 并发编辑冲突 | 保存评分 | `MessagePlugin.error('评价单已被他人更新，请刷新后重试')` |
| 来源已删除 | 更新基准 | 按钮禁用 + `Tooltip`「来源核算项目已删除，无法更新基准」 |

> 校验策略：**DQR 计算由服务端（mock）执行**，前端负责字段级校验与渲染；状态不允许的操作由 mock 抛错、前端 `MessagePlugin.error` 兜底。

### 6.2 计算逻辑（mock）

| 项 | 规格 |
| :--- | :--- |
| 输入 | 评价数据项（含五维评分）+ 各数据项贡献率 |
| 单项 DQR | `(reliability + completeness + temporal + geographical + technological) / 5`，保留 1 位小数 → 按业务 PRD §6.2 映射等级 |
| 单项不确定度 | `sqrt(Σ u_dim(s)²)`；无因子时仅取活动数据三维 |
| 整体 DQR | `Σ(contribution × dqr)`；`Σcontribution = 0` 时退化为算术平均 |
| 整体不确定度 | `sqrt(Σ(contribution × uncertainty)²)` |
| 分布 | `levelDistribution` / `stageDistribution`（贡献率加权）/ `itemDistribution`（DQR 降序）/ `categoryDistribution` / `keySources` |
| 定性初稿 | 由数据清单的统计时间 + 因子库 + 因子 `region` 去重拼接生成 |
| 版本失效 | mock 内为某项目提供「重新核算」触发点，用于演示状态转「待更新」 |
