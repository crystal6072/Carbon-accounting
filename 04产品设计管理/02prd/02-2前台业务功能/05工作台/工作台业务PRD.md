## 1. 需求概述

### 1.1 需求背景

工作台是前台业务平台的**落地页与总览屏**：用户登录进入系统后第一眼看到的内容。它不承载业务操作，只回答三个问题：

```text
① 最近算得怎么样 → 碳排放总览（最近一个已完成核算的产品碳足迹 + 各阶段构成）
② 还有什么没算   → 核算进度（待计算 / 已计算统计 + 最新待核算项目待办「去完成」）
③ 组织家底有多少 → 组织统计（已计算 / 产品 / 报告数量）+ 碳足迹概览（最近项目卡片）
```

**设计定位（2026-10-12 重设计，脱离竞品形态）**：不做「功能入口平铺 + 步骤引导横幅」的竞品形态，改为「**一个深色主块讲结论（碳排放总览）+ 两组轻量统计讲进度与家底**」的叙述结构；创建入口从工作台移除，统一收敛到「产品碳足迹核算」列表。

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :-: | :--- | :--- |
| G1 | **一屏讲清最近成果** | 首屏直接看到「最近一个已完成核算」的产品名称、碳足迹大数（kgCO₂e）、核算时间与各阶段构成条形图，无需任何点击 |
| G2 | **待办一键直达** | 待核算项目以「去完成」待办卡呈现，点击进入该项目工作台当前步骤 |
| G3 | **组织资产一屏盘点** | 已计算数量 / 产品数量 / 报告数量三项统计同屏呈现 |
| G4 | **概念不外露** | 全页不出现公式、因子、异常编号（E01–E16）、工程态术语、JSON 字段名 |
| G5 | **空态有引导** | 无数据时空态文案指明去处（如「去『产品碳足迹核算』新增」），不出现白屏 |
| G6 | **加载有反馈** | 页面级加载态：数值位显示 `-`、文案区显示「加载中…」 |

## 2. 用户与使用场景

| 场景ID | 场景 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| S01 | 登录进入工作台 | **主流程** | 登录后默认跳转 `/dashboard`；并行拉取项目列表、我的产品库、当前用户组织，随后逐项目拉取最近核算结果 |
| S02 | 查看最近核算成果 | **主流程** | 碳排放总览展示「最近一个已完成核算」：产品名称、碳足迹大数（kgCO₂e）、核算时间、各阶段构成条形图（阶段名 / 排放值 / 占比） |
| S03 | 继续待核算项目 | **主流程** | 核算进度卡内待办：最近更新的待计算态项目（名称 + 状态 Tag + 行业 · 边界 · 更新时间），点「去完成」→ `/pcf/project/:id` 落在项目当前步骤 |
| S04 | 进入任一项目 | 支线 | 碳足迹概览卡片点击 → `/pcf/project/:id`；卡片展示产品名称 / 核算主体 / 所属行业 / 创建人 / 碳足迹值 |
| S05 | 组织资产盘点 | 支线 | 组织统计卡：已计算数量 / 产品数量 / 报告数量（标题为当前组织名） |
| S06 | 空态浏览 | 辅助 | 新组织无任何数据：总览空态、待办空态、概览空态（引导去「产品碳足迹核算」新增）、报告空态依次呈现 |
| S07 | 加载中浏览 | 辅助 | 首屏并行请求期间：统计数值显示 `-`，总览 / 待办文案区显示「加载中…」 |

```text
   ├─ Promise.all([fetchPcfProjects(), fetchMyProducts(), fetchPcfCurrentUserOrg()])   ← 并行
   └─ 逐项目 Promise.all(projectList.map(fetchPcfCalcResult))                          ← 并行（取最近一次核算结果）
        └─ setResults(pairs.filter(非空)) → 渲染（总览取「最近已完成」+ 概览卡片共用）
```

## 5. 数据统计口径

### 5.1 项目状态分群（与《核算项目业务 PRD》§5.1 严格一致）

| 分群 | 状态枚举 | 工作台用途 |
| :--- | :--- | :--- |
| **待计算组** | `new` 新建 / `ongoing` 进行中 / `checking` 检测中 / `toCalc` 待核算 / `calculating` 核算中 / `calcFailed` 核算失败 | 「待计算产品」统计 + 待办选取范围 |
| **已计算组** | `calculated` 已核算 | 「已计算产品 / 已计算数量」统计 + 总览选取范围 |
| **报告组（历史保留）** | `reportGenerating` / `reportEditing` / `done` | 仅「报告数量」统计兼容；V0.8 起工作流不再产生 |

### 5.2 统计量定义

| 统计量 | 定义 | 口径编号 |
| :--- | :--- | :--- |
| 待计算产品数 | 项目列表中状态 ∈ 待计算组的条数 | C01 |
| 已计算产品数 | 项目列表中状态 = `calculated` 的条数 | C02 |
| 报告数量 | 项目列表中状态 ∈ 报告组（历史保留）的条数 | C03 |
| 产品数量 | 「我的产品库」列表长度（组织自建 + 引用平台产品） | C04 |
| 碳排放总览记录 | 状态 = `calculated` 且存在核算结果的项目中，按 `calculatedAt` 倒序取第一条 | C05 |
| 待办项目 | 项目列表（按 `updatedAt` 倒序）中首个待计算组项目 | C06 |
| 概览卡片集合 | 项目列表（按 `updatedAt` 倒序）前 3 条 | C07 |
| 数值格式化 | `formatEmission`：空 / 非有限值 → `-`；否则保留最多 4 位小数并去尾零 | C08 |

> **排序依赖**：`fetchPcfProjects()` 返回即按 `updatedAt` 倒序，工作台不再二次排序（总览按 `calculatedAt` 单独排序）。

## 6. 核心业务规则

| 规则ID | 规则 | 依据 |
| :--- | :--- | :--- |
| R-001 | **[总览取数]** 碳排放总览仅展示**最近一个已完成核算**（`status = 'calculated'` 且 `fetchPcfCalcResult` 非空）的项目，按 `calculatedAt` 倒序取第一条；无则展示空态 | 原型（C05） |
| R-002 | **[待计算口径]** 「待计算产品」统计覆盖 6 个非终态（new / ongoing / checking / toCalc / calculating / calcFailed），**不含** `calculated` 与历史报告态 | 原型（C01）/ 字段清单 §6 |
| R-003 | **[报告口径]** 「报告数量」仅统计历史报告三态（reportGenerating / reportEditing / done），为兼容保留；V0.8 起核算流程不再产生报告态，该统计在干净数据下恒为 0 | 原型（C03）/ 类型注释 |
| R-004 | **[待办取数]** 待办卡取「最近更新的待计算态项目」——项目列表已按 `updatedAt` 倒序，直接取首个命中待计算组者；无则空态 | 原型（C06） |
| R-005 | **[概览取数]** 碳足迹概览固定展示最近 3 个项目卡片（按 `updatedAt` 倒序）；每卡展示该项目最新版本结果的 `unitEmission`，无结果时数值显示 `-` | 原型（C07） |
| R-006 | **[数值格式]** 所有排放数值统一走 `formatEmission`：`null` / `undefined` / 非有限值 → `-`；否则 `Number(value.toFixed(4))` 转字符串（最多 4 位小数、去尾零，小量级不丢有效数字） | 原型（C08） |
| R-007 | **[条形口径]** 阶段条填充宽度 = `emission > 0 ? Math.max(ratio, 2) : 0`（%）；数值列展示 `formatEmission(emission)` + `ratio.toFixed(1)%` | 原型 |
| R-008 | **[无创建入口]** 工作台**不提供**「新增核算 / 新增产品模型」等创建入口（2026-10-12 重设计移除）；创建统一走「产品碳足迹核算」列表，概览空态文案负责引导 | 原型重设计结论 |
| R-009 | **[导航收敛]** 工作台所有可点元素（待办卡 / 概览卡片）统一跳转 `/pcf/project/{id}`，由项目工作台按 `currentStep` 落在当前步骤；不产生其他路由 | 原型 / App.tsx |
| R-010 | **[组织口径]** 欢迎语与组织统计卡标题取**当前登录用户所属组织**（`fetchPcfCurrentUserOrg`），不由用户手选；组织名为空时欢迎语显示 `—`、卡片标题兜底「我的组织」 | 原型 / 方案 §3.3.4 |
| R-011 | **[概念不外露]** 工作台不展示公式、因子、异常编号（E01–E16）、工程态术语、字段名（英文 / 下划线形式一律不得出现） | 《角色可见范围 v1.0》§3 |
| R-012 | **[单位书写]** 总览主块单位书写为 `kgCO₂e`，概览卡片单位书写为 `kg CO2-Eq`——同一口径的两种界面书写，以原型为准，不做统一改写 | 原型 |

## 7. 边界与异常处理

### 7.1 空态矩阵

| 场景 | 表现 |
| :--- | :--- |
| 无已完成核算（有待计算项目） | 总览主块虚线空态：「暂无已完成核算的产品，完成首次核算后展示碳足迹与阶段构成」；进度 / 概览正常展示 |
| 无任何核算项目 | 总览空态 + 待办空态「暂无待核算项目」+ 概览空态「暂无核算记录，去『产品碳足迹核算』新增」 |
| 项目无核算结果 | 概览卡片数值显示 `-`（`fetchPcfCalcResult` 返回 null） |
| 我的产品库为空 | 组织统计「产品数量」= 0（不展示空态文案） |
| 报告区块 | 任何数据条件下均为固定空态「暂无数据」 |
| 项目名 / 产品名缺失 | 卡片取 `productName \|\| name`；仍为空按空串渲染 |
| 行业缺失 | 待办元信息显示「未填行业」 |
| 组织名缺失 | 欢迎语 `—`；统计卡标题「我的组织」 |

### 7.2 加载与异常

| 场景 | 处理方式 |
| :--- | :--- |
| 首屏加载 | `loading = true`：统计数值 `-`，总览 / 待办文案区「加载中…」 |
| 请求失败 | **原型当前未处理**（无 error 分支与重试）——列入待确认 Q05，建议补错误态 + 重试 |
| 慢请求 | mock `request` 带 80–120ms 延迟模拟；无骨架屏，以「加载中…」文案覆盖 |
| 组织数据域 | 原型 mock 未模拟数据权限过滤；后端应按 `ownerOrg` = 当前用户组织过滤（见字段清单 D02） |
