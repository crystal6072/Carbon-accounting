## 一、页面概述

| 项目 | 内容 |
| :--- | :--- |
| 页面名称 | 碳足迹核算与结果（步骤④ 内容区） |
| 页面目标 | 执行核算、查看状态、失败重试；核算完成即在同页查看总量 / 阶段 / 工序 / 排放源结果并导出 |

**步骤④ 骨架结构（合并后单页）**

```text
① 核算说明（计算口径简介）
② 核算状态卡（待核算 / 核算中 / 完成 / 失败 四态）+ 执行动作
```

## 二、区域与控件规格（合并后单页）

> 2.1 ~ 2.3 为「执行区」，2.4 ~ 2.8 为「结果区」，同属步骤④ `/pcf/project/{id}/4` 页面。

### 2.1 核算说明

| 项目 | 规格 |
| :--- | :--- |
| 位置 | 内容区顶部（浅色提示条） |
| 内容 | 系统将按工序绑定的公式，对已填报的活动数据与匹配的排放因子进行计算，汇总生成总碳足迹、阶段 / 工序 / 排放源结果；核算完成后可查看结果并导出 |
| 样式 | 复用 `.pcf-form-tip`（浅色说明条） |

### 2.2 核算状态卡

| 项目 | 规格 |
| :--- | :--- |
| 容器 | 卡片（`card` 内嵌，或复用 `.pcf-panel`） |
| 内容 | 状态图标 + 文案 + 动作按钮 |

**四态规格**

| 状态 | 图标 / 配色 | 文案 | 动作 |
| :--- | :--- | :--- | :--- |
| 待核算（idle） | 灰 | 尚未执行核算 | `开始核算`（Primary） |
| 核算中（calculating） | 蓝（loading） | 核算中… | 无（按钮禁用 / 隐藏） |
| 完成（done） | 绿（success） | 核算完成 | 无跳转按钮（结果区在本页下方直接展开；导出见 2.4） |
| 失败（failed） | 红（error） | 核算失败 | `重新核算`（Primary） |

> **红线**：不可用的动作直接不渲染（不展示 disabled 假入口）。核算中仅保留「核算中…」的禁用按钮表达进行中；只读态（报告生成中及之后）不渲染任何核算执行按钮。

### 2.3 页头动作（工作台摘要条右侧）

| 元素 | 规格 |
| :--- | :--- |
| 可核算态 | `开始核算` / `重新核算`（Primary，由步骤④内容区状态卡承载，工作台摘要条不重复渲染） |
| 只读态 | 不渲染核算按钮 |

> 步骤④的核算动作按钮**落在内容区状态卡**；`导出结果` 落在内容区结果总览卡（2.4）。工作台摘要条右侧保持「返回」通用动作（本步骤无需「保存」）。

### 2.4 结果总览卡

> 结果区渲染条件：存在结果版本即渲染（含只读回看）；无结果时结果区整体以空态占位。
> 结果版本与当前项目数据不一致时（如已核算后修改了步骤①②数据），总览卡追加 `历史版本` Tag 提示需重新核算。

| 项目 | 规格 |
| :--- | :--- |
| 容器 | 卡片（结果高亮卡，浅绿背景） |
| 内容 | 单位产品碳足迹（大数字 + 单位 `kgCO₂e / 功能单位`）+ **口径切换（含生物碳净值 / 不含生物碳）** + 总排放量 + 结果单位 + 核算时间 + 版本号 |
| 口径切换 | **仅当结果含生物碳（`biogenicEmission ≠ 0`）时展示**；切换只改变大数字（含生物碳净值 ↔ 不含生物碳），并附「含生物碳 / 不含生物碳 / 生物碳净额」三行 meta；不含生物碳的项目不展示切换，等同单一口径 |
| 导出 | 「导出结果」导出明细（列含双口径，见 §五） |

```text
┌─────────────────────────────────────────────┐
│ 单位产品碳足迹   [含生物碳净值] [不含生物碳]   │  ← 口径切换（含生物碳时才显示）
│ 3.47  kgCO₂e / 双                            │
│ 含生物碳净值 3.47 · 不含生物碳 3.62 · 生物碳净额 -0.15  kgCO₂e/双
│ 总排放量 34,700 kgCO₂e · 核算时间 2026-09-13 10:15 · 结果版本 V3 │
└─────────────────────────────────────────────┘
```

## 四、校验与错误展示

| 检查 | 触发时机 | 失败反馈 |
| :--- | :--- | :--- |
| 状态不可核算 | 开始核算 | Toast：「当前状态不可核算」（服务端兜底） |
| 无填报数据 | 开始核算 | 前置检测已阻断，正常不可进入；兜底 Toast「请先完成数据填报与检测」 |
| 核算执行异常 | 开始核算 | 状态卡转「核算失败」，展示「重新核算」 |
| 项目不存在 | 加载结果 | Toast：「项目不存在或已被删除」 |

> 校验策略：**核算逻辑由服务端（mock）执行**，前端仅渲染返回的核算状态 / 结果；状态不可核算时 mock 抛错，前端 Toast 兜底。

## 五、Mock 数据规格

| 要求 | 说明 |
| :--- | :--- |
| 结果来源 | mock 提供 `fetchPcfCalcResult(projectId)` / `startPcfCalc(projectId)` / `resumePcfCalc(projectId)` / `exportPcfResult(projectId)` |
| 异步推进 | 项目处于「核算中」时，进入步骤④ 即调用 `resumePcfCalc` 模拟服务端异步完成（约 2s 后转为「已核算」并在同页展开结果） |
| 核算逻辑 | `startPcfCalc` 真实遍历项目活动数据（`pcfActivityStore`）+ 工序（`pcfOperationStore`）+ 公式（`calcFormulaStore`）做简化核算：单行排放 = `Π(活动量) × Π(常量) × 因子值`，逐工序 → 逐阶段 → 排放源 → 汇总；**双口径**：生物碳分量按 `gwpBiogenic` 用同一行级公式单独求值，结果输出 `totalEmission` / `fossilEmission` / `biogenicEmission` |
| 常量解析 | 公式 `constant` 因素的 value 支持 `"44/12"` 简单表达式（按 `/` 分割做除法）；其余 `parseFloat` |
| 结果版本 | 每次核算 `version` 递增，旧版本保留（store 内累积），界面仅展示最近版本 |
| 导出 | `exportPcfResult` 生成 CSV（结果明细，**列含「排放量 / 其中生物碳 / 不含生物碳」双口径**），触发浏览器下载（Blob） |
| 演示数据预置 | 为 PJ04 / PJ05 / PJ06 预置「已填报」的活动数据（活动量取工序流的基准数量、排放来源按数据项匹配因子、多产出工序分配比例补 100%），使核算可直接产出多维结果；PJ06 为项目内自定义产品，额外预置项目级自定义工序（模拟步骤② 手工新增），其余项目仍按填报流程留空 |
| 样本覆盖 | PJ04（`toCalc`，step4）：橡木实木餐桌，核算后含「生产 / 运输与交付」2 阶段、4 工序、材料 / 能源 / 废弃物 / 运输 4 类排放源（约 32.98 kgCO₂e / 件）；PJ05（`calculating`，step4）：进入后约 2s 自动完成核算（约 0.369 kgCO₂e / 个）；PJ06（`calcFailed`，step4）：「重新核算」可成功（约 2.12 kgCO₂e / 套）；PJ07（`calculated`，step4）：预置 V3 结果，并保留 V1 / V2 历史版本 |
| 数据要求 | 全部虚构演示数据 |
