## 0. 设计概要

### 0.1 为什么是三张表

台账的字段分三类：

| 字段类别 | 特征 | 落位 |
| :--- | :--- | :--- |
| **公共字段** | 5 种能源类型都有、含义与口径完全一致（工序、日期、能源类型、消耗量、单位、录入方式、备注） | **表一：主表** `process_energy_ledger` |
| **扩展字段** | 只在某一种能源类型下出现，字段集随能源类型变化（如电的电压等级、蒸汽的压力等级、柴油的设备编号） | **表二：扩展表** `process_energy_ledger_ext` |
| **附件** | 一条台账可挂 0–10 个数据凭证，与能源类型无关、可增删排序 | **表三：附件子表** `process_energy_ledger_attachment` |

**关键约束**：扩展字段采用**行式（EAV）**存储，一条扩展字段值 = 扩展表的一行，**不采用 `ext_json` 单列**。

| 方案 | 判断 | 理由 |
| :--- | :---: | :--- |
| 主表 + 扩展值表（行式） | **采用** | 可按字段检索（如"所有 10kV 用电记录"）、可加字段级约束与索引、可做字段级审计；与《租户管理字段清单》扩展档案的既有范式一致 |
| 主表 + `ext_json` 单列 | 不采用 | 无法建索引与唯一约束、字段级校验只能写进应用层、口径漂移后无法用 SQL 追溯 |
| 按能源类型拆 5 张子表 | 不采用 | 台账是**统一列表 / 统一导入 / 统一统计**的形态，拆表会导致列表查询要 UNION 5 次，且新增能源类型要改表结构 |
| 附件存主表（JSON 数组 / 逗号串） | 不采用 | 无法分页、无法按文件名检索、无法单附件软删与审计 |

### 0.2 三表的职责边界

```text
加工能耗台账（process_energy_ledger）              单据主体：1 条 = 1 次工序能耗填报
├── 扩展属性（process_energy_ledger_ext）          1:N，按能源类型写入差异字段；0 条也是合法状态
└── 附件（process_energy_ledger_attachment）       1:N，数据凭证；0–10 个，与能源类型无关

扩展字段的定义（field_code / 名称 / 类型 / 单位 / 适用能源类型）
└── 系统内置常量，落在本文档 §6 + 前端 energyLedgerMeta 常量表，不单独建定义表
    （若后续要求"字段集可由平台配置"，再引入 process_energy_field_def，见 Q05）
```

### 0.3 核心设计取舍

| 取舍 | 结论 | 说明 |
| :--- | :--- | :--- |
| 单位是否可编辑 | **只读**，由能源类型自动带出 | 台账是"事后统计"，单位口径必须统一到因子可匹配的基准；允许自由填单位会让 `kgCO₂e` 算不出来 |
| 扩展字段是否必填 | **条件必填** | 必填性跟随能源类型与同类型内其他字段的取值（如"是否绿电=是"才要求绿电交易量），见 §5.2 |
| 切换能源类型时旧扩展值 | **清空并要求二次确认** | 避免"电的电压等级"残留在蒸汽记录里（脏数据无法被 §5.1 的映射矩阵校验拦下） |
| 扩展字段口径变更 | 引入 `ext_version` | 扩展字段集变化后，旧记录仍按其版本解释，避免口径漂移污染历史台账 |
| 工序取值 | **自由文本（已确认 2026-10-30）** | 不做工序库外键；用归一化规则（D09）防止"干燥 / 干燥工序 / 干燥 "分裂成三个工序。后续若接入工序库，`process_name` 可直接作为映射回填依据 |
| 能源类型口径 | **5 品名（已确认 2026-10-30）** | 电 / 蒸汽 / 天然气 / 水 / 柴油；与能源库的"类别"口径通过映射表关联，不合并 |
| 附件承载方式 | **独立子表（已确认 2026-10-30）** | 一记录多附件，支持按类型分组、排序、单附件软删 |

| 规则类型 | 规则 |
| :--- | :--- |
| 行数 | 无强制行数；实际行数 = 该能源类型下的必填字段数 + 已填选填字段数 |
| 唯一/重复 | 同一 `ledger_id` 下 `field_code` 唯一（D06），重复写入走 upsert |

### 5.2 条件必填规则

| 规则ID | 触发条件 | 结果 |
| :--- | :--- | :--- |
| R-01 | `energy_type = 电` 且 `is_green_power = 是` | `green_power_amount` 变为**必填**，且必须 ≤ `consumption_amount` |
| R-02 | `energy_type = 电` | `grid_region` 默认取 `org_id` 所在区域并**置为必填**；组织区域为空时降级为选填并提示"请补充供电区域，否则无法匹配电网因子" |
| R-03 | `energy_type` 发生变更 | ① `unit` 立即按 §5.4 重带出；② 旧能源类型的扩展字段**清空（物理删除）**；③ 弹二次确认"切换能源类型将清空已填写的扩展信息"；④ `consumption_amount` 与附件**保留不清空** |
| R-04 | `energy_type = 蒸汽` 且 `steam_source = 自产锅炉` | `boiler_fuel_type` 变为**必填**；`supplier_name` 隐藏 |
| R-05 | `energy_type = 蒸汽` 且 `steam_source = 外购蒸汽` | `supplier_name` 变为**必填**；`boiler_fuel_type` 隐藏 |
| R-06 | `energy_type = 水` 且 `water_source = 自来水` | `supplier_name` 变为**必填** |
| R-07 | `energy_type = 天然气` 且 `lhv` 有值 | `lhv_source` 变为**必填**（默认带出"默认值"） |
| R-08 | `reading_start` 与 `reading_end` 均已填 | 自动计算 `consumption_amount = reading_end - reading_start` 并**置灰只读**；两者任一清空则恢复手工可填 |
| R-09 | `reading_end < reading_start` | 阻断提交，提示"期末读数不得小于期初读数（可能存在换表）"；如确为换表，需清空读数改用直接填报 |
| R-10 | `entry_method = 系统导入` | `process_name` / `energy_type` / `consumption_amount` / `unit` 只读（导入值不可改），需修改须改为"手工录入" |
| R-11 | `energy_type = 柴油` 且 `combustion_type = 移动燃烧` | `equipment_no` 变为**必填**（移动源需可追溯到车辆/设备） |

### 5.3 联动时序

```text
用户选择 energy_type
  ├─ ① 计算 unit（§5.4 映射表），写入只读字段
  ├─ ② 销毁扩展字段区（清空旧值 + 二次确认，R-03）
  ├─ ③ 按 §5.1 矩阵重建扩展字段区，按 §5.2 计算各字段必填性
  └─ ④ 带出默认值（grid_region ← 组织区域；lhv ← 因子库默认值；is_green_power ← 否）
     ※ 附件区不参与本时序，切换能源类型不重绘、不清空

用户修改扩展字段
  ├─ 命中级联规则（R-01 / R-04 / R-05 / R-06 / R-07 / R-11）→ 重算下游字段显隐与必填
  └─ 命中读数规则（R-08）→ 回写 consumption_amount
```

### 5.4 能源类型 → 单位自动带出

| 能源类型 | 默认单位 | 允许单位 | 说明 |
| :--- | :--- | :--- | :--- |
| 电 | `kWh` | `kWh`、`MWh` | 选 `MWh` 时表单提示"将按 1 MWh = 1000 kWh 折算后参与核算" |

> 方言基线：MySQL 8.0 / PostgreSQL 14 公共子集。PG 需将 `tinyint` → `smallint`、`datetime` → `timestamp`，并为枚举列加 `CHECK` 约束。

```sql
-- 表一：加工能耗台账主表
CREATE TABLE process_energy_ledger (
  id                  BIGINT        NOT NULL AUTO_INCREMENT,
  tenant_id           BIGINT        NOT NULL,
  org_id              BIGINT        NOT NULL,
  project_id          BIGINT        NULL,
  ledger_no           VARCHAR(32)   NOT NULL,
  process_name        VARCHAR(64)   NOT NULL,
  record_date         DATE          NOT NULL,
  energy_type         VARCHAR(16)   NOT NULL,
  consumption_amount  DECIMAL(18,4) NOT NULL,
  unit                VARCHAR(16)   NOT NULL,
  entry_method        VARCHAR(16)   NOT NULL DEFAULT 'manual',
  remark              VARCHAR(500)  NULL,
  ext_version         SMALLINT      NOT NULL DEFAULT 1,
  is_deleted          TINYINT       NOT NULL DEFAULT 0,
  created_by          BIGINT        NOT NULL,
  created_at          DATETIME      NOT NULL,
  updated_by          BIGINT        NOT NULL,
  updated_at          DATETIME      NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_ledger_no (tenant_id, ledger_no),
  KEY idx_query (org_id, record_date, energy_type),
  KEY idx_process (process_name, record_date)
);

-- 表二：台账扩展属性
CREATE TABLE process_energy_ledger_ext (
  id           BIGINT        NOT NULL AUTO_INCREMENT,
```
