## 1. 三栏视图与字段归属

租户信息页面按「是否可改」分三栏，字段来源于同一份租户主数据 + 业务属性模板（`PROFILE_FIELDS`）。

| 栏位 | 性质 | 字段 | 可编辑 |
| :--- | :--- | :--- | :--- |
| 法定资质信息 | 只读 | 租户主数据：租户编号（`unifiedCode`）、租户名称（`name`）、租户类型（`type`）、租户状态（`status`）、有效期（`validFrom` / `validTo`）、主管理员（`adminName` / `adminMobile`，未指定展示「未指定」）+ 资质类模板字段（`tenant_editable = false`，如统一社会信用代码、注册号、法定代表人、资质证书编号、发证机关、资质有效期、营业执照附件等） | 否（如需变更联系平台，由平台线下受理代录，见租户管理业务 PRD §4.16） |
| 日常联络展示信息 | 租户可编辑 | 联络人姓名（`contactName`）、联络电话（`contactPhone`），成对填写 | 是（保存后立即生效） |
| 业务属性信息 | 租户可编辑 | `tenant_editable = true` 的业务属性模板字段（如所属行业、规模、注册地址、联系邮箱、人员规模等，按租户类型取 `tenantSelfEditFields`） | 是（保存后立即生效） |

> 业务属性以 key-value 形式存于租户 `profile`（`Record<string,string>`），字段定义来自 `PROFILE_FIELDS` 模板，按租户类型（enterprise / government / org / park）取不同字段集；与《租户管理字段清单》T14「业务属性信息（模板驱动，key-value）」同源。
> **租户端不做复核**：所有可编辑字段保存即生效，无「待复核 / 审核通过 / 审核驳回」状态（原型未实现，见 §3）。

## 2. 业务属性模板字段定义（TenantProfileFieldDef）

| 字段名 | 中文名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- | :--- |
| code | 字段编码 | varchar(50) | 模板字段唯一键，对应 profile 的 key | 全局唯一 |
| name | 字段名称 | varchar(50) | 展示名 | — |
| type | 字段类型 | varchar(20) | text / textarea / number / date / select / multi_select / region / boolean | 驱动渲染控件 |
| required | 是否必填 | tinyint(1) | 1 / 0 | platform 档参与开户校验；tenant 档只驱动租户端待完善清单 |
| max_length | 最大长度 | int | 文本类约束 | — |
| options | 选项 | json | select / multi_select 类取值 | — |
| editable_scope | 可编辑方 | varchar(20) | platform / tenant / both（缺省 tenant） | platform 档 = 法定资质类，租户端只读 |
| need_review | 平台审核依据标记 | tinyint(1) | 1 / 0 | **仅 `editable_scope = platform` 档允许携带**，表示该字段为平台审核过的准入 / 监管依据；不驱动租户端保存流程（无待复核态） |
| tenant_editable | 租户可改 | tinyint(1) | 1（缺省）/ 0 | 0 = 法定资质类，纯只读（灰底），提示「如需修改请联系平台」；1 = 业务属性类，租户管理员可直接编辑（白底） |
| placeholder | 填写提示 | varchar(255) | 输入框 hint | — |
| is_public | 是否公共字段 | tinyint(1) | 1 / 0 | 四类租户共用 |

## 3. 保存与校验规则（无复核流程）

| 规则 | 说明 |
| :--- | :--- |
| 保存入口 | 区块二「日常联络展示信息」+ 区块三「业务属性信息」共用页面顶部一个【保存修改】按钮；无变化（`dirty = false`）时置灰 |
| 保存范围 | 只接受业务属性类字段（`tenant_editable = true`）与联络展示字段；法定资质类字段即使页面带出也不允许直写，服务端同样拒绝并提示「如需修改请联系平台」 |
| 生效时机 | 保存后**立即生效**；原型无「待复核 / 审核通过 / 审核驳回」状态，相关字段（`review_status` 等）本期不建模 |
| 留痕 | 每次有实际变化的保存写一条租户侧操作审计日志，记变更字段前后值 |
| 校验 | 联络人姓名与联络电话成对填写；联络电话 11 位手机号；文本类受 `max_length` 约束；数字类须为合法数字；必填项未填不阻断保存 |
| 整页只读 | 租户停用（`status = disabled`）时数据冻结，整页只读，保存 / 重置按钮隐藏 |
| 报告引用联动 | 本页保存的字段如被报告引用，引用该字段的报告标记为「待更新」 |
| 重置 | 【重置】还原为上次保存的值，仅在有无保存修改时可点 |

## 4. 完整度（tenantProfileCompleteness）

| 项 | 内容 |
| :--- | :--- |
| 计算口径 | 已填必填字段数 / 必填字段总数；只统计**租户可自编辑**（`tenant_editable = true`）的必填字段 |
| 缺失项 | `missingTenantProfileFields`：列出未填的租户可自编辑必填字段，引导补齐；法定资质类（只读）缺口由平台侧「档案待完善」呈现 |
| 触发 | 首次登录自动弹出引导（`TenantGuide`），本次会话「跳过」后不再自动弹出，可点「查看引导」再次打开 |
| 出口 | 「去完善」滚动定位到首个缺失字段；「跳过」不标记为已完成 |
| 业务影响 | 未完善不影响登录与业务使用 |
