## 0. 表定位

组织架构是租户内唯一的组织实体表，不另建「部门表」；成员 `dept_id` 与角色数据范围均指向 `org.id`。原型仅维护单表 `org`，组织类型为节点上的字符串标签。

```text
tenant（租户，由租户管理字段清单维护，本清单只引用）1 ──── N 组织节点（org）
组织节点（org）自关联：parent_id → org.id（同租户）
成员（member，由成员管理字段清单维护）N ──── 1 组织节点（member.dept_id 语义等于 org.id）
角色指定组织范围（role_function_dept，由角色管理字段清单维护）N ──── 1 组织节点
业务数据（核算项目 / 产品 / 工艺 / 工序 / 因子）N ──── 1 组织节点（owner_org_id）
```

推论：

| # | 推论 |
| :--- | :--- |
| 1 | 组织表是租户内唯一的组织实体表，不另建部门表；成员 `dept_id` 与角色 `dept_id` 均指向 `org.id` |
| 2 | 组织类型为节点上的 `type_name` 字符串标签（来自预置字典），原型无独立 `org_type_dict` 表、无 `org_type_id` 外键（区别于前向字段清单 §2） |
| 3 | 每租户有且只有一个根组织：`parent_id = NULL` 且 `is_root = 1`；根组织由 `ensureTenantRootOrg` 随租户开户自动建，名称 = 租户名称 |
| 4 | 组织不做软删：删除前由「无下级、无成员（按名称匹配）」两道校验拦截，通过后物理删除；无「已删除」状态（业务引用第三道拦截原型未做，见 §7 T04） |
| 5 | 原型 `OrgNode` 不含 `created_by / updated_by / version`，生产化需补乐观锁与操作人留痕（见 §7 T06） |

## 2. 表间关系

```text
tenant（租户，租户管理字段清单覆盖）
  └─ 1:N ─ org（组织节点，本清单 §1，parent_id 自关联）
                ├─ 被 member.dept_id 引用（成员管理字段清单覆盖）
                ├─ 被 role_function_dept.dept_id 引用（角色管理字段清单覆盖）
                └─ 被业务数据 owner_org_id 引用（核算项目 / 产品 / 工艺 / 工序 / 因子字段清单覆盖）
```

关键约束：

1. 组织节点 `parent_id` 自关联，同租户内层级成树；根为 `parent_id = NULL` 且 `is_root = 1`。
2. `org_path` 存 ID 路径（如 `/ON001/ON002/`），改名与移动不影响路径可读性；移动后由应用层重算本节点及全部子孙的 `level` 与 `path`。
3. 成员 `dept_id` = `org.id`；原型展示按 `deptName === org.name` 匹配直属成员，生产化建议统一以 `dept_id` 主键关联（见 §7 T02）。
4. 角色「本组织及下级」数据范围按 `org_path` 前缀实时计算；「指定组织」引用 `org.id`，组织删除时由成员 / 角色模块联动处置。
5. 租户物理删除时 `org` 记录一并物理清除（成员关系先统一置移出）。

## 3. 跨模块契约字段

> 本清单不维护下列表，只声明引用关系，供成员、角色、业务数据各模块对齐。字段名的最终维护方见表中「维护方」。

| 表 / 字段 | 语义 | 维护方 | 约束 |
| :--- | :--- | :--- | :--- |
| `member.dept_id` | 成员主组织，语义等于 `org.id` | 成员管理字段清单 | 可空；为空按「仅本人」；对应组织须启用才可挂新成员；组织删除前须无挂靠成员（原型按 `deptName` 匹配） |
| `role_function_dept.dept_id` | 角色「指定组织」数据范围的节点 | 角色管理字段清单 | 组织删除时由对应模块联动移除引用 |
| `pcf_project.owner_org_id` | 核算项目的核算主体组织 | 核算项目字段清单 | 不可空；组织删除前须无项目引用（原型未校验，见 §7 T04） |
| 产品 / 工艺 / 工序 / 因子 `owner_org_id` | 主数据归属组织 | 各模块字段清单 | 可空（平台预置为空）；组织删除前须无引用 |
| 角色范围枚举 | 2=本组织及下级 / 3=本组织 / 5=指定组织 | 角色管理字段清单 | 「本组织及下级」按 `org_path` 前缀匹配实时计算 |

## 4. 设计决策

| 编号 | 事项 | 决议 | 落点 |
| :--- | :--- | :--- | :--- |
| D01 | 单根组织 | 每租户一个根（`parent_id = NULL`，`is_root = 1`），系统随租户开户自动建，名称 = 租户名；不采用多根方案 | §0 推论 3、§1 |
| D02 | 组织类型形态 | 原型为 `type_name` 字符串标签，无 `org_type_dict` 表 / `org_type_id` 外键；如需字典能力需补表（§7 T03） | §1、§0 推论 2 |
| D03 | 层级上限 | 5 层（`ORG_MAX_LEVEL`），`org_level` 取值 1 至 5 | §1 |
| D04 | 路径存 ID | `org_path` 存 ID 路径（非名称），改名不影响；「含下级」按前缀匹配 | §1、§2 |
| D05 | 负责人 | 仅 `leader_name` 文本，不联动权限、不存账号 ID 与电话（区别于前向） | §1 |
| D06 | 删除策略 | 物理删除；仅「无下级、无成员」两道拦截止删，无业务引用第三道（§7 T04） | §0 推论 4 |
| D07 | 审计与版本 | 原型未含操作人 / 版本字段；生产化补 `created_by / updated_by / version` | §0 推论 5、§7 T06 |

## 5. 待确认（字段级）

| # | 事项 | 说明 |
| :--- | :--- | :--- |
| T01 | `parent_id` 用 NULL 还是 0 表示根 | 本清单用 NULL（与原型 `parentId = null` 一致），并以 `is_root` 标记根；若技术层对 NULL 唯一索引不友好，可改 0 并调整 `uk_org_parent_name` |
| T02 | 成员匹配主键 | 原型按名称匹配存在改名失配隐患；建议统一以 `dept_id`（= org.id）为主关联键 |
| T03 | 组织类型是否升级为字典表 | 当前 `type_name` 为标签；若需停用类型 / 强约束下级类型，需补 `org_type_dict` 与 `org_type_id` 外键 |
| T04 | 删除的业务引用拦截 | 原型删除仅校验「有下级 / 有成员」，缺「被业务数据归属引用」拦截；建议补齐，否则删除后业务数据 `owner_org_id` 悬空 |
| T05 | 负责人是否落账号 ID | 本期 `leader_name` 仅为姓名；若要「负责人自动获本组织及下级数据范围」，需改 `leader_account_id` 并补角色规则 |
| T06 | 审计 / 版本字段 | 原型 `OrgNode` 无 `created_by / updated_by / version`；生产化须补乐观锁（version）与操作人（created_by / updated_by），否则无法追溯与防并发 |
| T07 | 组织编码生成规则 | 原型系统兜底为 `ORG + 时间戳后 4 位`；若客户有既有编码体系，允许手填覆盖，需保证导入时编码不与系统生成冲突 |
