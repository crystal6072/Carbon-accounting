## 1. 拟添加的批注清单

### 1.1 整体流程

#### B17-01 组织架构维护整体流程
**拟标注位置**：功能标题「组织架构」附近（全局说明；面包屑 `系统管理 / 组织与权限 / 组织架构`）
**标记**：已确认

**批注内容**

- **适用场景**：租户管理员在租户端维护本租户组织树，作为成员挂靠、角色数据范围、业务数据归属的组织维度依据。
- **布局**：左栏为组织树（含根组织与全部下级）；右栏为选中节点的详情（字段 + 直属成员表）。
- **流程**：进入组织架构 → 左树选节点（默认选中根组织）→ 右栏看详情与直属成员 → 按需「新增下级 / 编辑 / 移动 / 停用·启用 / 删除」→ 保存即时生效，左树与右栏同步刷新。
- **根组织兜底**：进入时由 `ensureTenantRootOrg` 确保本租户存在一个系统自动创建的根组织（名称 = 租户名称）；不存在时自动补建，再加载节点列表。
- **结束**：所有写操作即时生效，无提交 / 审核 / 驳回；组织节点支持物理删除（满足条件时），无「作废 / 终结」状态，启用与停用可反复切换。
- **本期范围（与原前向 PRD 差异，以原型为准）**：原型**不提供**组织类型字典 CRUD、批量导入、组织模板、平台侧只读全景、受控代配置；组织类型仅为预置字符串标签（见 B17-02、B17-14）。

### 1.2 全局规则说明

#### B17-02 全局规则
**拟标注位置**：功能标题附近 + 左栏底部 `org-panel-tip` 两处说明条
**标记**：已确认（成员匹配口径、根组织可停用见 §4 待确认）

**批注内容**

1. **单根组织**：每租户有且只有一个根组织，`parentId = null`、`isRoot = true`、名称默认 = 租户名称；其余节点一律挂在根组织或其下级之下，不允许多根并列。
2. **层级上限**：组织树层级上限为 **5 层**（常量 `ORG_MAX_LEVEL`）；第 5 层节点不再提供「新增下级」入口（按钮置灰并提示「已达 5 层上限或节点已停用」）。
3. **同一上级下名称唯一**：同一上级节点下，组织名称不可重复（含根节点之间）；不同上级下允许同名。
4. **组织编码唯一**：组织编码在租户内唯一（不区分大小写），可手填或留空由系统生成（生成后转大写）；创建后保存时仍判重。
5. **类型仅为标签**：组织类型 `typeName` 取自本租户可用类型（预置集 ∪ 已用类型），为字符串标签，不做「该类型下只能挂某子类型」的强约束，无独立类型字典表。
6. **停用影响**：节点停用后，不可在其下新增下级、不可挂新成员，但存量成员的组织归属与数据范围不变；禁用态仍可「编辑 / 移动 / 启用」，仅「新增下级 / 删除」受限。
7. **删除前置（原型口径）**：删除仅校验「非根组织 / 无下级节点 / 无挂靠成员」三道，详见 B17-11（业务引用第三道拦截见 §4 C-01，原型未实做）。
8. **平台侧不代维护**：页面提示「平台侧不提供跨租户组织树只读查看，必要时经『进入租户』开启受控代配置」——即本页以外不提供组织全景维护入口。
9. **成员匹配**：右栏直属成员按 `deptName === org.name` 名称匹配（见 B17-06、§4 C-04）。
10. **权限**：原型未做角色 / 功能码限制（菜单恒渲染、接口不校验），正式实现需按「组织架构」功能码收敛（不阻塞批注）。

#### B17-03 业务状态（启用 / 停用）
**拟标注位置**：右栏详情「节点状态」标签、左树节点名后的「（停用）」标记、状态确认弹窗
**标记**：已确认（根组织是否允许停用见 §4 C-05）

**批注内容**

- **含义与取值**：组织两态——**启用**（可挂新成员、可新增下级、可参与数据范围）、**停用**（不可挂新成员、不可新增下级，存量数据与数据范围不变）。
- **进入条件**：新增保存后默认「启用」；「停用」由启用态经行操作「停用」进入；「启用」由停用态经行操作「启用」进入。
- **可进行的操作**：
  - 启用态：新增下级、编辑、移动、停用、删除（满足删除前置时）。
  - 停用态：编辑、移动、启用、删除（满足删除前置时）；不可新增下级、不可挂新成员。
- **状态变化**：启用 ↔ 停用双向可达，可反复切换；变更只刷新状态与最近更新时间，不改动名称 / 类型 / 上级 / 排序等。
- **停用阻断（原型口径）**：停用某节点前，若其下存在**启用状态**的下级，阻断并提示「该节点下仍有启用状态的下级，请先停用下级」（mock E08）；其下若全为停用下级，则可停用。
- **启用阻断（原型口径）**：启用某节点前，若其上级为停用状态（非根），阻断并提示「请先启用上级节点」（mock E09）；根组织无上级，恒可启用。

### 1.3 操作功能及对应业务规则

#### B17-04 组织树浏览与选中
**拟标注位置**：左栏「组织架构」卡片内的 `<Tree>` 区域
**标记**：已确认

**批注内容**

- **操作目的**：按层级逐层定位要维护或查看的组织节点。
- **展示规则**：节点名后追加「（停用）」标记（停用态）与「· 根组织」标记（根）；节点副标题展示「组织类型 · N 人」（N = 按名称匹配的直属成员数，为 0 时不显示）。
- **交互**：点选节点即设为当前范围，右栏同步展示该节点详情与直属成员；树默认全部展开（`expandedIds` 取全部节点）。
- **空态**：若租户无根组织（极端情况），左树显示「本租户尚未配置组织架构 / 请联系平台重新初始化根组织」。

#### B17-05 节点详情
**拟标注位置**：右栏 `org-detail-body` 详情列表
**标记**：已确认

**批注内容**

- **展示内容**：节点名称、组织编码、组织类型、上级节点、所在层级、层级路径、负责人、同级排序、下级节点 / 直属成员、含下级节点数、最近更新、节点状态。
- **口径**：
  - 上级节点：根组织显示「—（租户根组织，由系统自动创建）」，顶级（非根无上级）显示「—（顶级节点）」；原型实际仅根组织无上级，故常态只出现根组织这一支。
  - 所在层级：显示「第 N 层 / 上限 5 层」。
  - 层级路径：展示 `path`（如 `/ON001/ON002/`）。
  - 同级排序：显示「第 N 位（同级共 M 个）」。
  - 含下级节点数：`orgSubtreeCount` 含自身。

#### B17-06 直属成员（只读）
**拟标注位置**：右栏 `org-member-block` 表格区
**标记**：已确认（匹配口径见 §4 C-04）

**批注内容**

- **操作目的**：只读查看当前组织节点的直属成员（姓名、手机号、角色、成员状态）。
- **匹配规则**：按成员 `deptName === org.name` 名称匹配（非按 `dept_id`）。
- **只读**：表头提示「成员归属由成员管理调整，此处只读」；本页不提供成员增删改入口。
- **无内容时**：显示「该节点暂无直属成员」。

#### B17-07 新增下级
**拟标注位置**：页头「新增下级」按钮、右栏「新增下级」按钮、`OrgNodeModal` 弹窗
**标记**：已确认（弹窗「新增顶级节点」冗余路径见 §4 C-03）

**批注内容**

- **操作目的**：在当前选中节点（默认根组织）下建立子组织。
- **入口**：页头「新增下级」（选中或根组织禁用态 / 达 5 层时置灰）与右栏「新增下级」按钮；两处均把当前节点作为 `parent` 传入，原型**不提供**「新建顶级节点」入口（单根约束，B17-02）。
- **可操作条件**：所选节点须为「启用」且层级 < 5；否则按钮置灰并提示原因。
- **默认带入**：组织类型默认取本租户可用类型末项（企业常态为「部门」）；排序默认「同级末位 + 1」。
- **校验（保存时）**：① 名称必填且 ≤50 字符；② 排序须为不小于 0 的整数；③ 同上级下名称不重复；④ 编码租户内唯一（不区分大小写）。任一不通过即阻断并提示，已填内容保留。
- **结果**：保存成功后弹窗关闭、左树与右栏刷新，新节点层级 = 上级层级 + 1，状态为「启用」。

#### B17-08 编辑节点
**拟标注位置**：右栏「编辑」按钮、`OrgNodeModal` 弹窗
**标记**：已确认

**批注内容**

- **操作目的**：修改组织名称、组织编码、组织类型、负责人、排序号。
- **可操作条件**：任何状态均可编辑（启用 / 停用态均提供「编辑」）。
- **规则**：① 编辑**不改上级**——弹窗提示「编辑不改变上级，如需调整请使用『移动』」；② 名称 / 编码 / 排序校验同 B17-07；③ 编码改后判重（排除自身）；④ 同上级下名称去重排除自身。
- **结果**：保存成功后刷新，节点 ID / 路径 / 层级不变（改上级须走移动）。
- **根组织特例**：根组织可编辑名称 / 类型 / 负责人 / 排序，但不可删除、不可移动（见 B17-09、B17-11）。

#### B17-09 移动节点
**拟标注位置**：右栏「移动」按钮、移动确认弹窗
**标记**：已确认（子树层级校验缺口见 §4 C-02）

**批注内容**

- **操作目的**：把节点调整到另一个上级之下（含调整整棵子树位置）。
- **可操作条件**：根组织不可移动（按钮置灰，提示「根组织由系统自动创建，不可移动」）；其余节点恒可发起移动。
- **目标候选**：排除自身与其全部子孙（按 `path` 前缀判定）、排除停用节点、排除根组织——即候选仅为「启用态、非根、非自身及子孙」的节点；原型**不提供**「移动到顶级」选项（单根约束）。
- **校验（确认时）**：① 新上级不是自身或自身子孙；② 新上级为启用态；③ 移动后本节点层级 ≤5（**子树最大层级是否校验见 §4 C-02**，原型当前仅校验本节点）；④ 目标层级下不存在同名节点（mock E02 移动重名）。
- **级联重算**：移动成功后，本节点与全部子孙的 `level` 与 `path` 由 `recalcSubtree` 重算。
- **影响提示**：弹窗展示「本节点与全部下级（共 N 个）层级与路径将重算」「直属成员 M 人的数据范围按新树生效，历史业务数据归属不变」。
- **结果**：确认后节点挂到新上级，左树与右栏刷新。

#### B17-10 停用 / 启用
**拟标注位置**：右栏「停用 / 启用」按钮、状态确认弹窗
**标记**：已确认（根组织可否停用见 §4 C-05）

**批注内容**

- **操作目的**：切换节点启用 / 停用状态（离岗 / 复岗式生命周期）。
- **入口**：按钮文案随状态切换（启用态显示「停用」，停用态显示「启用」）；根组织同样提供此按钮（是否允许见 §4 C-05）。
- **停用确认弹窗**：正文「确认停用节点『名称』？停用后该节点不可挂新成员、不可新增下级，存量成员的数据范围不变。」；底栏「取消 / 确认」。
- **启用确认弹窗**：正文「确认启用节点『名称』？启用后该节点可继续新增下级与挂载成员。」；底栏「取消 / 确认」。
- **阻断规则**：见 B17-03（停用时存在启用下级、启用时上级为停用，均阻断并提示）。
- **结果**：确认后状态翻转、左树「（停用）」标记与右栏状态标签同步、写审计。

#### B17-11 删除节点
**拟标注位置**：右栏「删除」按钮、删除确认弹窗
**标记**：已确认（业务引用拦截见 §4 C-01）

**批注内容**

- **操作目的**：物理删除一个组织节点（删除后不可恢复）。
- **可操作条件（按钮禁用原因）**：① 根组织 → 禁用，提示「根组织由系统自动创建，不可删除；可修改组织名称」；② 存在下级节点（含停用）→ 禁用，提示「该节点下仍有下级节点，请先处理下级」；③ 存在挂靠成员 → 禁用，提示「该节点下仍有 N 名成员，请先调整成员所属组织」。三项均不满足时按钮可点。
- **删除确认弹窗**：正文「确认删除节点『名称』？删除后不可恢复。」并列出删除前置条件：
  1. 节点下不能有下级节点（含已停用节点）；
  2. 节点下不能有成员挂载，需先在成员管理中调整所属组织；
  3. **被业务数据归属引用时不可删除，只能停用**（注：此条与 mock 实现不一致，见 §4 C-01）。
- **mock 实际拦截（以原型为准）**：`deleteOrgNode` 仅校验 ① 非根；② 无下级；③ 无成员（按名称匹配）。满足即通过，物理删除节点。**业务引用第三道拦截原型未实做**。
- **结果**：确认后节点被物理删除，左树与右栏刷新。

### 1.4 字段说明

#### B17-12 节点名称
**拟标注位置**：表单「节点名称」、详情「节点名称」、左树节点名
**标记**：已确认

**批注内容**

- **业务含义**：组织的展示名称，也是组织树与详情中用户识别的依据。
- **必填**：必填；为空提示「节点名称必填」并阻断保存。
- **重复限制**：同一上级下不可重复（B17-02 第 3 条）。
- **长度上限**：**≤ 50 个字符**（原型校验口径，前端与 mock 双重校验）。

#### B17-13 组织编码
**拟标注位置**：表单「组织编码」、详情「组织编码」
**标记**：已确认（长度上限为待核对，见 §4 C-06）

**批注内容**

- **业务含义**：组织的稳定标识，用于导入与外部系统对接。
- **填写方式**：选填；留空由系统生成（mock 兜底为 `ORG + 时间戳后 4 位`），输入实时转大写。
- **唯一限制**：租户内唯一，不区分大小写；新增与编辑保存时均校验，重复提示「组织编码在租户内已存在」。
- **长度上限**：原型未强制编码长度（仅首字母占位提示「如 ORG0007」）；字段清单建议 `varchar(64)`，待核对是否需前端明限（见 §4 C-06）。

#### B17-14 组织类型
