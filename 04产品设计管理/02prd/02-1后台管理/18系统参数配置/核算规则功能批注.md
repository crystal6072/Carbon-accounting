# 核算规则功能批注

> 原型是唯一的真实来源。凡原型已表现而现有文档未覆盖的，统一标记为「原型已表现·待核对」；尚未裁决的问题归入 §4.1；原型与文档不一致的点归入 §4.2。

## 0 说明

- **项**：核算规则（路由 `/config/calc-rule`、`/config/calc-rule/new`、`/config/calc-rule/:id`、`/config/calc-rule/:id/edit`）
- **范围**：按标准号 = 一套规则，结构化记录某标准规定的取舍准则、可忽略排放项说明、分配方法与说明。本对象**不参与核算求值，不影响核算结果**；无审核流、无版本化、无单据下推；变更用「变更留痕」表达（原型为预留组件）。
- **与其他功能关系**：上游为标准文件库（标准号 / 名称 / 状态）、行业库（适用行业）；下游为项目核算步骤①、模型步骤① / ②、报告详情。仅 `enabled` 规则可被下游只读引用，且下游只带回显文本与分配门控，不传参给引擎。
- **编号规则**：`HS-01` 起；HS-01 流程；HS-02~HS-07 操作；HS-10~HS-11 字段；HS-23 全局；HS-24~HS-26 待确认 / 同步 / 演示。
- **依据**：《核算规则字段清单 V2.0》《系统参数配置业务 PRD V0.4》《系统参数配置功能批注 V1.2》及当前原型（CalcRuleListPage / CalcRuleFormPage / ChangeLogModal / mock/config.ts）。
- **标记口径**：已确认 / 原型已表现·待核对 / 待确认（仅 §4.1）。
- **版本记录**：V1.0（2026-11-10）初稿，以系统原型为准补全批注。

## 4 待确认清单

### 4.1 需补充规则（待裁决，不作为需求依据）

1. 核算规则是否支持导入 / 批量维护（Q01）。
2. 系统预置核算规则由谁维护、可否被组织覆盖（Q02）。
3. `allow_allocate`（是否允许共生产品分配）当前仅来自 Mock 数据、表单无控件，是否补采集入口（衍生 / T03）。
4. 变更留痕（ChangeLogModal）是否为本期交付项（原型已预留组件与数据，列表 / 表单未挂入口）。

### 4.2 需原型同步调整（文档与原型差异）

1. 取舍阈值原型未做 0–100 范围与「单环节 ≤ 累计上限」校验，建议补齐（T02）。
2. 标准号唯一性 / 新建时过滤已配置标准，原型未做校验（T01）。
3. 新建规则标识原型用 `RULE-${Date.now()}`，与演示数据 `RULE-YYYYMMDDNNN` 命名不一致（P-01）。
4. 各列表分页：文档约定 10 条/页，原型默认值需对齐。
5. 上游只读反查入口（标准文件详情 / 核算模型详情跳规则详情）未在本模块原型体现（T03 / P-08）。
