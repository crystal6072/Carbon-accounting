# 消息配置功能批注

> 原型是唯一的真实来源。凡原型已表现而现有文档未覆盖的，统一标记为「原型已表现·待核对」；尚未裁决的问题归入 §4.1；原型与文档不一致的点归入 §4.2。

## 0 说明

- **项**：消息配置（路由 `/config/message`；本模块本期简化为**仅「站内信配置 + 消息模板配置」**两个页签）
- **范围**：站内信配置（平台级单例：启用开关 + 消息保留天数）+ 消息模板配置（7 个内置事件各 1 条站内信模板，编辑标题 / 正文与启用状态）。不做事件订阅矩阵、邮件 / 短信通道、接收对象 / 频控 / 免打扰、发送记录、测试发送与失败重试。
- **与其他功能关系**：上游为内置事件清单（系统固定，不可增删）；下游为顶栏铃铛（站内信消费端，可标记已读）；接收人由事件自动确定，不配置订阅与通道。
- **编号规则**：`MC-01` 起；MC-01 流程；MC-02~MC-03 操作；MC-10~MC-11 字段；MC-23 全局；MC-24~MC-26 待确认 / 同步 / 演示。
- **依据**：《存储与消息配置字段清单 V1.2》§3–§5、《系统参数配置业务 PRD V0.6》《系统参数配置功能批注 V1.2》及当前原型（MessageConfigPage / mock/config.ts）。
- **标记口径**：已确认 / 原型已表现·待核对 / 待确认（仅 §4.1）。
- **版本记录**：V1.0（2026-11-10）初稿，以系统原型为准补全批注（消息配置简化为站内信配置 + 消息模板配置）。

1. 消息配置后续是否扩展更多事件或邮件通道（Q05）。

### 4.2 需原型同步调整（文档与原型差异）

1. 消息配置本期只做站内信配置与消息模板配置，需确认顶栏铃铛演示数据已与简化后的口径对齐。
2. 各列表 / 内容页分页与默认值需与文档约定对齐。
3. 站内信消息（message_inbox）为只读消费端，原型需确认铃铛「标记已读」与演示数据的对应关系。
