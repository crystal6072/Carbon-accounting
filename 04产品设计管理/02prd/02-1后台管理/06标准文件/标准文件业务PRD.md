## 1. 需求概述

### 1.1 需求背景

标准文件是**核算依据的载体**。方案 §4.2.5 明确：标准文件库用于沉淀核算依据，**供核算模型绑定引用**；而**标准差异由不同版本的核算模型承载**（方案 §4.3.1：不同标准 = 不同标准依据绑定 + 不同阶段 / 检测 / 报告配置，以不同模型版本交付）。

因此本模块**只提供"依据"，不定义"怎么算"** —— 算法规矩在核算模型里。

**决策 D3**：本版本首发标准依据对齐 **`GB/T 24067-2024`**，首个核算模型绑定该标准文件。这意味着本模块虽然方案标记为 **P1**，但**至少需交付「一条预置标准 + 模型可绑定」的最小闭环**，否则首个模型无法落地。

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :--- | :--- | :--- |
| G1 | 提供标准文件字典 | 字段覆盖方案 §2.3 A1-3 + §4.2.5（名称 / 编号 / 版本 / 发布机构 / 适用范围 / 生效日期） |
| G2 | 支撑 D3 首发模型 | 系统预置 `GB/T 24067` / `2024`，可被首个核算模型绑定 |
| G3 | 版本与替代关系可追溯 | 同一标准的多个版本各为独立记录，通过「被替代标准」串联 |
| G4 | 被引用后不可变 | 被核算模型引用的标准不可编辑、不可删除（对齐 §4.9） |
| G5 | 版权风险可控 | 附件仅限内部查阅，明确不得作为对外交付物 |

### 1.3 In Scope / Out of Scope

**In Scope**

| 能力 | 说明 |
| :--- | :--- |
| 标准文件列表与查询 | 按编号、名称、版本、类型、状态、数据来源筛选 |
| 新增 / 编辑标准文件 | 元数据维护 |
| 查看标准文件 | 独立详情页 + 引用情况（引用本标准的核算模型清单） |
| 附件上传 / 替换 | 选填、可多个（【待确认 Q01】） |
| 版本与替代关系维护 | 「被替代标准」自引用 |
| 标准状态变更 | 现行 → 被替代 / 作废 |
| 启用 / 禁用 | 行操作 + 二次确认 |
| 导出 | 导出当前查询结果 |

**Out of Scope**

| 不做项 | 说明 |
| :--- | :--- |
| 审核流 / 版本化 | 基础数据，均不涉及。**「一个版本 = 一条记录」即替代版本化字段**（【待确认 Q02】） |
| **在标准文件内定义算法** | 算法规矩（阶段 / 计算规则 / 检测规则 / 报告规定）归**核算模型**（§4.3.1） |
| 「采标程度」（IDT / MOD / NEQ） | 本期不做（【待确认 Q08】） |
| 「适用行业」关联 | 由「适用范围」文本承载，不设关联字段（【待确认 Q10】） |
| 标准英文名称 / 原文名称 | 本期不做（【待确认 Q12】） |
| Excel 导入 | V0.1 不支持（【待确认 Q11】） |
| 附件对外分发 | **一律不允许**（版权边界，见 §5） |

## 2. 用户与使用场景

### S01 维护系统预置标准文件（平台侧）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 平台需要录入一个新的核算标准（如首发录入 GB/T 24067-2024） |
| 操作流程 | 平台运营新增标准文件 → 填写编号、名称、版本、类型、发布机构、适用范围、生效日期 → 可选上传附件 → 保存 |
| 预期结果 | 标准文件创建成功，数据来源 = 系统预置，标准状态 = 现行；可被核算模型绑定 |

### S02 上传 / 更新标准文件附件

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要为标准补充电子文本供内部查阅 |
| 操作流程 | 编辑标准文件 → 上传附件（可多个）→ 保存 |
| 预期结果 | 附件挂载成功，通过附件管理的鉴权访问；**仅限内部查阅，不得作为对外交付物**（§5） |

### S03 登记标准的新版本并建立替代关系

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 标准发布了新版本（如 `GB/T 24067-2024` 替代 `GB/T 24067-2014`） |
| 操作流程 | 新增标准文件（编号相同、版本为新版本）→ 在「被替代标准」中选择旧版本 → 保存 → 将旧版本的标准状态改为「被替代」并填失效日期 |
| 预期结果 | 新旧版本形成替代关系；旧版本不可被新模型引用；**已绑定旧版本的模型不受影响**（按快照运行） |

### S04 将标准状态标记为「被替代 / 作废」

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 标准已被替代或已废止 |
| 操作流程 | 编辑标准文件 → 修改标准状态 → 填写失效日期 → 二次确认 → 保存 |
| 预期结果 | 状态变更生效；**不可被新的核算模型引用**；已引用该标准的模型与项目不受影响；需按新标准重算走 **E13** |

### S05 标准文件被核算模型引用后的限制

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 标准文件已被某个核算模型绑定 |
| 操作流程 | 尝试编辑或删除该标准 |
| 预期结果 | **不可编辑、不可删除**（对齐 §4.9 不可变对象）；详情页展示「引用本标准的核算模型清单」；如需变更，以**新版本记录**承载 |

### S06 在核算模型中引用标准文件

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 配置核算模型时需要绑定标准依据 |
| 操作流程 | 在核算模型（P14）的模型基本信息中选择标准依据 → 保存 → 发布模型 |
| 预期结果 | 模型绑定成功；只能选到**标准状态 = 现行 且 使用状态 = 启用**的标准（D10 / D03）；模型发布后绑定关系随模型版本冻结 |

### S07 查看标准文件详情与引用情况

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要确认标准信息或被谁使用 |
| 操作流程 | 列表点编号 / 名称进入详情页 → 查看元数据、附件、替代关系、引用情况 |
| 预期结果 | 展示完整字段与引用清单 |

## 4. 标准文件的结构与版本规则

### 4.1 一个版本 = 一条记录

| # | 规则 |
| :--- | :--- |
| V1 | **同一标准的不同版本 = 多条独立记录**；唯一键 = **「标准编号 + 标准版本」**（D01） |
| V2 | **不引入版本化字段** —— 本模块定性为「无版本化」；版本即记录 |
| V3 | 模型绑定的对象是**具体某一条记录**（即某个版本），因此「同一模型永远按当时的那个版本核算」，**快照语义天然成立**，无需额外的「绑哪个版本」表达 |
| V4 | 标准版本建议为 **4 位年份**（如 `2024`）（【待确认 Q09】） |

```text
示例：
GB/T 24067-2014（标准状态 = 被替代）  ←──┐
                                        │「被替代标准」指向旧版
GB/T 24067-2024（标准状态 = 现行）  ────┘
```

### 4.2 「被替代标准」的引用约束

| # | 规则 |
| :--- | :--- |
| V5 | 「被替代标准」为**自引用**：指向本标准文件表中的另一条记录（旧版本） |
| V6 | **不得自引用**（一条记录不能替代自己） |
| V7 | **不得成环**（A 替代 B、B 又替代 A 不成立；三节点及以上环路同样禁止）（D02） |
| V8 | 「被替代标准」为选填；新版记录创建时可暂不填写，后续补充 |

### 4.3 标准状态流转

| # | 规则 |
| :--- | :--- |
| V9 | 状态取值见字段清单 §5.2：现行 / 被替代 / 作废（是否含「即将生效」见【待确认 Q01】） |
| V10 | 新建默认「现行」 |
| V11 | 标准状态 = **作废** 时，**不可被新的核算模型引用**（D03） |
| V12 | 可被新模型引用需同时满足：**标准状态 = 现行** 且 **使用状态 = 启用**（D10） |
| V13 | 状态可回退（如「作废」→「现行」），但需二次确认并留痕（【待确认 Q05】） |
| V14 | 状态转为「被替代 / 作废」时，提示填写**失效日期**（【待确认 Q06】） |

### 4.4 日期约束

| # | 规则 |
| :--- | :--- |
| V15 | 生效日期必填（【待确认 Q06】） |
| V16 | 失效日期须 **≥ 生效日期**（D06）；未失效时可为空 |
| V17 | 失效日期**不参与业务校验**（不作自动禁用依据），仅供查阅与报告披露 |

## 5. 附件与版权边界

> 本章锁定标准文件附件的合规边界，**不得放松**。

| # | 规则 |
| :--- | :--- |
| A1 | 附件为**选填、可多个**（推荐口径 A，【待确认 Q01】） |
| A2 | 附件由**附件管理（§C6）**承载：存储隔离、访问鉴权、操作审计全留痕 |
| A3 | **版权边界**：GB/T 与 ISO 标准文本均受版权保护，内部分发亦可能受限 |

| 场景 | 是否允许 |
| :--- | :--- |
| 企业内部查阅（平台 / 租户自有人员） | 允许（按结论） |
| **作为对外交付物**（报告附件、导出文件、客户交付） | **一律不允许** |
| **租户间共享**（SaaS 多租户下跨租户可见） | **不允许** —— 附件的可见范围受限于其所属数据来源（系统预置附件仅平台运营可管理；组织自建附件仅本组织可见） |
| 导出时携带附件 | **不允许**（导出仅含元数据，见 A6） |

| # | 规则 |
| :--- | :--- |
| A4 | 附件缺失**不影响**标准文件的业务能力：模型绑定、核算、报告均基于**元数据**，不依赖附件 |
| A5 | 附件替换需保留历史（由附件管理的审计能力承载），避免"依据被静默改写" |
| A6 | 导出仅含元数据（编号、名称、版本、类型、发布机构、适用范围、日期、状态），**不含附件** |

## 6. 业务规则

| 规则编号 | 规则名称 | 触发条件 | 处理逻辑 | 例外策略 |
| :--- | :--- | :--- | :--- | :--- |
| R-001 | 编号 + 版本唯一 | 新增 / 编辑保存时 | 「标准编号 + 标准版本」唯一（D01 / V1） | 重复时阻断保存 |
| R-002 | 标准状态受控 | 保存时 | 必须取字段清单 §5.2 枚举之一；新建默认「现行」（V10） | 命中时阻断 |
| R-003 | 替代关系合法性 | 选择「被替代标准」时 | 不得自引用、不得成环（V6 / V7 / D02）；建议同编号下选择（跨编号替代需确认） | 命中时阻断 |
| R-004 | 日期约束 | 保存时 | 生效日期必填；失效日期 ≥ 生效日期（V15 / V16 / D06） | 命中时阻断 |
| R-005 | 系统预置只读 | 租户尝试编辑系统预置标准时 | 只读，不可编辑、不可禁用、不可删除（D04） | 仅平台运营可维护 |
| R-006 | 组织自建可编辑 | 编辑组织自建标准时 | 可编辑元数据与附件（【待确认 Q03】是否开放该能力） | 见 R-007 / R-009 |
| R-007 | **被引用后不可变** | 标准已被核算模型绑定时 | **不可编辑、不可删除**（D05，对齐 §4.9 不可变对象）；如需变更，以**新版本记录**承载 | 命中时阻断并列出引用它的模型清单 |
| R-008 | 引用准入 | 核算模型选择标准依据时 | 仅「标准状态 = 现行 且 使用状态 = 启用」的标准可被选中（D10 / V12） | 被替代 / 作废的标准不在候选列表出现 |
| R-009 | 删除规则 | 删除标准文件时 | 被核算模型引用过的**不可删除**；系统预置标准一律不可删除（D05 / D04） | 命中时阻断并列出引用清单 |
| R-010 | 状态变更的连锁处理 | 将标准改为「被替代 / 作废」时 | 状态变更**不追溯**已绑定该标准的模型与项目（按快照运行）；如需按新标准重算须走 **E13** | 变更时提示受影响的模型清单 |
| R-011 | 附件规则与版权边界 | 上传 / 访问 / 导出附件时 | 附件选填、可多个；仅限内部查阅；**不得作为对外交付物、不得跨租户共享、导出不含附件**（§5 A3 / A6） | 无例外 |
| R-012 | 导出规则 | 导出时 | 仅导出元数据，不含附件（A6） | 无例外 |

## 7. 状态与操作矩阵

### 7.1 状态维度说明

| 状态维度 | 取值 | 来源 |
| :--- | :--- | :--- |
| 数据来源 | 系统预置 / 组织自建 | 字段清单 |
| 标准状态 | 现行 / 被替代 / 作废 | 字段清单（业务状态，决定能否被引用） |
| 使用状态 | 启用 / 禁用 | 字段清单（用户操作） |
| 引用状态 | 未被引用 / 已被核算模型绑定 | 系统自动关联（只读） |

> 本模块**无版本维度、无审核维度**（「一个版本 = 一条记录」，见 V2）。

### 7.2 操作矩阵

| 数据来源 | 标准状态 | 引用状态 | 编辑 | 启用 | 禁用 | 删除 | 被新模型引用 |
| :--- | :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| 系统预置 | 现行 | 未被引用 | 否（仅平台运营） | — | 否（R-005） | 否（R-009） | 是 |
| 系统预置 | 现行 | 已被引用 | 否 | — | 否 | 否（R-007） | 是 |
| 系统预置 | 被替代 / 作废 | 任意 | 否 | — | 否 | 否 | 否（R-008） |
| 组织自建 | 现行 | 未被引用 | 是 | — | 是 | 是 | 是 |
| 组织自建 | 现行 | 已被引用 | **否**（R-007） | — | 否 | 否 | 是 |
| 组织自建 | 被替代 / 作废 | 任意 | 是（仅元数据说明性字段） | 是 | — | 否（若曾被引用） | 否 |

**闭环校验**

- 标准状态：现行 → 被替代 → 作废 正向可达；允许回退但需留痕（V13）；
- 「未被引用」的组组织自建标准有完整生命周期（编辑 / 启停 / 删除）；
- 「已被引用」构成**编辑、禁用、删除**三重限制（R-007）；
- 无版本维度、无审核分支。
