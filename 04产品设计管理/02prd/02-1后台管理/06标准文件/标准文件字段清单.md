# 标准文件字段清单

> **文档定位**：标准文件字段定义的唯一真相源（SST）。业务 PRD 和 Demo PRD 只引用字段名称，不重复维护枚举、必填性和字段口径。
> **适用类型**：基础数据维护（轻量）—— 非业务单据、**无审核流、无版本化**
> **核心用途**：沉淀核算依据的标准文件，**供核算模型绑定引用**（方案 §4.2.5）；标准差异由**不同版本的核算模型**承载
> **维护形态**：列表 + 独立详情页 + 独立新增/编辑页
> **成熟度**：粗纲
> **版本**：V0.1
> **更新时间**：2026-09-20

## 1. 模块与数据结构

### 1.1 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 模块名称 | 标准文件 |
| 业务归属 | 后台管理 → 基础库 → 标准文件库（方案 §2.3 A1-3、§4.2.5、§八 P05） |
| 模块类型 | 基础数据维护（轻量），非业务单据、无审核流、无版本化 |
| 核心对象 | 标准文件（一个版本 = 一条记录） |
| 核心职责 | 沉淀核算依据的标准文件，**供核算模型绑定引用**；标准差异由不同版本的核算模型承载（方案 §4.2.5、§4.3.1） |

### 1.2 对象结构

**推荐口径 A（【待确认 Q02】）**

| 结构 | 对象 | 与主对象关系 | 主键/唯一标识 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主表 | 标准文件 | 主对象 | **标准编号 + 标准版本** | **同一标准的不同版本 = 多条独立记录**，不引入版本化字段 |
| 自引用 | 被替代标准 | N:1 | 标准编号 + 标准版本 | 新版记录指向被替代的旧版记录；不得自引用、不得成环 |
| 附件 | 标准文件附件 | 1:N | 附件 id | 由附件管理（§C6）承载；选填、可多个 |

```text
版本与替代关系的表达（口径 A）：

GB/T 24067-2014（标准状态 = 被替代）  ←──┐
                                        │「被替代标准」指向旧版
GB/T 24067-2024（标准状态 = 现行）  ────┘

模型绑定的是【具体某一条记录】（即某个版本），快照语义天然成立。
```

> **备选口径 B**：一个标准 = 一条记录，版本作为版本化字段。取舍见 §9 Q02。

### 1.3 数据来源与维护边界

| 维度 | 说明 |
| :--- | :--- |
| 数据来源 | **系统预置**（平台运营维护，全体租户只读 —— 方案 §3.3.3 将标准文件列为 `PUBLIC`） + **组织自建**（若采纳，【待确认 Q03】） |
| ERP是否数据源 | 否 |
| 新增编辑 | 支持（系统预置标准仅平台运营可维护） |
| 子表 | 无（附件由附件管理承载） |
| 导入导出 | 导出：支持；导入：V0.1 不支持（【待确认 Q11】） |
| 状态与执行 | 标准状态（现行 / 被替代 / 作废）+ 使用状态（启用 / 禁用）；无版本化、无审核流、无外部推送 |
| 关键唯一键 | 「标准编号 + 标准版本」唯一 |
| 历史兼容 | 被核算模型引用的标准文件**不可编辑、不可删除**（对齐方案 **§4.9 不可变对象**）；如需变更，以**新版本记录**承载；状态变更不追溯已建模型，需按新口径重算走 **E13** |

### 1.4 关键数据约束

| 约束ID | 约束 | 影响对象 |
| :--- | :--- | :--- |
| D01 | **「标准编号 + 标准版本」唯一** | 主表 |
| D02 | 「被替代标准」**不得自引用、不得成环**（A 替代 B、B 又替代 A 不成立） | 自引用 |
| D03 | 标准状态 = 「作废」时，**不可被新的核算模型引用** | 主表 |
| D04 | 「数据来源 = 系统预置」时，租户**只读**（不可编辑 / 禁用 / 删除） | 主表 |
| D05 | **被核算模型引用过的标准文件不可编辑、不可删除**（§4.9） | 主表 |
| D06 | 失效日期必须 **≥ 生效日期**；未失效时可为空 | 主表 |
| D07 | 标准编号格式：字母 + 数字 + `/` + `-` 组合（如 `GB/T 24067`、`ISO 14067`）【待确认 Q09】 | 主表 |
| D08 | 标准版本为 **4 位年份**（如 `2024`）【待确认 Q09】 | 主表 |
| D09 | 附件为**选填**，可上传多个（推荐口径 A） | 附件 |
| D10 | 标准状态为「现行」且使用状态为「启用」时，才可被新模型引用 | 主表 |

## 5. 枚举值

### 5.1 标准类型（【待确认 Q07】）

| 枚举值 | 含义 | 备注 |
| :--- | :--- | :--- |
| 国家标准 | 如 GB / GB/T | 决策 **D3** 首发的 `GB/T 24067-2024` 属此类 |
| 行业标准 | 如 YB / LY / JB | — |
| 地方标准 | 如 DB | — |
| 团体标准 | 如 T/XXX | — |
| 国际标准 | 如 ISO / IEC | 如 ISO 14067 |
| 国外标准 | 如 PAS 2050（英国）、EN | — |
| 企业标准 | 如 Q/XXX | 与「组织自建」数据来源关联 |

### 5.2 标准状态（【待确认 Q01】）

| 枚举值 | 含义 | 是否可被新模型引用 | 备注 |
| :--- | :--- | :---: | :--- |
| 现行 | 当前有效、可依据执行 | 是 | 新建默认 |
| 被替代 | 已被新版标准替代 | 否 | 需填写「失效日期」 |
| 作废 | 已废止、不再适用 | 否 | — |
| 即将生效【待确认】 | 已发布但未到生效日期 | 否（生效后方可引用） | 若不需要可删除该取值 |

### 5.3 数据来源（仅用于权限判定）

| 枚举值 | 含义 | 是否默认 | 备注 |
| :--- | :--- | :---: | :--- |
| 系统预置 | 平台统一维护的标准文件 | 是 | 按方案 §3.3.3 为 `PUBLIC`，全平台只读，租户可引用 |
| 组织自建 | 组织自行维护的标准文件 | 否 | 【待确认 Q03】是否开放；若开放则为 `ORG`，本组织可编辑 |

### 5.4 使用状态

| 枚举值 | 含义 | 是否默认 | 备注 |
| :--- | :--- | :---: | :--- |
| 启用 | 可被核算模型引用 | 是 | 需同时满足标准状态为「现行」（D10） |
| 禁用 | 不可被新模型引用 | 否 | 系统预置标准、已被引用的标准不可禁用 |

## 9. 待确认事项

### 9.1 已确认决策

| 编号 | 结论 |
| :--- | :--- |
| **术语口径（2026-09-20）** | 「**数据来源**」只有「系统预置 / 组织自建」一个含义，仅用于权限判定 |
| **不设「可见性」** | 由「数据来源」推导（与物料 / 能源 / 计量单位库一致） |
| **D3 首发数据** | 系统预置第一条标准文件为 **`GB/T 24067`** / 版本 **`2024`**，供首个核算模型绑定（方案 §4.3.1、§十一 ⑦） |

### 9.2 优先处理

**Q01：是否上传「标准文件本体」**

| 出处 | 表述 |
| :--- | :--- |
| 方案 §2.3 A1-3 | 「**上传**核算标准文件，记录名称、编号、版本、适用范围、生效日期」→ 暗示有文件本体 |
| 方案 §4.2.5 | 只列元数据，**未提文件本体** |

| 口径 | 取舍 |
| :--- | :--- |
| **A（推荐）** | **元数据 + 可选附件**：附件（PDF）选填、可多个，由附件管理（§C6）承载。**本清单已按此撰写** |
| B | 仅元数据，不存文件本体：完全规避版权风险 |

> **版权提示**：GB/T 与 ISO 标准文本均受版权保护，内部分发亦可能受限。若采纳口径 A，**附件仅限内部查阅，不得作为对外交付物**（详见业务 PRD §5）。

**Q02：同一标准的多个版本如何表达**

| 口径 | 结构 | 取舍 |
| :--- | :--- | :--- |
| **A（推荐）** | **一个版本 = 一条记录**，唯一键 = 「标准编号 + 版本」，用「被替代标准」表达新旧关系 | 简单，与「无版本化」的模块定性一致；模型绑定具体某条记录，快照语义天然成立。**本清单已按此撰写** |
| B | 一个标准 = 一条记录 + 版本化字段 | 引入版本管理，与模块定性冲突；模型"绑哪个版本"需额外表达 |

**Q03：组织能否自建标准文件**

| 出处 / 实际 | 情况 |
| :--- | :--- |
| 方案 §3.3.3 | 标准文件被列为 **`PUBLIC` 系统预置数据**（与 environment 因子、行业库、计量单位、阶段基线并列）→ 暗示仅平台维护 |
| 业务实际 | 企业可能有**企业标准、客户指定的标准**需要录入 |

**推荐**：允许组织自建（数据来源 = 组织自建，可见性 `ORG`），以覆盖企业标准与客户要求场景。
