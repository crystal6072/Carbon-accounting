## 1. 需求概述

### 1.1 需求背景

行业库是平台「**通用 → 行业**」的**唯一扩展点**（方案 §4.2.5）。方案 §1.2 明确了本版本的通用性立场：

```text
行业只作为"配置结果"存在：
  木竹 / 钢铁 / 纺织 / 食品 …… 均通过「行业库 + 阶段配置 + 因子集 + 规则模板」组合接入，
  引擎与数据模型不感知具体行业。
```

在这一立场下，**行业库只提供「锚点」，不提供「算法」与「参数」**：

| 归属 | 模块 | 行业库的角色 |
| :--- | :--- | :--- |
| 有哪些行业、叫什么、怎么分级 | **行业库（本模块）** | 唯一维护方 |
| 该行业用哪些生命周期阶段（基线） | 生命周期阶段 A1-10 | **不承载**（§4.2.4：基线不是独立对象） |
| 该行业用哪些排放因子 | 排放因子库 A2-6 | **不承载** |
| 该行业怎么算（计算 / 检测 / 报告规定） | 核算模型 A2-3 | **不承载** |

因此「行业库 + 阶段配置 + 因子集 + 规则模板」的**组合关系不落成行业库上的引用字段**，而由各模块的「适用行业」字段**反向关联**到行业库。这是本模块最核心的定位边界（见 §4）。

同时，行业库是下游 **5 个模块**行业字段的**引用源**：物料（适用行业，多选）、能源（适用行业，多选）、产品信息 / 工艺流程 / 工序（所属行业，单选必填）、生命周期阶段（适用行业，多选）。方案将其列为 **P2**，但下游依赖强度已远超 P2 —— 该冲突的处理结论见 §5.2。

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :--- | :--- | :--- |
| G1 | 提供行业分类字典 | 字段覆盖方案 §2.3 A1-4「行业分类」诉求（编码 / 名称 / 上级 / 描述 / 指南） |
| G2 | 支撑下游 6 处的行业引用 | 物料 / 能源 / 产品 / 工艺流程 / 工序 / 生命周期阶段的下拉候选**全部来自本模块**（启用状态） |
| G3 | 划清与阶段 / 因子 / 模型的边界 | 行业库**不含**阶段基线、因子集、规则模板字段（§4） |
| G4 | 下游依赖不阻塞 | 行业库交付前，下游行业字段的降级方案明确可执行（§5.2） |
| G5 | 引用后的主数据安全 | 被引用的行业不可删除 / 不可禁用；主数据变更不追溯已建项目（§6） |
| G6 | 行业化配置可复用 | 新增行业只需在行业库建一条记录，其余配置在各模块按「适用行业」打标，**不改引擎、不改数据模型**（方案 §九「可扩展」） |

### 1.3 In Scope / Out of Scope

**In Scope**

| 能力 | 说明 |
| :--- | :--- |
| 行业列表与查询 | 按名称、描述（模糊）、上级行业、数据来源、使用状态筛选 |
| 新增 / 编辑行业 | 编码、名称、上级行业、描述、排序号维护 |
| 查看行业 | 详情 + 引用情况（哪些下游模块引用了本行业） |
| 行业核算指南维护 | 附件 / 外链，选填、可多个（【待确认 Q11】） |
| 两级分类维护 | 一级 / 二级（由「上级行业」推导） |
| 启用 / 禁用 | 行操作 + **批量启用 / 禁用** + 二次确认 |
| 导出 | 导出当前查询结果（列表字段全量） |

**Out of Scope**

| 不做项 | 说明 |
| :--- | :--- |
| 审核流 / 版本化 | 基础数据，均不涉及 |
| **在行业库定义参数与算法** | 阶段基线归 A1-10、因子集归 A2-6、计算 / 检测 / 报告规定归 A2-3（§4） |
| **在行业库重建「阶段基线」实体** | 与方案 §4.2.4 修订说明、附录二 · 已回改第 11 项冲突，明确不做 |
| 行业核算边界（摇篮到大门 / 坟墓） | 归**核算项目**（P19 / P20），行业库不含边界字段 |
| 三级及以上行业分类 | 本期只做两级（D08） |
| 行业别名 / 英文名称 / 典型产品 | 本期不做，可写入「行业描述」（【待确认 Q09 / Q10】） |
| Excel 导入 | V0.1 不支持（【待确认 Q08】） |
| 批量删除 | 本期不做（【待确认 Q07】） |

### 1.4 涉及角色

| 角色 | 数据域 | 在本模块的职责 |
| :--- | :--- | :--- |
| 平台运营管理员 | 平台域 | 维护**系统预置行业**（`PUBLIC`，方案 §3.3.3） |
| 组织管理员 | `SUB_TREE` | 维护**组织自建行业**（细分行业）—— **若采纳**（【待确认 Q03】） |

### 1.5 影响范围

| 方向 | 模块 | 影响 |
| :--- | :--- | :--- |

## 2. 用户与使用场景

### S01 维护系统预置行业（平台侧）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 平台需要新增 / 调整行业分类（如接入新行业包） |
| 操作流程 | 平台运营进入行业库 → 新增行业 → 选择上级行业（可空 = 一级）→ 填名称 / 编码 / 描述 → 可选上传核算指南 → 保存 |
| 预期结果 | 行业创建成功，数据来源 = 系统预置，使用状态 = 启用；下游 6 处下拉立即可选 |

### S02 组织自建细分行业（**若采纳**）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 组织的业务细分口径不在系统预置中（如「电解铝」） |
| 操作流程 | 组织管理员新增行业 → 选择上级行业 → 填写名称与描述 → 保存 |
| 预期结果 | 行业创建成功，数据来源 = 组织自建，`ORG`；**本组织及上级可选，其他租户不可见**；与其他组织的同名行业互不冲突（同级唯一按数据来源域判定，【待确认 Q03】） |

### S03 上传 / 更新行业核算指南

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要为行业挂上核算指南供查阅 |
| 操作流程 | 编辑行业 → 上传附件或填写外链 → 保存 |
| 预期结果 | 指南挂载成功（可多个）；**仅用于查阅，不参与计算与校验**；缺失不影响任何下游能力（D07） |

### S04 启用 / 禁用行业（单个 + 批量）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 某行业不再使用；或误建的行业需停用 |
| 操作流程 | 行操作「禁用」或勾选多条后「批量禁用」→ 二次确认 |
| 预期结果 | 成功项立即生效，**下游新业务不可再选**；命中「系统预置」或「已被引用」的条目**跳过并在失败清单中返回**（R-005 / R-006 / D09） |

### S05 行业被下游引用后的限制

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 行业已被物料 / 能源 / 产品 / 工艺流程 / 工序 / 生命周期阶段引用 |
| 操作流程 | 尝试删除或禁用该行业 |
| 预期结果 | **不可删除、不可禁用**（R-007）；详情页展示「引用本行业的对象清单」；如需停用，需先解除下游引用或改为**新建替代行业 + 迁移** |

### S06 下游页面选择「适用行业 / 所属行业」（引用方视角）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 在物料 / 能源 / 产品 / 工艺流程 / 工序 / 生命周期阶段上维护行业字段 |
| 操作流程 | 从下拉中选择行业（支持按名称 / 描述检索） |
| 预期结果 | 候选**仅含启用状态**的行业；已引用但后续被禁用的行业**仍只读回显并标注「已禁用」**，不可再被新选择（**具体控件与交互归各模块 Demo PRD**） |

### S07 新行业接入（组合式上线，**本模块只负责第一步**）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要支持一个新行业（如木竹 → 电解铝） |
| 操作流程 | ① 行业库新增行业；② 生命周期阶段 A1-10 为相关阶段标注「适用行业」；③ 排放因子库 A2-6 补充行业因子集；④ 核算模型 A2-3 配置 / 发布行业版模型 |
| 预期结果 | 行业包可用；**行业库侧无需新增任何参数字段**（口径 A 的验证点）；引擎与数据模型不变（方案 §九「可扩展」） |

### S08 查看行业详情与引用情况

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要确认行业信息或被谁使用 |
| 操作流程 | 列表点名称进入详情 → 查看元数据、核算指南、下级行业、引用情况 |
| 预期结果 | 展示完整字段 + 引用清单 + 下级行业清单 |

## 4. 行业库的定位边界（**核心章节之一**）

### 4.1 「管什么 / 不管什么」总表

| 边界对象 | 归属模块 | 行业库的写法 |
| :--- | :--- | :--- |
| 行业分类、行业元数据（编码 / 名称 / 上级 / 描述 / 排序） | **行业库** | 本模块维护 |
| 行业核算指南（附件 / 外链） | **行业库**（按字段清单结论，【待确认 Q11】） | 选填、仅查阅、不参与计算与校验 |
| **阶段基线**（某行业用哪些生命周期阶段） | **生命周期阶段 A1-10** | **不在行业库建阶段集合实体**；基线 = 按「行业 + 边界」从阶段库**查询**出来的集合（§4.2.4 / 附录二 第 11 项）。行业库侧**不加字段** |
| 阶段顺序、按边界的三态纳入规则（必须 / 可选 / 不纳入） | **生命周期阶段 A1-10** | 只引用，不定义 |
| 核算边界（摇篮到大门 / 摇篮到坟墓） | **核算项目 P19 / P20** | 行业库不含边界字段 |
| 排放因子集（含电网因子按区域 + 年度） | **排放因子库 A2-6** | 只引用，不定义 |
| 计算规则模板、检测规则、报告规定、分配规则 | **核算模型 A2-3 / A2-1 / A2-4 / A2-8** | 只引用，不定义 |
| 「适用行业」的引用关系 | 各模块自身字段 | 行业库只作为**被引用方**，不反向持有参数 |
| 可见性与归属组织 | 全局口径（方案 §3.3.3） | 可见性由「数据来源」推导，不单独设字段 |

### 4.2 为什么不在行业库挂「行业参数模板」（口径 A 的论证）

| 论据 | 出处 |
| :--- | :--- |
| 「基线」**不是独立对象**，**不另建阶段基线实体**；基线是查询结果 | 方案 §4.2.4 修订说明；附录二 · 已回改第 11 项 |
| 阶段字段已自带「适用行业」与「按边界的纳入规则」，再在行业库引用一遍 = **两层维护** | 同上（原理由原文） |
| 新行业的接入方式是「**行业库 + 阶段配置 + 因子集 + 规则模板**」四者组合，不是行业库内嵌套 | 方案 §1.2 |
| 行业库优先级 **P2**，但因子库（A2-6）与模型（A2-3）尚未交付；若在行业库挂它们的引用字段，行业库会被未交付模块阻塞 | 方案 §八 P06 / P15 / P14 |

> 若业务坚持在行业库呈现「该行业的配置概览」，**只读反查展示**（如详情页列出「引用本行业的生命周期阶段」）即可满足，**仍不设可维护字段**。

## 5. 下游引用与降级方案（**核心章节之二**）

### 5.1 引用方与引用口径

| 引用方 | 引用字段 | 引用口径 | 可选范围 | 被禁用行业的表现 |
| :--- | :--- | :--- | :--- | :--- |

### 5.2 「行业库 P2 与下游依赖强度不匹配」的处理（**必须给结论**）

| 方案 | 内容 | 代价 / 风险 |

| **A（推荐）** | **行业库提前到 P0**：至少交付「系统预置行业 + 列表 / 新增 / 编辑 / 启停」最小闭环 | 排期前移。**理由：产品信息 / 工艺流程 / 工序的「所属行业」已是必填字段**，若不交付行业库，这三个模块的必填校验**无法落地**，无法用「不展示」化解 |

## 6. 业务规则

| 规则编号 | 规则名称 | 触发条件 | 处理逻辑 | 例外策略 |
| :--- | :--- | :--- | :--- | :--- |
| R-001 | 同级名称唯一 | 新增 / 编辑保存时 | 行业名称在**同级**内唯一（D01）：一级行业之间唯一；同一上级下的二级行业之间唯一 | 重复时阻断保存并提示已存在的行业 |

| R-007 | **被引用后不可删除、不可禁用** | 行业已被任一引用方引用时 | 删除与禁用均阻断（D05），并列出引用对象清单；如需停用，应先解除引用或**新建替代行业并迁移** | 命中时阻断 |
| R-008 | 批量操作部分成功 | 执行批量启用 / 禁用时 | 按勾选项逐条执行；命中系统预置（R-005）或已被引用（R-007）的条目**跳过**，返回成功数与失败清单（D09） | 不整体回滚，返回失败清单 |

## 7. 状态与操作矩阵

### 7.1 状态维度说明

| 状态维度 | 取值 | 来源 |
| :--- | :--- | :--- |
| 数据来源 | 系统预置 / 组织自建 | 字段清单（决定可编辑性与可见范围） |
| 使用状态 | 启用 / 禁用 | 字段清单（用户操作，含批量） |
| 引用状态 | 未被引用 / 已被引用 | 系统自动关联（只读，反查物料 / 能源 / 产品 / 工艺流程 / 工序 / 生命周期阶段） |
| 层级 | 一级 / 二级 | 由「上级行业」推导（只读） |

> 本模块**无版本维度、无审核维度、无生效日期维度**。

### 7.2 操作矩阵

| 数据来源 | 层级 | 引用状态 | 编辑 | 禁用 | 删除 | 被下游选中 | 备注 |
| :--- | :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| 系统预置 | 一级 / 二级 | 未被引用 | 否（仅平台运营） | 否（R-005） | 否（R-005） | 是 | 租户只读 |
| 系统预置 | 一级 / 二级 | 已被引用 | 否 | 否 | 否（R-007 / R-009） | 是 | 租户只读 |
| 组织自建 | 二级 | 未被引用 | 是 | 是 | 是 | 是 | 完整生命周期 |
| 组织自建 | 二级 | 已被引用 | 是（元数据与指南） | **否**（R-007） | **否**（R-007） | 是 | 禁用 / 删除双重阻断 |
| 组织自建 | 一级 | 未被引用 | 是 | 是 | **否（存在下级行业）** | 是 | 需先处理下级（R-009） |
| 组织自建 | 一级 | 已被引用 | 是 | 否 | 否 | 是 | — |

**闭环校验**

- 一级行业：有完整的「编辑 → 禁用 → 删除」生命周期，但删除受「无下级 + 无引用」双重前置（R-009）；
- 二级行业：未被引用时有完整生命周期；被引用后收敛为「仅编辑元数据」（R-007）；
- 系统预置行业：租户侧**全锁**，仅平台运营可维护（R-005）；
- 「禁用」为**软停用**：已引用处仍只读回显 + 标注「已禁用」（§5.1）；
- 无版本维度、无审核分支，无死状态。

## 附录 · V0.2 范围收敛记录（2026-09-21）

> **收敛依据**：业务表态「行业库只做行业字典维护，不用太复杂，前端交互像产品分类就行」。本模块定位回归**轻量行业字典**，原型已按收敛后口径实现（`06prototypes/6-1系统原型骨架` · `/basic/industry`）。
>
> **收敛原则**：只保留「有哪些行业、叫什么、怎么分级」；凡是**不参与计算、不参与校验、需要额外维护成本**的能力一律后置。

### 一、收敛项清单

| # | 能力 | 原设计（V0.1） | 现设计（V0.2） | 原因 |
| :-: | :--- | :--- | :--- | :--- |
| 1 | 前端交互 | 列表 + 批量操作（对齐物料库） | **左树 + 右表 + 弹窗**（对齐产品分类） | 行业天然是**两级分类**，树表联动比长列表更贴合；与产品分类交互统一，降低理解成本 |
| 2 | 行业核算指南 | 附件 / 外链，选填、可多个（对标竞品列） | **不做** | 方案 §2.3 A1-4 / §4.2.5 均未提；不参与计算与校验。若后续需要"指南查阅"，建议在**标准文件库（A1-3）**统一承载 |
| 3 | 批量启用 / 禁用 | 支持（逐条执行 + 跳过清单） | **不做**（启用 ↔ 禁用走行操作） | 行业数量少（字典级），批量收益低；对齐产品分类 |
| 4 | 删除 | 支持（受「已禁用 + 未被引用 + 无下级」三重前置约束） | **不做**（无删除入口） | 行业是被下游 5 处引用的**基础字典**，删除风险高；对齐产品分类「V0.1 不提供删除」 |
| 5 | 被引用约束 | 「已被引用则不可禁用 / 不可删除」+ 引用情况只读反查 | **不做** | 删除能力移除后，禁用是唯一"退出"手段，若再拦禁用会导致字典无法收敛；引用一致性由各引用方各自负责 |
| 6 | 数据来源 | 系统预置 / 组织自建（`PUBLIC` / `ORG`） | **不做** | 与物料库 / 能源库 / 生命周期阶段同口径（这些模块也未设该字段）；组织自建能力待后续统一决策 |
| 7 | 描述参与检索 | 查询区为「行业名称/描述」（对齐竞品 placeholder） | **只检索编码 / 名称 / 状态** | 与产品分类查询区一致 |
| 8 | 行业编码 | 选填、可系统生成 | **必填且唯一** | 对齐产品分类（编码必填）；作为树节点与下游引用的稳定标识 |

### 二、规则状态（R-001～R-010）

| 规则 | 状态 | 说明 |
| :--- | :--- | :--- |
| R-001 同级名称唯一 | **生效** | 一级行业之间唯一；同一上级下的二级行业之间唯一 |
| R-002 编码唯一 | **生效** | 编码必填（V0.2 调整）且唯一 |
| R-003 层级合法性 | **生效** | 仅两级；上级必须为一级行业；不得自引用 |
| R-004 描述约束 | **生效（收窄）** | 仅保留「描述 ≤ 500 字符」；指南相关约束废止 |
| R-005 系统预置只读 | **废止** | 随「数据来源」移除 |
| R-006 组织自建可编辑 | **废止** | 随「数据来源」移除 |
| R-007 被引用后不可删除 / 不可禁用 | **废止** | 见收敛项 4 / 5 |
| R-008 批量操作部分成功 | **废止** | 见收敛项 3 |
| R-009 删除规则 | **废止** | 无删除能力 |
| R-010 主数据变更不追溯已建项目 | **生效（业务规则保留）** | 行业主数据变更不影响已建核算项目（项目按加载时的阶段基线快照冻结）；项目侧快照与重算走 E13 |

> 生效规则共 **5 条**（R-001～R-004、R-010），低于「8～10 条」的上限 —— 符合"轻量字典"的定性。
