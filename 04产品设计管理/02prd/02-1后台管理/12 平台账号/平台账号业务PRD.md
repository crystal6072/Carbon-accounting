## 1. 前置问题

### 1.1 平台账号与租户成员是否共用一张账号表

**结论：共用一张表。平台账号表即全系统账号表，租户成员关联本表，不另建账号表。**

| 对象 | 落表 | 关系 | 说明 |
| :--- | :--- | :--- | :--- |
| 账号 | 账号表，全局 1 份 | 主对象 | 登录名、手机号、密码、账号状态、锁定计数、首登改密标记 |
| 平台侧身份 | 平台角色关联 | N:N | 有则出现在平台账号列表，靠角色取权限 |
| 租户侧身份 | 成员关系表，本模块不写 | N:N | 关联本表账号，只引用；与平台角色互斥（存量双身份为例外） |

判断依据：

1. §5.9 只有一套登录入口，登录名或手机号二选一，凭证必须唯一，不能按域分裂成两套。
2. §5.2.1-1 要求登录名、手机号各自全局唯一；§5.5.1-6 要求成员「关联已有账号、不建号」——所有账号只有一处存放。
3. §5.3.1-7 角色成员页签「平台查平台账号、租户查成员关系」，两者查的是同一批账号的两个不同切面。

推论：

1. 账号只有一份，平台侧与租户侧都是在同一账号上挂载身份，账号本身不设归属标签。
2. 平台角色与租户成员**互斥**：持平台角色的账号不得成为租户成员，租户成员不得被分配平台角色；存量双身份按例外处理并逐步清理。
3. 平台后台「平台账号」菜单只展示持有生效平台角色的账号，无平台角色的账号不在本菜单出现（改由「账号管理 · 全部账号」视图查看）。

### 1.2 平台账号如何被识别为平台账号

**结论：靠是否持有生效平台角色识别，不设账号归属标签。**

| 项 | 内容 |
| :--- | :--- |
| 识别判据 | 账号存在至少 1 条未收回的平台角色关联 |
| 不采用的判据 | ① 账号上的归属类型字段（会把「同时是平台人员与租户成员」这个合法状态卡死）② 无租户成员关系（可同时具备租户身份）③ 登录入口（全站同一入口） |

判断依据：

1. 平台角色天然只挂平台侧功能码、只产生平台端权限（§5.3.2-1），持有平台角色即构成平台侧身份。
2. 平台账号至少保留 1 个平台角色（§5.3），角色不会被清空，因此账号不会因角色收回而从列表消失。
3. 账号不设归属标签；平台角色与租户成员互斥，持平台角色的账号不得挂租户成员关系（存量双身份按例外）；平台人员查看租户数据走「进入租户」只读。

**识别 ≠ 准入**，两层分开：

| 层次 | 判据 |
| :--- | :--- |
| 识别为平台账号 | 存在至少 1 条未收回的平台角色关联（账号状态只有启用 / 停用两态，注销即物理删除，不存在注销态账号） |
| 允许进入平台后台 | 识别成立 且 账号状态为启用 |

### 1.3 超级管理员如何判定与保护

**结论：超管身份按角色持有动态判定；账号保护只针对「系统内置根账号」这一个 `is_builtin` 标记，不针对「超管」这个角色。**

两层口径必须分开：

| 层次 | 判据 | 作用 |
| :--- | :--- | :--- |
| 是不是超管 | 账号持有「角色 = 超级管理员」的生效关联，且账号状态为启用 | 决定能否进入平台后台、能否执行超管专属动作（重置密码） |
| 是不是内置根账号 | 账号表 `is_builtin = 1`（系统初始化写入，全系统仅 1 条） | 决定该账号是否在账号管理中**只读** |

| 项 | 内容 |
| :--- | :--- |
| 有效超管计数 | 满足「持超管角色 + 启用」的账号数，每次操作前实时统计（根账号始终计入） |
| 根账号数量 | 全系统恒为 1 个，由初始化脚本写入，产品内不可新增、不可删除 |
| 超管角色变更入口 | 只能经「分配平台角色」增加或移除，不设「设为超管」独立按钮；根账号不可经此入口变更 |
| 根账号的初始口令 | 初始化脚本写入，由部署实施方线下交付；登录后由本人自助维护，产品内不提供他人重置入口 |

保护措施：

| # | 保护措施 | 作用对象 | 依据 |
| :--- | :--- | :--- | :--- |
| P1 | 超级管理员角色不可删、不可停用、不可取消内置 | 角色本身 | §5.3.1-5 |
| P2 | 系统内置根账号在账号管理中只读：不可编辑、不可分配角色、不可停用、不可启用、不可注销；**例外：允许本人重置自己的密码**（走标准重置流程，新密码一次性展示） | 根账号 | §5.12、E22–E24 |
| P2a | 根账号登录后仍是完整超管：可对全部非根账号执行新建 / 编辑 / 分配角色 / 重置 / 启停 / 注销 | 根账号（作为操作人） | §5.12-8 |
| P3 | 根账号恒为启用状态且恒持超级管理员角色，因此系统结构性保证始终存在 1 个可登录超管；非内置超管被停用 / 注销 / 移除超管角色时无需再计数阻断 | 全部账号 | §1.3、§3.2 |
| P4 | 任一超管可重置其他非根账号的密码，不可重置自己，也不可重置根账号 | 全部账号 | §5.6 |
| P5 | 根账号口令遗失、或全部超管均无法登录时，产品内不设自助恢复入口，统一转运维恢复，须双人复核并出复盘 | 全部账号 | §5.8、§5.12-5 |

> 保护阈值不再按「剩余超管数」动态计算：根账号不可停用 / 不可注销 / 不可移除角色，已天然满足「至少 1 个可登录超管」，且不会被平台内部任何操作接管。本期仍只保留 1 个根账号，不提高至 2 个。

## 2. 需求描述

维护平台自有账号：建号授角色、改档、停用启用、重置密码、注销。系统初始化时内置 1 个只读的超管根账号，作为兜底建号与授权入口（建号并分配超管角色由它完成）；由它建立的非内置超管账号按普通平台账号运维。

```mermaid
  D -->|是| E[拒绝 仅可查看]
  D -->|否| D2{停用后该租户可用管理员归零}
  D2 -->|是| D3[拒绝 引导先到租户管理更换主管理员]
  D2 -->|否| F{名下有租户身份}
  F -->|是| G[提示 N 个租户身份将同时失效]
  F -->|否| H[置账号为停用]
  G --> H
  H --> I[踢下线 会话立即失效]
  I --> J[写审计]
```

> 非内置超管停用后，系统仍有根账号可用，故不再按「最后一个启用超管」阻断。

### 3.3 重置密码

```mermaid
flowchart TD

  B -->|是且操作人非本人| C[拒绝 仅可查看]
  B -->|是且操作人是本人| D[选择重置方式：随机生成 / 自定义]
```

本模块不设产品内自助恢复入口，无可画分支。全部超管均无法登录时转运维恢复，规则见 §5.8。

## 5. 业务规则

### 5.1 新建

1. 操作人填写登录名、手机号、姓名；邮箱为非必填字段，可不填。
2. 系统校验登录名全局唯一。
3. 系统校验手机号全局唯一。
4. 系统校验登录名不为 11 位纯数字。
5. 系统校验登录名不区分大小写、去空格、转半角后判重。
6. 操作人分配 1 至 5 个平台角色。
7. 系统拒绝 0 个平台角色的提交。
8. 系统生成一次性密码并一次性展示。
9. 系统置首登改密标记。
10. 系统置平台账号为启用。
11. 系统记录创建人。
12. 系统写审计。
13. 系统不限制平台账号总数。
14. 系统允许头像为空。
15. 系统允许操作人在新建时分配「超级管理员」角色，超管账号由内置根账号建立（引导路径）；新建的超管账号**不是**内置根账号（`is_builtin = 0`），此后按普通平台账号运维，可被编辑 / 重新分配角色 / 停用 / 启用 / 重置 / 注销。
16. 系统不因新建超管账号而复制、修改或替换内置根账号；根账号不受建号流程影响。

### 5.2 编辑

1. 操作人修改姓名。
2. 操作人修改手机号。
3. 系统校验手机号格式。
4. 系统校验手机号全局唯一。
5. 系统不修改登录名。
6. 操作人上传、更换或移除头像。
7. 系统允许头像为空。
8. 系统记录更新人与更新时间。
9. 系统写审计并记手机号前后值。
10. 系统拒绝编辑**系统内置根账号**（`is_builtin = 1`）：根账号姓名、手机号、邮箱、头像均不可改，接口返回「系统内置根账号受保护，仅支持查看」（E22）。

> 登录名创建后不可改，手机号可改，见 §9 D02。
> 头像非必填，见 §5.11。

### 5.3 分配平台角色

1. 操作人为目标平台账号增减平台角色。
2. 系统只展示归属类型为平台的启用角色。
3. 系统校验增减后角色总数在 1 至 5 之间。
4. 系统校验增减后至少保留 1 个平台角色。
5. 系统对非内置账号校验有效超管数：移除其超级管理员角色后若系统已无启用超管则拒绝；内置根账号恒持超级管理员角色，故该场景实际不会命中。
6. 系统实时生效并踢目标账号下线。
7. 系统写审计并记前后值。
8. 系统只展示归属类型为平台的启用角色（角色定义与维护在平台侧「平台角色管理」），不出现任何租户角色；提交含租户角色时拒绝（平台角色只授予平台人员，与租户角色完全隔离）。
9. 系统不把平台角色写入该账号的租户成员关系，也不因账号持有租户成员关系而改动其平台角色。
10. 系统拒绝为**系统内置根账号**增减平台角色：根账号的角色组合由初始化写入（超级管理员），产品内不可变更（E23）。

### 5.4 停用

1. 操作人对目标平台账号发起停用。
2. 系统校验目标不是操作人本人。
3. 系统校验目标不是**系统内置根账号**：根账号不可停用，命中即阻断（E24）。
4. 系统校验目标停用后**不会使任一启用中的租户失去可用管理员**：按「可用管理员 = 成员状态正常 且 账号启用 且 持『租户管理员』角色」逐租户计算，扣减本账号后为 0 则阻断，提示「该人员为在任『XX 租户』的主管理员，暂时不允许停用，请先更换管理员」，并提供直达「租户管理 → 更换主管理员」的入口。
   - 判定**不看租户状态**：租户已停用时不纳入保护范围（停用期间无人在用），允许停用其管理员账号；该租户再启用时由租户管理另做管理员校验（租户管理 PRD E38）。
5. 系统统计该账号名下的有效租户成员关系数（仅存量双身份例外会存在）。
6. 系统在确认弹窗展示受影响租户身份数与租户名称。
7. 操作人确认后系统置账号为停用。
8. 系统踢目标账号下线并使会话立即失效。
9. 系统不改该账号的租户成员关系记录。
10. 系统不收回平台角色关联。
11. 系统使该账号在租户端的登录同时失效。
12. 系统写审计，记受影响租户身份数。

### 5.5 启用

1. 操作人对停用状态的平台账号发起启用。
2. 系统校验目标至少持有 1 个生效平台角色。
3. 目标角色为 0 时系统引导先分配角色。
4. 系统置平台账号为启用。
5. 系统写审计。
6. 系统不接受对**系统内置根账号**的启用请求：根账号恒为启用态，不存在停用态与启用动作（E24）。

### 5.6 重置密码

1. 超管对目标平台账号发起重置。
2. 系统校验目标不是操作人本人。
3. 操作人选择重置方式。
4. 系统提供随机生成与自定义两种方式，默认随机生成。
5. 操作人选择自定义时填写新密码与确认新密码。
6. 系统校验自定义密码不少于 8 位。
7. 系统校验自定义密码含大写、小写、数字、特殊字符中的三类。
8. 系统校验两次输入一致。
9. 系统生成新密码并一次性展示。
10. 系统使旧密码立即失效。
11. 系统使目标账号全部会话失效。
12. 系统写密码重置记录并记重置方式。
13. 系统写审计。
14. 系统置首登改密标记。
15. 新密码遗失时系统只允许再次重置，不提供明文找回。
16. 系统允许超管对**租户成员账号**发起重置（「全部账号」视图入口，见 §10.3-7）；对象含租户主管理员，与租户管理 PRD §4.18 共用同一重置服务，不新增功能码。
17. 系统在对租户成员执行重置时，**重置原因必填**（枚举：忘记密码 / 人员失联 / 安全事件 / 租户管理员无法处理 · 平台协助，可附补充说明）。
18. 系统在对租户成员执行重置时，弹窗展示跨租户影响：该账号同时属于 N 个租户、重置将使其在**全部租户**的会话失效，并要求确认。
19. 系统写重置记录时按对象区分 `reset_type`：平台账号记 1（超管重置），租户成员记 4（超管兜底重置租户成员），并记 `source_channel`（account）与 `tenant_id`（当前上下文租户，可空）。
20. 系统拒绝**他人**重置系统内置根账号的密码（含超管重置）：避免任一超管借此接管根账号（E24）。**唯一例外：根账号本人可重置自己的密码**（账号管理行内 / 详情页「重置密码」，仅 `isSelf` 可见，§5.12-5）；重置后标记首登改密，下次登录强制换新密码；口令遗失按 §5.8 走运维恢复。

> 平台账号的重置不收集原因（原型已取消，见 Changelog V0.9）；**租户成员的兜底重置必须收集原因**——跨租户操作需可追责，这是唯一的差异化口径。随机 / 自定义二选一与密码复杂度校验两种对象一致。

### 5.7 注销（物理删除）

1. 操作人对目标平台账号发起注销。
2. 系统校验目标不是操作人本人。
3. 系统校验目标不是**系统内置根账号**：根账号不可注销，命中即阻断（E24）。
4. 系统校验注销后**不会使任一启用中的租户失去可用管理员**（口径同 §5.4-4）；命中则阻断，提示先到「租户管理 → 更换主管理员」完成交接。
5. 系统统计该账号名下的有效租户成员关系数（仅存量双身份例外会存在），二次确认弹窗展示影响说明（租户名称、将失效的租户身份数）并要求勾选知悉。
6. 操作人确认后，系统把该账号的全部有效租户成员关系置为「已移出」，移出方式记「账号注销」（removed_type = 3），记录保留并保存账号姓名 / 手机号快照。
7. 系统物理删除该账号的全部平台角色关联。
8. 系统物理删除该账号的密码重置记录。
9. 系统物理删除账号记录。
10. 系统踢目标账号下线并使全部会话失效。
11. 系统释放登录名与手机号，二者可被重新注册使用。
12. 系统写审计，冗余记录姓名、登录名、手机号快照、操作人、受影响租户身份数，审计长期保留。
13. 注销后该账号不再出现在平台账号列表、账号查询与租户成员的有效列表中。
14. 系统拒绝注销**系统内置根账号**（`is_builtin = 1`）：根账号记录不可物理删除，其登录名与手机号也不释放（E24）。

### 5.8 超管全灭兜底

1. 系统不提供登录页自助找回密码入口。
2. 系统不提供凭码或凭令牌绕过登录的密码重置入口。
3. 系统在全部超管均无法登录时，转运维恢复流程。
4. 运维恢复须由实施方双人复核。
5. 运维恢复须留存操作记录并出具复盘报告。
6. 运维恢复后系统要求受影响账号首登改密。
7. 系统写审计日志。
8. 内置根账号恒存在且不可删除，故「超管全灭」在结构上只可能由**根账号口令失联**引起：根账号恢复走本流程，恢复后标记首登改密（§5.12-5）。

> 恢复码方案已取消，依据见本文 Changelog 与字段清单 V0.2。

### 5.9 通用

1. 系统按是否存在生效平台角色关联识别平台账号。
2. 系统按「存在生效平台角色关联 且 启用」放行平台后台。
3. 系统不允许同一账号同时持有平台角色与租户成员关系（互斥）；存量双身份按例外处理，禁止新增。
4. 系统按角色持有实时统计有效超管数。
5. 系统不因分配平台角色而创建或修改成员关系。
6. 系统不将平台账号计入租户成员数。
7. 系统不接收前端传入的操作人身份。
8. 系统对所有写操作记录审计。
9. 系统只在生成时一次性展示密码明文。
10. 系统在弹窗关闭后不提供密码明文查询入口。
11. 系统在列表与详情以掩码展示密码。
12. 系统只在平台侧分配平台角色：租户角色由租户管理员在租户端分配，本模块不展示、不分配、不回收（角色管理 PRD §5.11-5）。
13. 系统在本账号被指定为某租户主管理员时，不为其分配任何平台角色；该账号的租户权限来自租户侧自动授予的「租户管理员」角色（租户管理 PRD §4.17）。
14. 系统按账号表 `is_builtin` 识别系统内置根账号（全系统 1 条）：根账号只读，任何写操作均在接口层拒绝并写审计；`is_builtin` 只由初始化脚本写入，产品功能不得修改。

### 5.10 手机号脱敏

1. 系统在列表脱敏展示手机号。
2. 系统在详情脱敏展示手机号。
3. 系统在编辑表单展示手机号明文。
4. 系统保留手机号前 3 位与后 4 位。
5. 系统将手机号中间 4 位替换为掩码。
6. 系统不提供列表与详情的明文查看入口。

### 5.11 头像

1. 系统允许账号头像为空。
2. 系统在上传后展示头像图片。
3. 系统在头像为空时以姓名首字占位。
4. 操作人可更换或移除头像。
5. 系统不限制头像尺寸与格式。
6. 系统将头像与账号记录同事务保存。

### 5.12 系统内置根账号

1. 系统在初始化（建库部署）时向账号表写入 **1 个**超管根账号，`is_builtin = 1`，创建人与更新人固定为「系统初始化」，全系统仅此 1 条。
2. 根账号的登录名、手机号、姓名在初始化脚本中固定，产品内不提供资料修改入口；初始口令由脚本写入、部署实施方线下交付，**本人可在账号管理中重置自己的密码**（第 5 条）。
3. 根账号恒持「超级管理员」角色且恒为启用状态；角色与状态不随任何页面操作变化。
4. 根账号在账号管理中**只读**：列表与详情仅提供「查看」，不提供编辑 / 分配角色 / 停用 / 启用 / 注销；接口层对上述动作一律拒绝（E22–E24）。**唯一例外：允许根账号本人重置自己的密码**（走标准「重置密码」流程，入口见第 5 条）。
5. 根账号本人重置密码的入口有两个，能力同源：① 账号管理中该账号行 / 详情页的「重置密码」（仅 `isSelf` 可见）；② 顶栏「个人账户信息 → 密码 → 修改」。走重置流程：随机生成 / 自定义新密码，**新密码一次性展示**，旧密码与既有会话立即失效，并标记首登改密；**不提供「修改密码」这一独立操作**。
6. 根账号口令遗失或本人无法登录时，按 §5.8 转运维恢复；**他人重置根账号密码一律拒绝**，防止任一超管借此接管根账号。
7. 系统不允许新建第二个内置根账号：`is_builtin = 1` 不对产品功能开放，仅初始化脚本可写。
8. **根账号作为操作人拥有完整超管能力**：第 4 条的只读限制只作用于「针对根账号自身」的写操作；根账号登录后可对全部非根账号执行新建 / 编辑 / 分配平台角色 / 重置密码 / 停用 / 启用 / 注销，与其他超管无差异。
9. 非内置账号被授予超级管理员角色后**不受本条约束**：可被查看 / 编辑 / 分配角色 / 重置密码 / 注销 / 停用 / 启用，与普通平台账号完全一致。

## 8. 状态与操作矩阵

| 状态 | 可编辑 | 可分配角色 | 可重置密码 | 可停用 | 可启用 | 可注销 | 可登录平台后台 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 启用 | 是 | 是 | 是 | 是 | 否 | 是 | 是 |
| 停用 | 是 | 是 | 是 | 否 | 是 | 是 | 否 |

> 账号状态只有启用 / 停用两态；注销为物理删除，不设「注销」状态行，执行后账号记录不存在。主管理员（任一租户在任）在启用 / 停用两态下均不可停用、不可注销，须先完成主管理员交接。
> 本矩阵只适用于**非内置账号**：系统内置根账号不受状态矩阵约束，任何状态下都只提供「查看」+「重置密码（仅本人）」（§5.12）。矩阵中「可重置密码」对根账号仅对**本人**成立，**他人重置根账号一律阻断**（E24）。

## 9. 设计决策

| 编号 | 事项 | 决议 | 落点 |

## 10. 全部账号视图（账号管理 · 全局只读 + 超管治理）

### 10.1 定位

**结论：「全部账号」是账号管理的第二个视图，跨域展示全部账号（平台账号 + 租户成员）；默认只读，仅超管可对「孤账号」执行注销。**

| 项 | 内容 |
| :--- | :--- |
| 菜单 | 平台后台 → 系统管理 → 组织与权限 → 账号管理 · 全部账号（视图切换；功能编码沿用 `M221`，`scope = platform`，由平台角色勾选控制） |
| 数据范围 | 全系统账号表全局一份（不含已注销并物理删除的账号）：既含持平台角色的平台账号，也含不持平台角色的租户成员 |
| 账号类型判定 | 由「是否存在生效平台角色关联」动态判定（与 §1.2 识别口径一致），不设账号归属字段 |
| 写操作 | 平台账号行支持与「平台账号」视图一致的全部操作（编辑 / 分配角色 / 停用启用 / 重置密码 / 注销）；**系统内置根账号行只读，仅「查看」**；租户成员行支持**重置密码 / 停用 / 启用**（账号层能力，规则与平台账号一致），并可对**孤账号**执行注销（无有效成员关系、无平台角色、非任何租户主管理员）；**改角色 / 移出 / 编辑资料不提供**（归租户端成员管理） |
| 下钻 | 所有账号的姓名均可下钻详情：平台账号进入可操作的平台账号详情；租户成员进入只读详情，不提供任何运维动作 |
| 与平台账号视图的分界 | 平台账号视图 = 仅平台账号；全部账号视图 = 平台账号（同权限操作）+ 租户成员（只读 + 孤账号注销） |

### 10.2 查询与展示

1. 列表字段：姓名、登录名、手机号（脱敏，前 3 后 4）、邮箱、账号类型（平台账号 / 租户成员）、账号状态、最近登录时间、所属组织（生效成员关系对应的租户名）、创建人、创建时间。
2. 筛选条件：姓名 / 登录名 / 手机号关键字、账号类型（平台账号 / 租户成员）、账号状态（启用 / 停用）。
3. 排序：平台账号在前、租户成员在后；同类内启用状态在前，其余按更新时间倒序。
4. 分页：每页 20 条。
5. 工具栏统计：总条数、平台账号条数、租户成员条数（账号表全局唯一一份，两域共享）。
6. 手机号脱敏口径与本模块 §5.10 一致；本页不展示密码与头像。

### 10.3 业务规则

1. 平台账号行沿用「平台账号」视图的操作矩阵（编辑 / 分配角色 / 停用启用 / 重置密码 / 注销，受状态矩阵与本人规则约束）；**系统内置根账号行只保留「查看」**，不提供任何写操作（§5.12）；租户成员行提供**重置密码 / 停用 / 启用**与孤账号「注销」（见第 7、11 条；V0.17 起开放，改角色与移出仍不提供）。
2. 账号类型动态判定：存在生效平台角色关联即为「平台账号」，否则为「租户成员」；同一账号不会因同时持有两种身份而出现两行。
3. 租户成员行的「所属组织」取其生效成员关系对应的租户名称；无生效成员关系时展示「—」。
4. 访问控制：由平台角色勾选「账号查询」功能码控制；无功能码时菜单不渲染、直接调接口返回无权限并写审计。
5. 平台账号行的详情下钻复用平台账号详情页口径（操作记录 / 角色 / 状态等），不在本页重复展示。
6. 注销账号已物理删除，不在本页出现；账号状态筛选项只有「启用 / 停用」，不提供「注销」选项。
7. **平台侧对租户成员的操作边界**：提供查看（只读）、**重置密码**、**停用 / 启用**、注销孤账号；**不提供改角色、移出、编辑资料**。
   - 判定原则：**能降低访问权（停用）与恢复访问权（重置密码 / 启用）归平台兜底；改变租户内部权力结构（改角色 / 移出）留在租户域**。
   - 租户管理员仍是成员治理的第一责任人；平台动作仅在租户侧无法处理时使用，且原因必填、租户侧审计可见。
8. **孤账号判定**：该账号无任何有效成员关系、无任何平台角色、不是任何租户的在任主管理员；三项同时成立才允许注销。有成员关系的账号须先由租户管理员移出。
9. **强制下线**列为后置能力：仅在安全事件（疑似盗号）时由超管使用，本期不提供独立入口；停用 / 重置密码 / 移出已自带会话失效。
10. **所有账号支持查看详情**：本视图每行均提供「查看」；平台账号可操作，租户成员只读。
11. **租户成员的停用 / 重置前置**：停用 / 注销沿用 §5.4-4 的「可用管理员归零」判定（E19），命中时阻断并给「去更换主管理员」出口；重置密码要求目标账号为启用状态，原因必填，并展示跨租户影响（§5.6-16～19）。
