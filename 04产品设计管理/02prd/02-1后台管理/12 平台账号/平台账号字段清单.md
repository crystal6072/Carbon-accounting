# 平台账号字段清单

> **文档定位**：平台账号相关表结构的字段唯一真相源。业务 PRD 只引用字段名，不重复维护类型、必填与枚举。
> **依据**：产品碳足迹核算工具-用户体系 PRD（精简版）v3.5.1 §5.2、§5.3
> **覆盖表**：平台账号、平台账号与平台角色关联、密码重置记录
> **版本**：V0.8
> **更新时间**：2026-10-21

---

## 0. 表定位

平台账号表是全系统账号的唯一存储，不按域拆表。账号本身不设归属标签，平台侧与租户侧的区别由「挂了什么身份」决定，租户成员表关联本表，不另建账号表。

```text
一个账号 = 平台账号表 1 条记录
平台侧身份 = 该账号挂平台角色（N:N）
租户侧身份 = 该账号挂成员关系（N:N，本清单不覆盖）
两者可同时存在，互不排斥
```

推论：

| # | 推论 |
| :--- | :--- |
| 1 | 登录名、手机号、密码全局只有一份，唯一索引建在本表 |
| 2 | 平台后台「平台账号」菜单只展示持有生效平台角色的账号 |
| 3 | 本表状态变更作用于账号本身，对平台侧与租户侧同时生效 |
| 4 | 本清单一经建表，租户端成员管理不再另建账号表，只建成员关系 |
| 5 | 同一账号可同时出现在平台账号列表与某租户成员列表中 |

## 4. 表间关系

```text
account（全系统账号表，唯一存储）
  ├─ 1:N ─ platform_account_role（平台角色关联，归属类型 = 平台）
  ├─ 1:N ─ platform_password_reset_log（密码重置记录）
  └─ 1:N ─ 成员关系表（租户域，本清单不覆盖）

角色表（本清单不覆盖）
  └─ 1:N ─ platform_account_role
```

关键约束：

1. 账号只有一份，平台侧与租户侧都是在本表账号上挂身份，不复制账号。
2. 平台角色只产生平台端权限，租户角色只经成员关系挂载；同一账号可同时持有两者。
3. 平台账号不写入租户标识字段，不参与租户成员数统计。
4. 本期不设应急恢复码表。超管全灭由运维恢复处理，恢复过程不落产品表，只落审计日志。
5. 密码不做可逆存储，只在生成时一次性展示，事后任何入口均不可查。
6. 手机号在账号表存明文，脱敏只发生在列表与详情的展示层，编辑表单读明文。
7. 头像与账号同事务保存，不独立建表。

## 5. 设计决策

| 编号 | 事项 | 决议 | 落点 |
| :--- | :--- | :--- | :--- |
| D01 | 停用范围 | 账号级停用，租户端登录同时失效，不设分域状态字段 | §0 推论 3、§1 status |
| D02 | 登录名、手机号可否编辑 | 登录名不可改；手机号可改，须校验格式与全局唯一 | §1 |
| D03 | 重置后是否强制首登改密 | 置 1，与建号口径一致 | §1 first_login_required |
| D04 | 注销后登录名与手机号 | 不释放，记录不可恢复，保留档案备审计 | §1 唯一索引 |
| D05 | 账号身份 | 不设归属字段，同一账号可同时持有平台角色与成员关系 | §0、§1 |
| D06 | 运维恢复留痕 | 只在审计日志记 1 条，不建独立表 | §4 关键约束 4 |
| D07 | 密码重置记录 | 独立建表，审计只记事件摘要 | §3 |
| D08 | 平台账号数量 | 不设上限 | §1 |
| D09 | 表名 | 用 `account`，因其承载全系统账号 | §1 |
| D10 | 头像 | 非必填，未上传以姓名首字占位，不独立建表 | §1 avatar_url |
| D11 | 手机号脱敏 | 表内存明文，脱敏只发生在列表与详情展示层，编辑表单读明文 | §4 关键约束 6 |
| D12 | 密码生成方式 | 随机生成与自定义二选一，默认随机；自定义按复杂度校验 | §3 password_mode |
