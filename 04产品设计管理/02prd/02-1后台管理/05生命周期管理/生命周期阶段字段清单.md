**两条「不设字段」的设计约定**

| 约定 | 说明 |
| :--- | :--- |
| **不设「数据来源」字段** | 阶段字典统一由平台维护，**不设「系统预置 / 组织自建」数据来源字段**（与物料 / 能源 / 计量单位库同口径，见原型 `lifecycleMeta` / `LifecycleStageItem` 注释「不设数据来源、不设引用状态」）；据此不设「可见性」字段，无「系统预置只读 / 组织自建可编辑」的权限分支 |

| **不设「排除原因」字段** | 「排除 + 填原因」是**项目级行为**（在 P20 生命周期模型配置中执行），**不回写阶段主数据**（【待确认 Q03】）。不同产品对同一阶段的排除理由可能不同，写回主数据会互相覆盖 |

## 1. 模块与数据结构

### 1.1 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 模块名称 | 生命周期阶段 |
| 业务归属 | 后台管理 → 基础库 → 生命周期阶段（方案 §2.3 A1-10、§4.2.4、§八 P12） |
| 模块类型 | 基础数据维护（系统预置 + 组织自定义），非业务单据、无审核流、无版本化 |
| 核心对象 | 生命周期阶段（一级 / 二级） |
| 核心职责 | 提供**填报、检测、汇总与报告**共用的阶段骨架；按「**系统边界**」向核算项目输出**默认阶段基线**（每个阶段通过「适用系统边界」声明其适用的边界） |

### 1.2 对象结构

**推荐口径 A（单一对象，【待确认 Q01】）**

| 结构 | 对象 | 与主对象关系 | 主键/唯一标识 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主表 | 生命周期阶段 | 主对象 | 阶段编码 | **单一对象，无子表**；层级用「阶段层级 + 上级阶段」自引用表达 |
| 自引用 | 上级阶段 | N:1 | 阶段编码 | 二级阶段指向其一级阶段（仅两层） |
| 只读反查 | 引用情况 | — | — | 引用本阶段的核算项目 / 报告清单（用于禁用与删除约束） |

**「阶段基线」的处理（口径 A，【待确认 Q01】）**

```text
不建独立的「阶段基线」对象。
基线 = 按「系统边界」查询出来的阶段集合：

    项目创建时 →（读取 项目选择的系统边界）
              →（筛选阶段库：适用系统边界 为空 或 包含该项目边界）
              →（得到该项目的默认阶段基线）

举例：
  摇篮到大门基线 = 适用系统边界为空 或 含「摇篮到大门」的所有阶段
  摇篮到坟墓基线 = 适用系统边界为空 或 含「摇篮到坟墓」的所有阶段
```

> **备选口径 B**：另建「阶段基线」对象（基线名称 + 适用行业 + 阶段清单 × 纳入规则），阶段字典复用。取舍见 §9 Q01。

## 5. 枚举值

### 5.1 阶段层级

| 枚举值 | 含义 | 备注 |
| :--- | :--- | :--- |
| 一级 | 顶层阶段（如「原材料获取」） | 无上级阶段 |
| 二级 | 一级阶段下的细分（如「原材料运输」） | 上级阶段必填 |

### 5.2 适用系统边界（引用「数据字典 · 系统边界」）

> 每个阶段通过「适用系统边界」声明其在哪些系统边界下可见 / 参与核算。**本字段取代原「适用行业 + 摇篮到大门纳入规则 + 摇篮到坟墓纳入规则」三字段**（对齐原型 `LifecycleStageItem.boundaries: string[]`，见 Changelog V0.2）。

| 字典项编码 | 含义 | 备注 |
| :--- | :--- | :--- |
| `gate` | 摇篮到大门 | 阶段适用于摇篮到大门边界 |
| `grave` | 摇篮到坟墓 | 阶段适用于摇篮到坟墓边界 |
| `gate_to_grave` | 摇篮到坟墓 | 阶段适用于摇篮到坟墓边界（与 `grave` 同义，原型字典同时提供两编码） |

**取值规则**

| # | 规则 |
| :--- | :--- |
| B1 | 「适用系统边界」**多选**，取值来自「数据字典 · 系统边界」字典项编码 |
| B2 | **为空 = 全边界通用**（该阶段在摇篮到大门 / 摇篮到坟墓下均可见） |
| B3 | 项目加载阶段基线时，取「适用系统边界为空 **或** 包含项目所选边界」的阶段 |

## 9. 待确认事项

### 9.1 已确认决策

| 编号 | 结论 |
| :--- | :--- |
| **不设「数据来源」（V0.2，对齐原型）** | 阶段字典不设「系统预置 / 组织自建」数据来源字段（与物料 / 能源 / 计量单位库同口径，见原型 `lifecycleMeta` / `LifecycleStageItem` 注释「不设数据来源、不设引用状态」）；据此不设「可见性」 |
| **不设「适用行业」与「纳入规则」（V0.2，对齐原型）** | 阶段与行业解耦：原「适用行业 + 摇篮到大门纳入规则 + 摇篮到坟墓纳入规则」三字段由「**适用系统边界**」取代（`LifecycleStageItem.boundaries`）；基线改按「系统边界」查询，不再按行业拆基线 |
| **不设「排除原因」** | 「排除 + 填原因」属**项目级**行为（P20），不回写阶段主数据（【待确认 Q03】） |

### 9.2 优先处理

**Q01：「阶段基线」是否独立对象**

| 口径 | 结构 | 取舍 |
| :--- | :--- | :--- |
| **A（推荐，原型采用）** | 单一对象「生命周期阶段」，自带「适用系统边界」；基线 = 按「系统边界」**查询出来的集合** | 简单、少一个对象；**原型 `LifecycleStageItem` 已按此实现**。代价：基线不能作为可发布 / 可选中的实体；且不按行业拆基线 |
| B | 两个对象：阶段字典 + 阶段基线（基线名称 + 适用行业 + 阶段清单 × 纳入规则） | 基线可作实体被项目选中；代价是多一个对象与两层维护 |

**Q02：纳入规则三态还是两态**

> **V0.2 对齐原型：本项关闭。** 原型阶段库**不设「纳入规则」字段**（原「摇篮到大门 / 摇篮到坟墓纳入规则」两字段已由「适用系统边界」取代，见 §5.2 与 Changelog V0.2）。阶段与边界的适用关系由「适用系统边界」多选表达；项目内的纳入 / 排除及原因填写仍归 P20（D09）。若后续需恢复三态纳入规则，应重新引入按边界的纳入规则字段。

**Q03：「排除 + 原因」的归属**

| 位置 | 评价 |
| :--- | :--- |

| 阶段主数据级 | 无法表达项目间差异，不推荐 |
