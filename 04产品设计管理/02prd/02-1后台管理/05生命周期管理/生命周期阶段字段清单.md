## 1. 模块与数据结构

### 1.1 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 模块名称 | 生命周期阶段 |
| 业务归属 | 后台管理 → 基础库 → 生命周期阶段（方案 §2.3 A1-10、§4.2.4、§八 P12） |
| 模块类型 | 基础数据维护（系统预置 + 组织自定义），非业务单据、无审核流、无版本化 |
| 核心对象 | 生命周期阶段（一级 / 二级） |
| 核心职责 | 提供**填报、检测、汇总与报告**共用的阶段骨架；按「行业 + 边界」向核算项目输出**默认阶段基线**及**默认纳入规则** |

### 1.2 对象结构

**推荐口径 A（单一对象，【待确认 Q01】）**

| 结构 | 对象 | 与主对象关系 | 主键/唯一标识 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主表 | 生命周期阶段 | 主对象 | 阶段编码 | **单一对象，无子表**；层级用「阶段层级 + 上级阶段」自引用表达 |
| 自引用 | 上级阶段 | N:1 | 阶段编码 | 二级阶段指向其一级阶段（仅两层） |
| 只读反查 | 引用情况 | — | — | 引用本阶段的核算项目 / 报告清单（用于禁用与删除约束） |

**「阶段基线」的处理（口径 A，【待确认 Q01】）**

```text
不建独立的「阶段基线」对象。
基线 = 按「行业 + 边界」查询出来的阶段集合：

    项目创建时 →（读取 项目的行业 + 边界）
              →（筛选阶段库：适用行业 为空 或 包含该项目行业）
              →（按所选边界读取「纳入规则」字段）
              →（得到该项目的默认阶段基线）

举例：
  通用/制造业基线 = 适用行业为空的所有阶段
  木竹基线       = 通用阶段 + 适用行业含「木竹」的专属阶段（如 种植与培育、生物碳释放）
```

> **备选口径 B**：另建「阶段基线」对象（基线名称 + 适用行业 + 阶段清单 × 纳入规则），阶段字典复用。取舍见 §9 Q01。

### 1.3 数据来源与维护边界

| 维度 | 说明 |
| :--- | :--- |
| 数据来源 | **系统预置**（平台运营维护，全体租户只读） + **组织自建**（组织管理员维护，本组织可编辑 — 方案 §4.2.4「用户可自定义」，【待确认 Q05】） |
| ERP是否数据源 | 否 |
| 新增编辑 | 支持（系统预置阶段仅平台运营可维护） |
| 子表 | 无 |
| 导入导出 | 导出：支持；导入：V0.1 不支持（【待确认 Q11】） |
| 状态与执行 | 使用状态（启用 / 禁用）；无版本化、无审核流、无外部系统推送 |
| 关键唯一键 | 阶段编码唯一；同级内「阶段名称」唯一；同级内「阶段顺序」不重复 |
| 历史兼容 | 阶段主数据变更**不追溯**已建项目（项目按加载时的基线冻结，对齐方案 **§4.9**）；需按新基线重算走 **E13** |

### 1.4 关键数据约束

| 约束ID | 约束 | 影响对象 |
| :--- | :--- | :--- |
| D01 | 阶段编码唯一 | 主表 |
| D02 | **二级阶段的「上级阶段」必填，且只能指向一级阶段**；一级阶段该字段为空 | 主表 |
| D03 | **层级仅支持一级 / 二级，不支持三级**（方案 §4.2.4） | 主表 |
| D04 | **同级内阶段名称不重复**（同一上级下的二级阶段不重名） | 主表 |
| D05 | **同级内阶段顺序不重复**；一级与二级各自独立排序 | 主表 |
| D06 | 「适用行业」为空 = **全行业通用**；非空时阶段只对该行业可见 | 主表 |
| D07 | 「数据来源 = 系统预置」时，租户**只读**（不可编辑 / 禁用 / 删除） | 主表 |
| D08 | 已被核算项目加载 / 引用过的阶段**不可删除、不可禁用**（避免历史项目阶段结构漂移） | 主表 |
| D09 | **「排除 + 填原因」不在本模块维护**，属项目级行为（P20） | 主表 |
| D10 | 两个「纳入规则」字段必须取 §5.2 三态枚举之一，不允许留空 | 主表 |
| D11 | 二级阶段的顺序取值应在其一级阶段范围内连贯 | 主表 |

## 5. 枚举值

### 5.1 阶段层级

| 枚举值 | 含义 | 备注 |
| :--- | :--- | :--- |
| 一级 | 顶层阶段（如「原材料获取」） | 无上级阶段 |
| 二级 | 一级阶段下的细分（如「原材料运输」） | 上级阶段必填 |

### 5.2 纳入规则（三态，【待确认 Q02】）

| 枚举值 | 含义 | 项目内可排除 | 依据 |
| :--- | :--- | :---: | :--- |
| 必须纳入 | 该边界下此阶段为必需 | 否（缺失数据触发 **E10** 阻断） | 方案 §5.5 报告准入「必需阶段完成」 |
| 可选纳入 | 按产品实际情况决定是否纳入 | 是（需填原因） | 方案 §5.5「各阶段完成或明确不适用」 |
| 不纳入 | 该边界下此阶段天然不适用 | — （默认排除，无需原因） | 方案 §4.2.4 基线表 |

> 该三态口径来自方案 **§4.3.1**「各边界下**必须纳入 / 可选纳入 / 排除**的阶段」。
> 方案 §4.2.4 原写作「是否默认纳入（按边界）」（两态），**方案已同步统一为三态**（方案 v1.2 r4，见方案「附录二」第 6 项）。本项仅需业务追认（【待确认 Q02】）。

### 5.3 默认阶段基线（通用 / 制造业，方案 §4.2.4）

| 一级阶段 | 二级阶段 | 摇篮到大门 | 摇篮到坟墓 |
| :--- | :--- | :--- | :--- |
| 原材料获取 | 原材料获取 | 必须纳入 | 必须纳入 |
| 原材料获取 | 原材料运输 | 必须纳入 | 必须纳入 |
| 生产 | 生产过程 | 必须纳入 | 必须纳入 |
| 生产 | 生产过程废弃物处理 | 必须纳入 | 必须纳入 |
| 运输与交付 | 运输 | 不纳入 | 必须纳入 |
| 使用 | 仓储 | 不纳入 | 可选纳入 |
| 使用 | 产品使用 | 不纳入 | 可选纳入 |

### 5.4 木竹基线差异（决策 D2，【待确认 Q09】）

> 通用/制造业基线 = 上表全部 + 适用行业为空。木竹基线 = 通用阶段 + 下表**适用行业 = 木竹**的专属阶段。

| 一级阶段 | 二级阶段 | 摇篮到大门 | 摇篮到坟墓 | 新增理由 |
| :--- | :--- | :--- | :--- | :--- |
| **种植与培育**（新增一级） | 育苗与种植 | 必须纳入 | 必须纳入 | 木竹属生物质原料，原料获取前存在种植 / 培育环节（方案 §4.2.4 脚注「如增加"种植/培育"阶段」） |
| **种植与培育** | 抚育管理 | 可选纳入 | 可选纳入 | 同上 |
| 生产 | **碳化处理**（新增二级） | 可选纳入 | 可选纳入 | 木竹样板工序含碳化（240mm 全竹碳化筷子） |
| 生命周期末期 | **生物碳释放**（新增二级） | 不纳入 | 必须纳入 | 方案 §6.5：固碳计入后摇篮到坟墓**必须对称计入生物碳释放**，否则触发 **E16** |

> 上述为**建议枚举**，需业务确认后落入正式基线（【待确认 Q09】）。

## 9. 待确认事项

### 9.1 已确认决策

| 编号 | 结论 |
| :--- | :--- |
| **术语口径（2026-09-20）** | 「**数据来源**」只有「系统预置 / 组织自建」一个含义，仅用于权限判定 |
| **不设「可见性」** | 由「数据来源」推导（与物料 / 能源 / 计量单位库一致） |
| **不设「排除原因」** | 「排除 + 填原因」属**项目级**行为（P20），不回写阶段主数据（【待确认 Q03】） |

### 9.2 优先处理

**Q01：「阶段基线」是否独立对象**

| 口径 | 结构 | 取舍 |
| :--- | :--- | :--- |
| **A（推荐）** | 单一对象「生命周期阶段」，自带「适用行业」与「按边界的纳入规则」；基线 = 按「行业 + 边界」**查询出来的集合** | 简单、少一个对象；满足 D2「按行业预置多套」；**本清单已按此撰写**。代价：基线不能作为可发布 / 可选中的实体 |
| B | 两个对象：阶段字典 + 阶段基线（基线名称 + 适用行业 + 阶段清单 × 纳入规则） | 基线可作实体被项目选中；代价是多一个对象与两层维护 |

**Q02：纳入规则三态还是两态**

- 方案 §4.3.1 写「**必须纳入 / 可选纳入 / 排除**」→ 三态
- 方案 §4.2.4 写「**是否默认纳入（按边界）**」→ 两态
- **推荐三态**（本清单已按此撰写）：两态无法表达「必须纳入」与「可选纳入」的区别，而该区别直接决定 E10 是否阻断

**Q03：「排除 + 原因」的归属**

| 位置 | 评价 |
| :--- | :--- |
| **项目级（推荐）** | 「排除 + 填原因」在 P20 生命周期模型配置中执行，原因随项目保存。理由：不同产品 / 不同批次对同一阶段的排除理由可能不同，写回主数据会互相覆盖 |
| 阶段主数据级 | 无法表达项目间差异，不推荐 |
