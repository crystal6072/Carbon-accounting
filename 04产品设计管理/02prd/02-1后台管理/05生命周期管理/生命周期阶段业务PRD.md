## 1. 需求概述

### 1.1 需求背景

生命周期阶段是**组织填报、检测、汇总与报告的骨架**（方案 §1.4 术语：用于组织填报、检测、汇总与报告的阶段结构，支持一级/二级，可自定义）。

阶段配置的正确性**直接决定报告能否生成**：方案 §5.5 报告生成准入条件中「生命周期」为**阻断级**要求 —— 「阶段配置与边界一致：必需阶段完成 / 各阶段完成或明确不适用」。配置错误的后果：

| 异常 | 触发场景 | 后果 |
| :--- | :--- | :--- |
| **E10** | 需纳入下游阶段却无数据 | **阻断**计算与报告（不能把空白当 0） |
| **E11** | 阶段不适用无理由 | 可计算但标风险、**阻断报告**（必须留痕） |
| **E16** | 生物碳吸收已计入但末期未对称处理 | 摇篮到坟墓报告阻断（方案 §6.5） |

本模块为轻量基础数据，不做审核流与版本化。

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :--- | :--- | :--- |
| G1 | 提供一级 / 二级的阶段字典 | 层级仅两级，二级阶段必有所属一级阶段 |
| G2 | 提供按边界的默认纳入规则 | 每个阶段对「摇篮到大门 / 摇篮到坟墓」各有一个三态取值 |
| G3 | 支持按行业预置多套基线（**决策 D2**） | 项目创建时按「行业 + 边界」自动加载对应阶段集合；同输入必得同结果（可复现） |
| G4 | 木竹场景可用 | 木竹基线含种植与培育、碳化处理、生物碳释放等专属阶段 |
| G5 | 阶段变更不污染已建项目 | 项目按加载时的基线冻结；需重算走 **E13** |

| 按边界的纳入规则维护 | 摇篮到大门 / 摇篮到坟墓各一个三态取值 |
| 启用 / 禁用阶段 | 行操作 + 二次确认 |
| 导出 | 导出当前查询结果 |

**Out of Scope**

| 不做项 | 说明 |
| :--- | :--- |
| 审核流 / 版本化 | 基础数据，均不涉及 |

| 阶段图标 / 颜色等展示属性 | 本期不做 |
| Excel 导入 | V0.1 不支持（【待确认 Q11】） |
| 项目内阶段配置的操作界面 | 归 P20 生命周期模型配置（本模块只提供默认规则） |

## 2. 用户与使用场景

### S01 查看系统预置阶段基线（通用 / 制造业）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要确认通用基线包含哪些阶段 |
| 操作流程 | 进入生命周期阶段 → 按「适用行业 = 空」筛选 → 查看一级 / 二级阶段与两个边界的纳入规则 |
| 预期结果 | 展示通用基线的 5 个一级阶段与对应二级阶段（详见字段清单 §5.3） |

### S02 查看行业基线（木竹）与通用基线的差异

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 木竹产品项目需要确认其专属阶段 |
| 操作流程 | 按「适用行业 = 木竹」筛选 → 查看专属阶段 |
| 预期结果 | 展示木竹专属阶段（种植与培育、碳化处理、生物碳释放）；项目创建时这些阶段与通用阶段一并加载 |

### S03 新增 / 调整阶段（组织自定义）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 企业有特有阶段需要补充（如某行业专有的预处理环节） |
| 操作流程 | 新增阶段 → 选择层级（一级 / 二级）→ 二级阶段必选上级阶段 → 填写顺序、适用行业、两个边界的纳入规则 → 保存 |
| 预期结果 | 阶段创建成功；若「适用行业」为空则该阶段进入通用基线，否则只对指定行业可见 |

### S04 启用 / 禁用阶段

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 某阶段不再适用于新的项目 |
| 操作流程 | 行操作点「禁用」→ 二次确认 → 确认 |
| 预期结果 | 禁用后**不可被新项目加载**；已加载该阶段的在途项目不受影响；系统预置阶段与已被加载的阶段不可禁用 |

### S05 调整一级 / 二级阶段的顺序

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 阶段展示顺序需要调整 |
| 操作流程 | 编辑阶段 → 修改阶段顺序 → 保存 |
| 预期结果 | 保存后同级内顺序不重复；一级与二级各自独立排序；**已建项目的阶段顺序按加载时的快照，不随之变化** |

### S06 项目内启用 / 排除阶段（含排除必须填原因）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 某产品实际不涉及某阶段（如摇篮到大门项目不涉及「使用」阶段） |
| 操作流程 | 在项目的生命周期模型配置（P20）中 → 选择排除该阶段 → **填写排除原因** → 保存 |
| 预期结果 | 排除生效并留痕；**排除动作与原因保存在项目内，不回写阶段主数据**；未填原因时触发 **E11**（可计算但标风险、阻断报告） |

### S07 阶段被项目加载后的编辑 / 禁用 / 删除限制

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 阶段已被某个核算项目加载 |
| 操作流程 | 尝试禁用或删除该阶段 |
| 预期结果 | **不可禁用、不可删除**；详情页可查看引用清单；阶段编码、层级、上级阶段转为只读，名称 / 描述 / 顺序可改但需提示影响范围 |

### S08 阶段变更对已建项目的影响

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 阶段主数据（名称、顺序、纳入规则）发生变更，而某些项目已基于旧基线建立 |
| 操作流程 | 查看在途项目 |
| 预期结果 | 已建项目**按加载时的基线快照运行**，不受主数据变更影响（对齐方案 **§4.9**）；若需按新基线重算，须走 **E13**（重新检测 → 重新核算 → 生成新结果版本） |

## 4. 阶段结构与基线规则

### 4.1 层级结构

| # | 规则 |
| :--- | :--- |
| S1 | 层级**仅支持一级 / 二级**（方案 §4.2.4），**不支持三级**（D03） |
| S2 | 一级阶段无上级；**二级阶段的「上级阶段」必填**，且只能指向一级阶段（D02） |
| S3 | 「阶段顺序」**一级与二级各自独立排序**；同级内不重复（D05） |
| S4 | 二级阶段的顺序取值应在其一级阶段范围内连贯（D11） |
| S5 | 同级内阶段名称不重复（D04） |

### 4.2 默认阶段基线（通用 / 制造业，方案 §4.2.4）

| 一级阶段 | 二级阶段示例 | 摇篮到大门 | 摇篮到坟墓 |
| :--- | :--- | :--- | :--- |
| 原材料获取 | 原材料获取、原材料运输 | 必须纳入 | 必须纳入 |
| 生产 | 生产过程、生产过程废弃物处理 | 必须纳入 | 必须纳入 |
| 运输与交付 | 运输 | 不纳入 | 必须纳入 |
| 使用 | 仓储、产品使用 | 不纳入 | 可选纳入 |
| 生命周期末期 | 回收与最终处置 | 不纳入 | 必须纳入 |

> 该表是**默认值**，不同行业可通过自定义阶段适配（方案 §4.2.4 原文）。

### 4.3 决策 D2 的落地：按行业预置多套基线

| # | 规则 |
| :--- | :--- |
| B1 | 基线**按行业预置多套**：一套通用 / 制造业基线 + **木竹基线** + 后续行业基线 |
| B2 | 每套基线含「一级 + 二级 + **按边界的默认纳入规则**」 |
| B3 | **项目创建时按「行业 + 边界」自动加载对应基线**（方案 §5.1 第 3 / 4 步） |
| B4 | **行业基线由行业库承载，与核算模型解耦**（决策 D2 原文）—— 本模块提供阶段字典与纳入规则，核算模型不重复定义阶段（【待确认 Q07】） |
| B5 | **基线加载必须可复现**：同一「行业 + 边界」在同一时点必得到同一阶段集合与同一纳入规则 |
| B6 | 基线不是独立实体，而是「适用行业为空或包含项目行业」+「按边界读取纳入规则」的查询结果（推荐口径 A，【待确认 Q01】） |

### 4.4 木竹基线的差异

| 一级阶段 | 二级阶段 | 摇篮到大门 | 摇篮到坟墓 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| **种植与培育**（新增一级） | 育苗与种植、抚育管理 | 必须纳入 / 可选纳入 | 必须纳入 / 可选纳入 | 木竹属生物质原料，原料获取前存在种植 / 培育（方案 §4.2.4 脚注） |
| 生产 | **碳化处理**（新增二级） | 可选纳入 | 可选纳入 | 木竹样板工序含碳化（240mm 全竹碳化筷子） |
| 生命周期末期 | **生物碳释放**（新增二级） | 不纳入 | 必须纳入 | 方案 §6.5：固碳计入后摇篮到坟墓**必须对称计入生物碳释放**，否则触发 **E16** |

> 上述为建议枚举，需业务确认后落入正式基线（【待确认 Q09】）。

## 5. 纳入规则与排除规则

### 5.1 纳入规则的表达（三态）

| 取值 | 含义 | 项目内可排除 | 缺失数据的后果 |
| :--- | :--- | :---: | :--- |
| **必须纳入** | 该边界下此阶段为必需 | 否 | 触发 **E10**，**阻断**计算与报告 |
| **可选纳入** | 按产品实际情况决定是否纳入 | 是（需填原因） | 排除后不校验 |
| **不纳入** | 该边界下此阶段天然不适用 | —（默认排除，无需原因） | 不校验 |

> 三态口径来自方案 **§4.3.1**「各边界下**必须纳入 / 可选纳入 / 排除**的阶段」。
> 方案 §4.2.4 写作「是否默认纳入（按边界）」（两态），**两处表述不一致，以三态为准**（【待确认 Q02】）。两态无法表达「必须纳入」与「可选纳入」的区别，而该区别直接决定 E10 是否阻断。

### 5.2 阶段加载机制

```text
项目创建（P18 / P19 选择行业与边界）
        ↓
按「行业 + 边界」加载阶段基线（B3 / B6）
        ↓
├── 适用行业 为空 或 包含项目行业 的阶段 → 纳入候选
└── 按所选边界读取「纳入规则」字段 → 得到默认纳入 / 排除状态
        ↓
项目内生命周期模型配置（P20）
        ↓
核算人员可启用 / 排除阶段（排除必须填原因）
        ↓
基线快照随项目冻结（对齐方案 §4.9）
```

| # | 规则 |
| :--- | :--- |
| L1 | 加载范围为「适用行业为空（通用）**或**包含该项目行业（行业专属）」的阶段 |
| L2 | 加载结果按所选边界读取「摇篮到大门 / 摇篮到坟墓纳入规则」字段，得到默认状态 |
| L3 | 「必须纳入」的阶段**不可在项目内排除** |
| L4 | 「可选纳入」的阶段可在项目内排除，**必须填写排除原因** |
| L5 | 「不纳入」的阶段默认不加载，无需原因 |
| L6 | 加载结果作为**基线快照**随项目冻结；阶段主数据后续变更不影响已建项目（对齐 §4.9） |

### 5.3 排除与不适用规则

| # | 规则 |
| :--- | :--- |
| X1 | **排除动作发生在项目内**（P20），**原因随项目保存，不回写阶段主数据**（【待确认 Q03】） |
| X2 | 未填写排除原因即排除 → 触发 **E11**（可计算但标风险、**阻断报告**） |
| X3 | 「必须纳入」的阶段缺失活动数据 → 触发 **E10**（**阻断**计算与报告，不能把空白当 0） |
| X4 | 排除原因需可解释、可复核（进入报告的目标与范围声明） |
| X5 | 同一产品在不同项目中对同一阶段的排除理由可以不同，因此**不能写回主数据** |

### 5.4 生物碳相关的末期要求

## 6. 业务规则

| 规则编号 | 规则名称 | 触发条件 | 处理逻辑 | 例外策略 |
| :--- | :--- | :--- | :--- | :--- |
| R-001 | 阶段编码唯一 | 新增 / 编辑保存时 | 阶段编码唯一（【待确认 Q06】范围） | 重复时阻断保存 |
| R-002 | 同级名称不重复 | 保存时 | 同一上级下的阶段名称不得重复（D04） | 命中时阻断 |
| R-003 | 层级仅两级 | 保存时 | 只能选一级或二级；二级必须选上级阶段，且上级必须是一级阶段（D02 / D03） | 命中时阻断 |
| R-004 | 顺序同级唯一 | 保存时 | 同级内阶段顺序不重复；一级与二级各自独立排序（D05） | 命中时阻断 |
| R-005 | 适用行业语义 | 保存 / 加载时 | 为空 = **全行业通用**；非空时只对该行业可见（D06 / L1） | 无例外 |
| R-006 | 纳入规则必填且受控 | 保存时 | 两个边界的纳入规则都必须取三态枚举之一，不允许留空（D10） | 命中时阻断 |
| R-007 | 系统预置阶段只读 | 租户尝试编辑系统预置阶段时 | 只读，不可编辑、不可禁用、不可删除（D07） | 仅平台运营可维护 |
| R-008 | 被加载阶段不可禁用 / 删除 | 对已被项目加载的阶段操作时 | **不可禁用、不可删除**（D08）；阶段编码、层级、上级阶段转只读 | 命中时阻断并列出引用项目清单 |
| R-009 | 基线加载可复现 | 项目创建时 | 同一「行业 + 边界」在同一时点必得同一阶段集合与纳入规则（B5） | 无例外 |
| R-010 | 必须纳入不可排除 | 项目内排除阶段时 | 「必须纳入」的阶段不可排除（L3） | 命中时阻断 |
| R-011 | 排除必须填原因 | 项目内排除「可选纳入」阶段时 | 必须填写原因；未填触发 **E11**（标风险 + 阻断报告）（X2） | 无例外 |
| R-012 | 必需阶段缺数据阻断 | 检测 / 核算时 | 「必须纳入」阶段缺活动数据 → **E10**，阻断计算与报告（X3） | 无例外 |
| R-013 | 变更不追溯已建项目 | 修改阶段主数据后 | 已建项目按**加载时的基线快照**运行，不受影响（L6）；需按新基线重算走 **E13** | 命中时对在途项目给出提示 |
| R-014 | 生物碳末期对称 | 摇篮到坟墓项目检测时 | 固碳计入后末期须对称计入生物碳释放或注明长期储存，否则 **E16** 阻断报告（C1 / C2） | 无例外 |
| R-015 | 与核算模型解耦 | 全生命周期 | 本模块提供阶段字典与纳入规则；核算模型**只引用不重定义**（B4） | 无例外 |

## 7. 状态与操作矩阵

### 7.1 状态维度说明

| 状态维度 | 取值 | 来源 |
| :--- | :--- | :--- |
| 数据来源 | 系统预置 / 组织自建 | 字段清单 |
| 使用状态 | 启用 / 禁用 | 字段清单（用户操作） |
| 引用状态 | 未被加载 / 已被项目加载 | 系统自动关联（只读） |

> 本模块**无版本维度、无审核维度**。

### 7.2 操作矩阵

| 数据来源 | 引用状态 | 编辑 | 启用 | 禁用 | 删除 | 被新项目加载 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| 系统预置 | 未被加载 | 否（仅平台运营） | — | 否（R-007） | 否（R-007） | 是 |
| 系统预置 | 已被加载 | 否 | — | 否 | 否 | 是 |
| 组织自建 | 未被加载 | 是 | — | 是 | 是 | 是 |
| 组织自建 | 已被加载 | 部分（编码 / 层级 / 上级只读，见 R-008） | 是 | 否（R-008） | 否（R-008） | 是 |
| 组织自建 | 已被加载且已禁用 | 同上 | 是 | — | 否 | 否 |

**闭环校验**

- 启用 ↔ 禁用双向可达（系统预置阶段、已被加载阶段除外，属**受保护**不可禁用）；
- 「已被加载」不构成完全编辑限制，但**构成禁用与删除限制**，并锁定结构字段；
- 无版本维度、无审核分支；
- 项目内「排除」不属于本模块状态，不进入本矩阵（X1）。
