## 0. 使用说明

### 0.1 分类口径（三档）

| 分类 | 含义 |
| :--- | :--- |
| **已明确** | 有上位需求/PRD/业务说明支持，且原型实现与之一致（可直接写进标注） |
| **原型已有** | 代码已实现，但**未找到上位文档确认**（只能写成「当前原型行为」，不可写成正式需求） |
| **待确认** | 文档缺失、含糊、或原型与文档冲突——**必须由你裁决**；标注中一律保留「待确认」标签 |

冲突细分：`待确认(冲突)` = 原型与文档不一致；`待确认(缺失)` = 文档未覆盖或无上位文档；`待确认(含糊)` = 文档自相矛盾或未定。

### 0.2 编号规则（第二轮标注锚点）

`<模块代号>-<两位序号>`，例如 `B01-01`。模块代号见 §1.2。

### 0.3 依据文档

- `04产品设计管理/00业务设计/产品碳足迹核算系统_整体设计方案_v1.2.md`、`角色可见范围分层与本期后置清单_v1.0.md`
- `04产品设计管理/02prd/02-1后台管理/**`（11 个模块的 PRD + 字段清单；含《计算公式功能批注》）
- `04产品设计管理/02prd/02-2前台业务功能/**`（碳核算项目 6 组、我的产品库、我的因子库）
- 无上位文档的模块：**我的工艺库**、**数据字典**、**报告管理**（4 个占位）、**组织架构/用户与角色**（占位）

### 0.4 重要前置结论（影响第二轮写法）

1. **原型无任何角色 / 权限 / 审批实现**（全库检索仅见 a11y 用 `role` 属性）。所有「权限限制」类标注**没有事实可依**，需你给出权限模型。
2. **原型全量数据为前端内存 mock**，刷新即回种子值；所有「接口」均未约定。
3. 工作台实际 **4 步**（报告已移出核算流程）；`ProjectStepFive.tsx`、`PcfWordPreview.tsx` 已成**孤儿代码**（路由不可达）。
4. 多个模块存在**原型领先于 PRD**（原型已按最新裁定改造，PRD 未同步）与**PRD 领先于原型**（文档要求未实现）两个方向的偏差，两类都要裁决。
