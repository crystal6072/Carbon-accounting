## 1. 需求概述

### 1.1 需求背景

产品是碳足迹核算的对象载体。方案 §4.2.2 明确：**产品 = 产品基本信息 + 工艺 + 工序的组合**。核算项目在「产品与边界配置（P19）」中引用产品，并按方案 §4.9 的**快照机制**引用「产品 id + 版本号」，历史项目永远还原当时的产品定义。

因此本模块承担两个职责：一是把「基本信息 + 工艺 + 工序」的组合作业做出来；二是通过版本化与不可变机制，保证已核算项目不被后续产品变更污染。

本模块为完整主数据，不涉及审核流、外部系统同步与单据下推。

### 1.2 需求目标

| # | 目标 | 可验证口径 |
| :--- | :--- | :--- |
| G1 | 支持以「基本信息 + 工艺 + 工序」组合方式定义产品 | 产品下可挂工艺流程与工序，工序按顺序组织 |
| G2 | 支持产品版本化 | 同一产品可有多个版本，版本号自动生成且不重复 |
| G3 | 保证已核算项目不被产品变更影响 | 被项目引用的版本全字段只读、不可删除，只能新建版本 |
| G4 | 支持上架 / 下架控制可用范围 | 下架版本不可被新项目选择，历史引用保留 |
| G5 | 产品可被核算项目稳定引用 | P19 引用「产品 id + 版本号」，禁止实时引用最新版本 |

## 2. 用户与使用场景

### S01 新建产品（基本信息 + 组合工艺工序）

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 有一个新的被核算产品需要建档 |
| 操作流程 | 进入产品信息库 → 页头「新增」→ 填写基本信息（名称、分类、型号、规格、单位、所属行业、产品图片等）→ 添加工艺流程 → 带出工序并调整顺序 → 保存 |
| 预期结果 | 产品创建成功，生成 V1.0 版本；组合校验（R-004～R-006）通过；产品可被项目引用（需先上架） |

### S02 编辑产品

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 产品信息需要修正 |
| 操作流程 | 列表点「编辑」→ 修改字段 → 保存 |
| 预期结果 | **草稿版本**：可直接修改全部可编辑字段；**已发布且未被引用的版本**：修改后按 R-008 判定为「原地修改」还是「生成新版本」；**已被项目引用的版本**：不提供编辑入口，只能新建版本 |

### S03 建立新版本

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 产品发生结构性变更（工艺/工序组合、单位等） |
| 操作流程 | 详情页点「新建版本」→ 系统带出上一版本内容 → 修改变更内容并填写版本变更说明 → 保存 |
| 预期结果 | 生成新版本号（R-007）；新版本为草稿态；上一版本保持原样且仍可查看 |

### S04 上架 / 下架

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 产品版本需要投入或停止使用 |
| 操作流程 | 列表/详情页点「上架」或「下架」→ 二次确认 → 确认 |
| 预期结果 | 上架：可被新核算项目选择；下架：新项目不可选，历史项目引用与核算结果不受影响 |

### S05 被核算项目引用后的锁定表现

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 某产品版本已被核算项目引用 |
| 操作流程 | 尝试编辑、删除该版本 |
| 预期结果 | 无编辑入口（不渲染 disabled 假入口）、无删除入口；详情页展示「引用核算项目数」并说明原因；如需变更只能新建版本 |

### S06 查看产品详情与操作日志

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 需要查看产品完整定义或历史变更 |
| 操作流程 | 列表点编码/名称进入详情页 → 查看基本信息、工艺工序、版本信息 → 展开操作日志 |
| 预期结果 | 展示完整字段（含子表）与制单信息；操作日志可折叠并分页 |

## 4. 产品与工艺、工序的组合规则

> 本章为模块核心。**对象结构（三层 or 两层）尚未确认（Q01），下述规则按推荐方案 A（产品 → 工艺 → 工序）表述；确认前不得据此画页面。**

### 4.1 组合层级

| # | 规则 |
| :--- | :--- |
| C1 | 产品（版本）至少包含 **1 个工艺流程**，每个工艺流程至少包含 **1 个工序**（D05） |
| C2 | 工艺流程从「工艺流程库」引用，仅可选择**已发布**的工艺流程版本 |
| C3 | 工序从「工序管理」引用，工序随所选工艺流程带出并**复制为产品版本自己的副本**（已确认：基础库 → 产品版本 是**复制**关系）；副本可在产品版本内修改，明细行的增删范围见 §8 Q18 |
| C3b | **副本须保留来源模板标识**（工序编码 + 复制时点）；基础库模板后续调整**不回写**副本，仅在产品版本上标记「来源模板已更新」，由用户决定是否同步（V0.1 不做自动同步） |
| C4 | 同一工艺流程下的工序顺序连续且不重复（D06） |
| C5 | 工序链必须**首尾相接**：上游工序的产出（成品/中间品）必须等于下游工序的投入，否则触发校验提示 |
| C6 | **末道工序的产出必须为「成品」**（D07） |
| C7 | 投入产出流在本模块**只读展示**，维护归属为「工序管理」（A1-8），本模块不提供编辑入口（Q07） |
| C8 | 明细行数上限：工艺流程 ≤ 5 个、每个工艺流程工序 ≤ 50 道（Q15，对齐方案 §九 性能约束） |
| C9 | **同一生命周期阶段只能挂一个工艺流程**（2026-09-24 新增）：一个工艺流程对应一个生命周期阶段；产品内**同一生命周期阶段不得重复选择多个工艺流程**，重复选择时阻断并提示 |

### 4.2 组合变更的影响

| 场景 | 处理 |
| :--- | :--- |
| 草稿版本内调整工艺/工序 | 允许，保存后重新校验 C1～C6 |
| 已上架版本调整工艺/工序 | 视为结构性变更，**必须新建版本**（R-008），不得原地修改 |
| 上游工艺流程发生版本升级 | 已引用该工艺的产品**不受影响**（复制的副本已归产品版本所有）；产品如需采用新工艺，须新建产品版本或手工同步 |
| 上游工序发生变更 | 工序**不做版本化**（已确认 2026-09-20），模板可自由编辑；已建产品版本持有**副本**，**不受影响**，仅在副本上展示「来源模板已更新」标记 |

## 5. 版本与上架规则

| 规则编号 | 规则名称 | 触发条件 | 处理逻辑 | 例外策略 |
| :--- | :--- | :--- | :--- | :--- |
| R-001 | 产品编码唯一 | 新增产品保存时 | 编码在约束范围内唯一（D01，【待确认】范围） | 重复时阻断保存并提示 |
| R-002 | 版本号生成 | 新建产品 / 新建版本时 | 首个版本为 V1.0；后续按 R-007 规则进位，系统生成不可手工编辑 | 版本号重复时阻断 |
| R-003 | 产品分类引用约束 | 选择产品分类时 | 只能选择「启用」状态的分类；分类被禁用后不可新选 | 命中时提示分类已禁用 |
| R-004 | 组合完整性校验 | 保存产品版本时 | 校验 C1～C6，任一不通过则阻断保存 | 命中时定位到具体明细行 |
| R-005 | 末道工序产出校验 | 保存产品版本时 | 末道工序产出必须为成品 | 命中时阻断并提示 |
| R-006 | 投入产出流只读 | 全生命周期 | 本模块不提供投入产出流编辑入口 | 无例外 |
| R-007 | 版本号进位规则 | 新建版本时 | **结构性变更**（工艺/工序组合、单位）→ 进位大版本（V1.x → V2.0）；**说明性变更**（描述、型号、规格）→ 进位小版本（V1.0 → V1.1）（【待确认 Q04】） | 进位规则可配置后置 |
| R-008 | 原地修改 vs 新版本 | 编辑已发布版本时 | 仅说明性字段允许原地修改；接触及结构性字段则**阻断并引导新建版本** | 命中时提示建议新建版本 |
| R-009 | 上架 / 下架作用层级 | 上架 / 下架操作时 | **作用于版本**：某版本下架后不可被新核算项目选择（【待确认 Q03】） | 产品级状态由「是否至少存在一个上架版本」汇总 |
| R-010 | 被引用版本不可变 | 版本被核算项目引用后 | 全字段只读、不可删除、不可再编辑；只能新建版本（对齐方案 §4.9） | 如需修正，走新建版本；项目侧重新引用新版本 |
| R-011 | 删除规则 | 删除产品 / 版本时 | 仅「未被任何项目引用的**草稿**版本」可删除；存在子表明细、已发布或被引用的版本一律不可删（D08 / D09） | 命中时阻断并说明原因 |
| R-012 | 历史版本只读 | 查看历史版本时 | 历史版本全字段只读；仅可查看、导出、作为新建版本的模板 | 无例外 |
| R-013 | 快照引用 | 核算项目引用产品时 | 项目记录「产品 id + 版本号」，**禁止实时引用最新版本**（对齐方案 §4.9 落地原则） | 无例外 |
| R-014 | 下架后的下游影响 | 版本下架后 | 新项目不可选择该版本；已引用该版本的项目、核算结果与报告不受影响，可继续查看与导出 | 无例外 |
| R-015 | 当前版本唯一 | 保存版本时 | 一个产品下「是否为当前版本」为真的记录唯一（D10） | 无例外 |

## 6. 状态与操作矩阵

### 6.1 状态维度说明

| 状态维度 | 取值 | 来源 |
| :--- | :--- | :--- |
| 版本状态 | 草稿 / 已发布 / 已停用（【待确认 Q09】） | 字段清单 |
| 使用状态 | 上架 / 下架（作用于版本，【待确认 Q03】） | 字段清单 |
| 引用状态 | 未被引用 / 已被核算项目引用（系统自动关联，只读） | 系统计算 |

> 两个状态维度**必须分离**，不得合并为一个字段。

### 6.2 操作矩阵

| 版本状态 | 使用状态 | 引用状态 | 编辑业务字段 | 新增版本 | 上架 | 下架 | 删除 | 被新项目选择 |
| :--- | :--- | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| 草稿 | 下架 | 未被引用 | 是 | 是 | 是 | — | 是（R-011） | 否 |
| 草稿 | 下架 | 已被引用 | 否 | 是 | 是 | — | 否 | 否 |
| 已发布 | 上架 | 未被引用 | 仅说明性字段（R-008） | 是 | — | 是 | 否 | 是 |
| 已发布 | 上架 | 已被引用 | 否（R-010） | 是 | — | 是（R-014） | 否 | 是 |
| 已发布 | 下架 | 未被引用 | 否 | 是 | 是 | — | 否 | 否 |
| 已发布 | 下架 | 已被引用 | 否 | 是 | 是 | — | 否 | 否 |
| 已停用 | — | — | 否 | 是 | 否 | — | 否 | 否 |

**闭环校验**

- 草稿 →（上架）→ 已发布上架 →（下架）→ 已发布下架 →（上架）可达，无死状态；
- 「已被引用」不是独立状态，而是所有状态下叠加的**只读约束**（R-010）；
- 无审核分支：本模块不涉及提交 / 审核 / 驳回；
- 无删除终态：删除仅对「草稿 + 未引用」开放（R-011）。
