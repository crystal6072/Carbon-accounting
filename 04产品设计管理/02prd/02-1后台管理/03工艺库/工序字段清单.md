## 1. 模块与数据结构

### 1.1 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 模块名称 | 工序 |
| 业务归属 | 后台管理 → 基础库 → 工艺库 → 工序（方案 §2.3 A1-8、§八 P10） |
| 模块类型 | 完整主数据（带可维护子表：投入项 / 产出项） |
| 核心对象 | 工序（含投入产出流：投入项 / 产出项） |
| 核心职责 | 定义生产工序及其投入与产出，作为工艺流程装配、产品组合、核算项目生成核算工序、数据填报与排放计算的最小单元（方案 §1.4 术语） |

### 1.2 对象结构

| 结构 | 对象 | 与主对象关系 | 主键/唯一标识 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主表 | 工序 | 主对象 | 工序编码 | 投入产出流的载体；**不做版本化**（已确认 2026-09-20），生命周期靠启用 / 禁用表达 |
| 子表 | 投入项 | 1:N | 工序 + 投入项序号 | **已确认 Q01 / 2026-09-21**：承载「原辅料 / 能源 / 自然资源输入」三类流 |
| 子表 | 产出项 | 1:N | 工序 + 产出项序号 | **已确认 Q01 / 2026-09-21**：承载「中间品 / 产品 / 副产品 / 排放物」四类流 |
| 只读明细 | 引用明细 | — | — | 本模块暂无只读明细子表；「适用工艺流程」为只读反查（【待确认 Q07】） |

**对象结构说明（已确认 Q01，2026-09-20；流类型于 2026-09-21 调整为 7 类）**

```text
按「投入 / 产出」拆为两张子表，表内用「流类型」字段承载 7 类流语义：

├── 投入项（1:N）
│   └── 数据项 = 流类型 ∈ { 原辅料（物料库）, 能源（能源库）, 自然资源输入（物料库）}
│                    + 物料 + 单位（默认取物料默认单位，可覆盖）
└── 产出项（1:N）
    └── 数据项 = 流类型 ∈ { 中间品, 产品, 副产品, 排放物 }（均引用物料库）
                        + 物料 + 单位
        └── 排放物：须标注排放物类别 ∈ { 废气, 废水, 废渣 }

注：**不记录「数量」** —— 数量 = 工序单耗，在核算模型创建 / 数据录入阶段填写。

确认理由：
① 对标竞品「输入项 / 产出项」的分组交互，符合用户对工序的基本认知；
② 两张表的字段语义更集中（投入侧要选物料/能源，产出侧只选物料），
   可避免单表内「物料字段与能源字段互斥」的空值歧义，D04 的约束也更容易表达；
③ 保留「中间品」，不因对标而简化掉工序链衔接能力；同时补入「自然资源输入」「排放物」，
   使投入产出流覆盖 LCA 的资源投入与排放两端（原「成品」更名为「产品」，更贴合各工序产出物）。

已废弃的备选方案：单张子表 + 「流类型」字段区分 5 类流。
```

### 1.3 数据来源与维护边界

| 维度 | 说明 |
| :--- | :--- |

| 子表 | 可维护（投入项 / 产出项 两张子表） |

> **已确认决策（移出待确认）**
> - **Q01（2026-09-20 确认）**：投入产出流拆为「**投入项 / 产出项**」两张子表，表内用「流类型」字段保留方案 §4.2.2 的 5 类流语义（投入项 = 原料投入 / 能源投入；产出项 = 中间品 / 成品 / 副产品）。
> - **Q03（2026-09-20 确认）**：同一物料在不同流类型下不作同一条流处理；**中间品不记录上下游工序关联，工序链衔接由「工艺流程」的工序顺序推导**。
> - **Q06（2026-09-20 确认）**：**工序不做版本化**，仅保留「启用 / 禁用」。版本化只落在「工艺流程」层（对齐方案 A1-7 仅对工艺流程提出「版本管理」要求，A1-8 未提）。
> - **Q08（2026-09-20 确认）**：只保留「**工序类型**」单一维度（**不设「工序分类」**），枚举 = **主工序 / 辅助工序 / 处置工序**；工序编码全租户唯一，工序名称可不唯一。
> - **Q02（2026-09-20 确认）**：「物料」与「能源」**分别引用物料库（A1-1）与能源库（A1-2）**，不合并为统一的「投入产出物」对象。
> - **Q07（2026-09-20 确认，复用部分）**：**工序可被多个工艺流程复用**（一对多）；「适用工艺流程」反查字段是否展示仍待确认。
> - **Q16（2026-09-20 确认）**：**工序图标为选填，仅支持本地上传**，不做系统预置图标库。
> - **Q17（2026-09-20 确认）**：工序库**需要按工序类型筛选**；「工序类型」字段须支持筛选（页面形态属 Demo PRD）。
> - **Q12（2026-09-20 确认）**：**质量平衡相关数据（投入合计 / 产出合计 / 损耗）不在工序主数据记录**。工序是标准定义（理论配方），质量平衡校验的对象是某次核算实际填报的活动数据（P22），由检测引擎执行（方案 §5.4 E09）。
> - **Q15（2026-09-20 确认）**：**工序 = 模板，引用即复制；模板可自由编辑，且不受「被引用」约束**。副本归目标所有、可在目标侧修改，基础库后续调整不回写副本 ⇒ 工序后续调整不影响已建模型。追溯由**副本**保证（D12），不依赖基础库不可变。
> - **Q18（2026-09-20 确认）**：被引用过的工序模板**可禁用、不可删除**（删除会切断 D12 的来源追溯）。
> - **Q19（2026-09-20 确认）**：**「产品」不走"引用即复制"**，维持现状 —— 产品版本化 + 被项目引用后只读（产品信息 PRD R-010 不变）。**复制只发生在"基础库 → 产品版本"这一段**。
> - **Q20（2026-09-20 确认）**：**复制点在「产品版本层」**。产品版本引用工艺流程 / 工序时复制成自己的副本；核算项目引用产品版本时按既有快照机制冻结产品版本。**不采用双层复制**。
> - **Q21（2026-09-20 确认）**：**V0.1 不做「从模板同步」自动更新**；副本上展示「来源模板已更新」标记，由用户决定是否同步（D13）。
> - **Q04（2026-09-20 确认）**：**工序只维护「输入数据项 / 输出数据项清单」，不填具体数值**（数值在核算填报 P22 时填写）。子表「数量 / 单位」与主对象「基准数量 / 基准单位」**一律不保留**；D07 改为「本模块不记录数量与单位」，单位引用与换算校验前移至核算填报（E04）。
> - **流类型枚举调整（2026-09-21 确认）**：投入项 = **原辅料 / 能源 / 自然资源输入**；产出项 = **中间品 / 产品 / 副产品 / 排放物**（共 **7 类**）。原「原料投入」→「原辅料」、「成品」→「产品」；**新增**「自然资源输入」「排放物」；**中间品保留**，工序链衔接口径不变。新增「排放物类别（废气 / 废水 / 废渣）」字段（D15 / R-021）；自然资源输入与排放物**复用物料库**承载。该枚举为**产品库与工序共用**，产品库侧文档与原型需同步。
> - **工序库瘦身（2026-09-21 确认）**：
>   ① **删除「归属组织」「可见性」** —— 可见范围由**创建主体**自动判定（运营管理员创建 = 全平台可见可引用；用户自建 = 仅创建人可见），不落地为字段；
>   ② **删除「引用状态」与「适用工艺流程」反查** —— 删除规则改为「**仅禁用状态可删除**」（D14 修订：以使用状态替代引用状态），工序库只保留「使用状态」一个维度（关闭 Q07）；
>   ③ **删除「是否主产出」「产出分配依据」** —— 主次由**流类型**（产品 / 副产品）表达，分配由「分配规则管理」承载（关闭 Q09）；
>   ④ **~~「含中间品」仅详情展示~~ → 已改为「不设『是否含中间品』字段」**（2026-09-21 二次确认：新增 / 编辑页无该字段，详情页随之取消该字段展示）；
>   ⑤ **补回「单位」** —— 数据项 = 流类型 + 物料 + **单位**；单位默认取物料默认单位、可覆盖，引用计量单位库，每行必填（新增 D16 / R-022）；**数量仍不记录**（数量 = 「工序单耗」，在核算模型创建 / 数据录入阶段填写）。
> - 编号保留原有序号，空号（Q01 / Q02 / Q03 / Q04 / Q06 / Q08 / Q12 / Q15 / Q16 / Q17 / Q18 / Q19 / Q20 / Q21）表示该项已关闭，便于下游文档与 Prompt 的交叉引用保持稳定。

> **Q15 已确认口径（2026-09-20）：「模板 + 引用即复制」**（**方案 §4.9 已同步回改**，见方案 v1.2 r4「附录二 · 基础库落地偏离清单」第 9 项）
>
> ```text
> 基础库（工序 / 工艺流程）= 模板库
>         │
>         └── 被引用时【复制】一份定义到目标侧
>                     │
>                     ├── 副本归目标所有（产品版本 / 项目快照）
>                     ├── 副本可在目标侧继续修改
>                     └── 基础库后续调整【不回写】副本 ⇒ 基础库可自由改，不影响已建模型
> ```
>
> **与方案 v1.2 的关系**：追溯不再依赖「基础库对象不可变」（§4.9 的机制），而是依赖**副本**。因此工序**不需要版本化**（与已确认 Q06 一致），也**不受"被引用后只读"约束**（D08 已修订）。方案 §4.9「禁止实时引用最新版本」的原则**并未被违反** —— 本项目仍然是"引用后冻结"，只是实现方式是**复制**而非**版本号引用**。
>

> | 2 | **复制点在「产品版本层」**（已确认 Q20）：产品版本引用工艺流程 / 工序时复制成副本；核算项目引用产品版本时按既有快照机制冻结，**不双层复制** | 本清单 D12、§1.3；产品信息 PRD §4 |
> | 3 | **不做自动同步**（已确认 Q21）：副本上展示「来源模板已更新」标记，由用户决定是否同步 | 本清单 D13 |
