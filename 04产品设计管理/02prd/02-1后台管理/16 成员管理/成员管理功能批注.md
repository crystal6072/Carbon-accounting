## 1. 拟添加的批注清单

### 1.1 整体流程

#### B16-01 成员维护整体流程
**拟标注位置**：功能标题「成员管理」附近（全局说明入口，面包屑路径 `系统管理 / 组织与权限 / 成员管理`）
**标记**：已确认

**批注内容**

- **适用场景**：租户管理员在租户端维护本租户成员全生命周期——入职（新建）、调岗与配角色（编辑）、离岗（禁用）、复岗（启用）、凭证遗失（重置密码）、核查权限（查看有效权限）。
- **流程**：进入成员管理 → 列表展示本租户成员（默认按「正常」过滤）→ 按姓名 / 登录名 / 手机号、角色、成员状态查询 → 点「详情」查看只读档案与操作记录 → 点「新建成员」建号 → 对行内成员点「编辑 / 禁用 / 启用 / 重置密码 / 有效权限」维护。
- **分支**：新建只有「新建成员」一个入口（打开弹窗建账号 + 成员关系 + 角色）。
- **衔接**：列表点姓名、点「详情」均进只读详情弹窗；编辑、状态、重置、权限均通过弹窗完成，不离开本页；操作后列表与详情同步刷新。
- **结束**：保存 / 状态变更即时生效，无提交、审核、驳回；成员关系记录长期保留（不提供物理删除），仅以状态表达离岗。
- **本期范围（PRD 差异，以原型为准）**：PRD 的「关联已有账号」（按手机号命中已有账号、不建号）与「移出（离职）」在本原型**收敛为不做**——前者无入口，后者为隐藏的高权限终态，常规 UI 不可见（见 §3 R-02、R-04，PRD 待修订）。

### 1.2 全局规则说明

#### B16-02 全局规则
**拟标注位置**：功能标题附近（与整体流程同一全局说明入口）
**标记**：已确认

**批注内容**

1. **账号与成员两层关系**：账号全局唯一一份（平台账号模块维护）；成员是账号在租户上的挂载（成员关系表），不另建账号表、不复制凭证。同一账号可同时是多租户成员，各租户成员关系互相隔离。
2. **两层状态闸门**：账号状态（account.status）管全系统；成员状态（tenant_member.status）管本租户。登录本租户需「账号状态 = 启用 且 成员状态 = 启用 且 租户状态 = 启用」三者同时成立。账号停用 / 注销时该账号全部租户身份失效，但成员关系记录保留。
3. **角色挂载统一走 role_member**：成员角色 1 至 5 个（至少 1 个），只可指派**归属类型为租户、属本租户、状态为启用**的租户角色；平台角色既不展示也不接受写入。
4. **成员数口径**：含主管理员、含停用、含已移出；已注销账号的成员关系不计入。新增成员受「成员数上限（tenant.member_limit）」闸门，用量达上限时禁止新建。工具条「用量 x / 上限（已达上限时禁新增）」与此一致。
5. **登录名不可改**：登录名创建后不可修改；手机号可改，改后全局唯一（与平台账号口径一致）。
6. **密码策略**：新建 / 重置生成的新密码一次性展示明文，关闭弹窗后不可再查，遗失只能再次重置，不提供明文找回；新密码置首登改密。列表与详情对手机号、密码以掩码展示。
7. **主管理员保护**：主管理员不可停用、不可移出、不可主动退出，密码不可由租户管理员重置（须由超管在平台「租户管理」执行）；主管理员身份按 `tenant_admin_relation` 派生，本模块只展示结果。
8. **唯一管理员保护**：若租户仅剩 1 名在任（启用）管理员（按持有「租户管理员」角色且状态为正常计），禁止禁用该唯一管理员（PRD E07 之外的扩展口径，以原型为准）。
9. **不提供物理删除 / 移出入口**：本页不提供删除成员；「移出」为隐藏的高权限终态，常规 UI 不提供入口。
10. **权限**：原型未做角色 / 功能码限制（菜单恒渲染、接口不校验），正式实现需按「成员管理」功能码收敛（PRD / 实现后续跟进，不阻塞批注）。

### 1.3 业务状态说明

#### B16-03 成员状态
**拟标注位置**：清单「成员状态」列旁（确认弹窗内相应引用）
**标记**：已确认

**批注内容**

- **含义与取值（原型口径）**：成员三态——**正常**（原型，等同 PRD「启用」）= 可登录本租户、可操作；**已禁用**（原型，等同 PRD「停用」）= 本租户登录被切断、会话即时失效、记录与角色保留、可恢复；**已移出** = 终态，不可登录本租户、记录保留、常规 UI 不提供任何操作。
- **进入条件**：新建保存后默认「正常」；「已禁用」由正常态经行操作「禁用」进入；「正常」由已禁用态经行操作「启用」进入；「已移出」为隐藏终态（常规入口不提供）。
- **可进行的操作（原型口径）**：
  - 正常态：详情、编辑、禁用、重置密码、有效权限（5 项）。
  - 已禁用态：仅「启用」与「详情」（编辑、重置密码、有效权限、移出均收敛，见 §3 R-03 / R-05 / R-06）。
  - 已移出：终态，常规 UI 不提供任何操作。
- **对登录的影响**：成员状态只作用本租户；正常 + 账号启用 + 租户启用 才放行登录（见 B16-02 第 2 条）。
- **主管理员 / 唯一管理员额外受限**：不可停用、密码不可由租户管理员重置（见 B16-02 第 7、8 条）。
- **不作为独立状态的说明**：页面加载中、保存中按钮暂不可点、列表为空等属于交互表现，不视为业务状态。

### 1.4 操作功能及对应业务规则

#### B16-04 成员列表
**拟标注位置**：清单表格区域与清单上方工具条
**标记**：已确认

**批注内容**

- **展示内容**：姓名（含「主管理员」「本人」标记）、登录名、手机号（掩码）、部门（未挂组织）、角色（标签）、成员状态、加入方式、加入时间、操作。
- **规则**：① 行按「正常在前、已禁用次之、已移出靠后；同状态按加入时间倒序」排序；② 操作列超过 3 个时收起到「更多 ▾」下拉（详情、编辑、禁用常驻，重置密码、有效权限进更多）；③ 已禁用 / 已移出行以浅色样式区分；④ 每页 20 条。
- **工具条**：左侧显示「成员列表」标题与「共 N 条 · 正常 X 条 · 用量 x / 上限（已达上限时禁新增）」，并提示「主管理员不可禁用 / 重置密码，须先在平台租户管理更换；租户仅剩 1 名管理员时禁止禁用该唯一管理员」；右侧为查询结果统计。
- **行内派生标记**：姓名旁的「主管理员」按 `tenant.adminAccountId === accountId` 派生；「本人」按当前操作者派生。

#### B16-05 查询与重置
**拟标注位置**：清单上方查询区
**标记**：已确认

**批注内容**

- **查询项**：① 姓名 / 登录名 / 手机号 —— 单一输入框，按包含关系模糊匹配（登录名、手机号忽略大小写）；② 角色 —— 下拉选本租户角色名称；③ 成员状态 —— 下拉选「全部 / 正常 / 已禁用」。
- **规则**：三项条件叠加过滤；任一条件变化清单回到第 1 页；「重置」清空全部条件。
- **默认过滤（原型口径）**：进入时成员状态默认选中「正常」，因此默认只显示「正常」成员；「已禁用」与「已移出」仅在筛选为「全部」时可见（原型无「已移出」独立筛选项，见 §3 R-11）。
- **搜索按钮保留**：点「搜索」执行一次当前条件的筛选；输入即即时收敛，按钮为显式触发入口，二者结果一致。

#### B16-06 新建成员
**拟标注位置**：页头「新建成员」按钮旁、新建弹窗
**标记**：已确认

**批注内容**

- **操作目的**：为新人开户——建账号 + 建成员关系 + 写角色关联，并可一次性生成 / 自填密码。
- **入口**：页头「新建成员」（恒可操作；达成员数上限时保存被拦截，见 B16-02 第 4 条）。
- **填写项**：姓名（必填）、登录名（必填，创建后不可改）、手机号（必填，全局唯一）、密码（必填，随机生成 / 自定义二选一，默认随机）、部门（选填）、角色（必填，1 至 5 个）。
- **校验与阻断**：① 姓名非空、≤50 字符；② 登录名非空、仅支持字母数字下划线、非 11 位纯数字、全局唯一（不区分大小写、去空格、转半角）；③ 手机号格式正确、全局唯一；④ 角色 1 至 5 个；⑤ 部门为空或存在且为启用状态；⑥ 成员用量未达上限。任一不通过即阻断保存并提示，已填内容保留。
- **结果**：保存成功后弹窗切换为「一次性密码」展示页（提示抄录线下交付、关闭不可再查、遗失只能再次重置），点「完成」关闭；列表刷新出现该成员，状态为正常，密码置首登改密。
- **写审计**：每次新建写操作记录（操作人、IP、时间、变更摘要）。

#### B16-07 编辑成员
**拟标注位置**：操作列「编辑」、详情弹窗
**标记**：已确认

**批注内容**

- **操作目的**：修改姓名 / 手机号 / 邮箱（账号级字段，全局生效）、部门（调岗）、角色（租户域字段）；登录名不可改。
- **可操作条件（原型口径）**：仅「正常」态提供「编辑」；已禁用 / 已移出不提供（PRD §8 状态矩阵原允许停用态编辑，以原型为准，见 §3 R-03）。
- **规则**：① 手机号改到其他账号时，若该手机号对应账号已是本租户成员则阻断（E06）；② 部门为空或存在且为启用；③ 角色增减后总数 1 至 5，只展示本租户启用租户角色；④ 角色变更立即生效并刷新该成员会话权限；⑤ 改部门不影响已建业务数据上的部门快照；⑥ 登录名不可改。
- **账号级字段**：编辑态提供「邮箱」字段（原型新增，见 §3 R-09）；姓名 / 手机号 / 邮箱写在账号表，平台后台「平台账号」同步可见。
- **写审计**：记录变更字段前后值。

#### B16-08 停用（离岗）
**拟标注位置**：操作列「禁用」按钮旁、确认弹窗
**标记**：已确认

**批注内容**

- **操作目的**：临时冻结某成员在本租户的身份（离岗），保留记录、角色与历史业务数据，可恢复。
- **可操作条件**：仅「正常」态提供「禁用」；目标为主管理员时入口隐藏（不可停用，须先更换主管理员，E07）；目标为该租户唯一在任管理员时按钮置灰并提示先添加其他管理员（唯一管理员保护，见 B16-02 第 8 条）。
- **确认弹窗**：标题「确认禁用」，正文提示「禁用后无法登录本租户、会话立即失效；成员记录、历史业务数据与操作日志均保留，角色关联保留，可重新启用；禁用只作用本租户，不影响该账号在其他租户的成员关系与登录，也不改变账号状态」。底栏「取消 / 确认禁用」。
- **本人被禁用**：不阻断，但弹窗增加「已知悉：将被禁用的成员正是本人…」勾选确认。
- **结果**：确认后置成员状态为已禁用、踢本租户会话下线、保留记录与角色、计入成员数、写审计。

#### B16-09 启用（复岗）
**拟标注位置**：操作列「启用」按钮旁、确认弹窗
**标记**：已确认

**批注内容**

- **操作目的**：恢复某已禁用成员在本租户的登录能力（复岗），原角色自动恢复生效。
- **可操作条件**：仅「已禁用」态提供「启用」；启用时须持有生效角色不少于 1 个（E08，为 0 时阻断并引导先指派角色）。
- **确认弹窗**：标题「确认启用」，提示「启用后恢复本租户登录能力，原角色自动恢复生效」。底栏「取消 / 确认启用」。
- **应对调岗（原型口径）**：启用弹窗额外提供「部门」树选择，确认时若部门与当前不同，摘要提示「部门将由 X 调整为 Y」，复岗 + 调岗一次完成；不影响历史业务数据部门快照（见 §3 R-12，PRD §5.5 未提可改部门，调岗原走编辑）。
- **结果**：确认后置成员状态为正常、写审计。

#### B16-10 重置密码
**拟标注位置**：操作列「重置密码」按钮旁、重置弹窗
**标记**：已确认

**批注内容**

- **操作目的**：租户管理员为本租户成员重置密码，新密码一次性展示，旧密码立即失效、目标账号全部会话失效、置首登改密。
- **可操作条件（原型口径）**：仅「正常」态提供「重置密码」；目标为主管理员时入口隐藏（E10，须由超管在平台「租户管理」重置）；已禁用态不提供（见 §3 R-05，PRD AC26 原允许停用态重置，以原型为准）。
- **弹窗**：标题「重置密码 · 姓名」，提示「旧密码立即失效、全部会话失效（含其他租户，密码为账号级凭证）、标记首登改密、新密码仅展示一次」；重置方式随机生成 / 自定义二选一（默认随机）；自定义须 ≥8 位且两次一致（复杂度提示同平台账号）。
- **结果**：确认后展示一次性密码（提示抄录、关闭不可再查、不提供明文找回），写密码重置记录（reset_type = 3）与审计。

#### B16-11 查看有效权限
**拟标注位置**：操作列「有效权限」按钮旁、权限弹窗
**标记**：已确认

**批注内容**

- **操作目的**：只读核查某成员的实际生效权限。
- **可操作条件（原型口径）**：仅「正常」态提供「有效权限」（见 §3 R-06，PRD §8 原允许停用态查看，以原型为准）。
- **弹窗内容**：① 所持角色清单；② 角色共勾选功能点（含未开通模块内的勾选）；③ 合并生效功能点 = 已开通模块内功能点 ∩ 角色勾选功能点（多角色并集、按最宽档合并）；④ 表格按「所属功能 / 功能点 / 读范围 / 写范围」分列，只读。
- **审计**：每次打开写一条查看记录（操作人、目标、时间）。

#### B16-12 成员详情
**拟标注位置**：操作列「详情」、姓名链接、详情弹窗
**标记**：已确认

**批注内容**

- **操作目的**：只读核对成员完整档案与操作记录。
- **入口**：操作列「详情」、列表姓名链接。
- **展示内容**：姓名（含主管理员 / 本人标记）、登录名、手机号、邮箱（空显示「—」）、密码（掩码）、部门（未挂组织）、角色、成员状态、账号状态（含「登录本租户需账号、成员、租户三者均启用」提示）、加入方式 / 时间、创建人 / 时间、更新人 / 时间、操作记录表。
- **操作记录表**：时间、操作（标签）、操作人、变更摘要；「审计只增不改不删」。
- **规则**：只读，底栏「关闭」；可从详情发起编辑（正常态）。
