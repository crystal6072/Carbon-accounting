> **文档定位**：能源字段定义的唯一真相源（SST）。业务 PRD 和 Demo PRD 只引用字段名称，不重复维护枚举、必填性和字段口径。
> **适用类型**：基础数据维护（轻量）—— 无审核流、无版本化
> **维护形态**：列表（支持批量启用 / 停用）+ 查看 / 新增 / 编辑弹窗
> **与物料的关系**：**两个独立对象**（方案 §2.3 A1-1 / A1-2），字段结构相似；能源**本期不落「热值 / 热值单位」字段**（【待确认 Q12】）

> **版本**：V0.4
> **更新时间**：2026-09-21

**八条「不设字段」的设计约定**

| 约定 | 说明 |
| :--- | :--- |
| **不设「默认单位」** | 能源和物料一样**不绑定默认单位**。单位在**工序的投入项 / 产出项**中逐行选择（**已确认，2026-09-20**）。方案 §4.2.1 已同步回改（方案 v1.2 r4，见方案「附录二 · 基础库落地偏离清单」第 2 项） |
| **不设「数据来源」** | 不区分「系统预置 / 组织自建」，**不设记录归属字段**，因此也不推导可见性、不设「仅平台运营可维护」的只读档（**已确认，2026-09-21**，与物料库原型落地口径一致）。这是相对方案 §3.3.3 的**有意偏离** |
| **不设「引用状态 / 引用清单」** | 能源主数据上**不维护引用状态**：编辑与启用 / 禁用对所有能源开放，不受工序引用约束（**已确认，2026-09-21**，与物料库原型落地口径一致）；删除仅由「使用状态」决定（见 D04） |
| **不设「热值 / 热值单位」** | **本期不落字段**。能源的「实物量 → 能量」折算是否需要热值，取决于排放因子库的因子表达口径（【待确认 Q12】），确认后再定是否补两个字段 |
| **不设「数据获取方式」** | 实测 / 统计 / 估算 / 供应商 / 数据库 是**活动数据**的属性（方案 §4.6），在数据填报（P22）时记录 |
| **不采「引用资源」** | 竞品的资源文件选择器不采纳：不参与计算，且会引入对标准文件库（A1-3）的依赖，与「能源库保持轻量」的定位不符 |
| **不设「可见性」** | 不单独设字段（原「由数据来源推导」的口径随「数据来源」移除而失效） |
| **不设「适用区域 / 适用年度」「排放因子」** | 电网因子的区域 + 年度、以及「活动数据 → 排放量」的折算均属**排放因子库**（方案 §4.4），本模块不存因子（【待确认 Q04】） |

> **关于「热值」的说明（Q12，重要）**：
> - 能源的折算链路为 `实物量 → 能量（MJ） → 排放量`：第一层由**热值**承担，第二层归**排放因子库**（方案 §4.4）
> - **若**排放因子按**能量**给出（如 `kgCO₂e/GJ`）→ 热值必需，届时补「热值 + 热值单位」两个字段（主对象 6 → 8 项）
> - **若**因子全部按**物理量**给出（如 `kgCO₂e/L 柴油`）→ 活动数据 × 因子即可直接计算，热值冗余，可**永久不设**
> - 故本清单**本期不落热值字段**；待排放因子库口径确认后再定
> - 若 Q12 落地热值，需注意：「**热值单位**」是**定义域语义**（热值这个比值的分母，如 `44.8 MJ/kg` 中的 `kg`），**不是填报单位**；「默认单位」才是填报语义 —— 后者已移除，二者职责不同、不可互相替代

## 1. 模块与数据结构

### 1.1 模块定位

| 项目 | 内容 |
| :--- | :--- |
| 模块名称 | 能源 |
| 业务归属 | 后台管理 → 基础库 → 物料库 → 能源管理（方案 §2.3 A1-2、§4.2.1、§八 P04） |
| 模块类型 | 基础数据维护（轻量），非业务单据、无审核流、无版本化 |
| 核心对象 | 能源 |
| 核心职责 | 维护工序「能源投入」引用的**能源字典**：只回答「是什么」（能源名称 + 类型 + 适用行业），**不回答「多少、用什么单位」**（数量与单位在工序行填写）；「活动数据 → 排放量」的折算归排放因子库 |

### 1.2 对象结构

| 结构 | 对象 | 与主对象关系 | 主键/唯一标识 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主表 | 能源 | 主对象 | 能源编码 | **单一对象，无子表**；轻量基础数据 |
| 字典 | 能源类型 | — | 类型编码 | 系统内置枚举（§5.1），不开放维护 |
| 字典 | 适用行业 | — | 行业编码 | 引用行业库（A1-4）；主表存多选值 |

**能源与物料、因子库的职责边界（避免重叠）**

```text
物料：原料 / 辅料 / 包装材料 / 中间品 / 成品 / 副产品 / 废弃物
能源：燃料 / 电力 / 热力

分工（本期）：
├── 能源库     只回答「是什么」：能源名称 + 能源类型 + 适用行业（不落热值，见 Q12）
├── 排放因子库  负责「活动数据 → 排放量」的折算 ⇐ 排放因子（方案 §4.4）
└── 两层不得混算：能源库不存排放因子，因子库不存能源字典

单位归属：
├── 工序行（投入项 / 产出项）  负责「这次填了多少、用什么单位」 ⇒ 物料与能源都不持有默认单位
└── 若 Q12 落地「热值」，其「热值单位」仅作为热值的分母存在，不是填报单位
```

### 1.3 维护边界

| 维度 | 说明 |
| :--- | :--- |
| 数据来源 | **不设**（V0.4 起）：能源不分「系统预置 / 组织自建」，统一由后台维护，**对所有有权进入本模块的用户同等可编辑** |
| ERP是否数据源 | 否 |
| 新增编辑 | 支持（**查看 / 新增 / 编辑均走弹窗**，与物料库一致） |
| 子表 | 无 |
| 导入导出 | 导出：支持；导入：V0.1 不支持（【待确认 Q07】） |
| 状态与执行 | 使用状态（启用 / 禁用）+ **支持批量启用 / 停用**；无版本化、无审核流、无外部推送 |
| 关键唯一键 | 能源编码唯一（全租户） |
| 删除 | **仅「已禁用」的能源可删除**（不检查引用状态） |
| 历史兼容 | 能源主数据变更后，已核算项目的既有结果不变；需按新口径重算走 **E13** |

> 方案 §2.3 A1-2 写的是「电、柴油、天然气、蒸汽、热力」，把**类型**与**具体品名**混在了一个枚举里。**推荐按竞品分层**：

| 枚举值 | 含义 | 典型能源名称 |

### 9.2 优先处理

**Q01：能源类型的枚举分层**

| 出处 | 内容 |
| :--- | :--- |
| 方案 §2.3 A1-2 | 能源类型（**电、柴油、天然气、蒸汽、热力**等）—— 类型与品名混用 |
| 竞品界面 | 能源类型 = **燃料 / 电力 / 热力**，品名放在「能源名称」 |

**推荐按竞品分层**（本清单与原型均已按此撰写）。

**Q12：热值字段是否必需？（本清单 V0.4 的决定性前置项）**

| 情形 | 是否需要热值 |
| :--- | :--- |
| 排放因子按**物理量**给出（如 `kgCO₂e/L 柴油`） | **不需要** —— 活动数据 × 因子即可直接计算，热值是冗余 |
| 排放因子按**能量**给出（如 `kgCO₂e/GJ`） | **需要** —— 必须先把实物量折算为能量 |

**本期处理**：在排放因子库口径确认前，**暂不落「热值 + 热值单位」字段**，能源主对象保持 **6 项**（编码 / 名称 / 类型 / 适用行业 / 使用状态 / 描述）。
**若 Q12 结论为「需要」**：补「热值（正数，必填）」+「热值单位（引用计量单位库能量类单位）」两字段，并启用《能源业务 PRD》§4.2 的热值规则。

**Q02：热值的口径与边界（仅 Q12 = 需要时生效）**

| # | 问题 | 当前建议 |
| :--- | :--- | :--- |
| 1 | 低位热值（LHV）还是高位热值（HHV）？ | 只留**低位热值**（碳核算惯例用 LHV） |
| 2 | 热值的作用域是「实物量 → 能量」还是「实物量 → 排放量」？ | **只负责「实物量 → 能量」**；「排放量」由排放因子库负责 |
| 3 | 热值是否必填？ | **必填**（燃烧类能源没有热值无法计算） |
| 4 | 热值随批次变化时如何处理？ | 允许在活动数据填报（P22）时按实际批次覆盖默认值，不保留历史热值版本 |

**Q04：与排放因子库的边界**

- 电网类因子按「**区域 + 年度**」管理属**排放因子库**（方案 §4.4）
- **推荐**：能源库**不含**区域 / 年度字段，避免两处维护（D06）
