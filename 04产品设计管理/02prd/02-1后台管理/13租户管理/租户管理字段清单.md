## 0. 表定位

```text
租户主档（tenant）1 ──── N 租户扩展档案值（tenant_profile_value）
租户主档（tenant）1 ──── N 租户模块授权（tenant_module_authorization）
租户主档（tenant）1 ──── N 主管理员关系（tenant_admin_relation，同时仅 1 条生效）
租户主档（tenant）1 ──── N 租户状态变更记录（tenant_status_change_log）
租户主档（tenant）1 ──── N 租户独占字段变更申请（tenant_field_change_request）
租户扩展档案字段定义（tenant_profile_field_def）N ──── 1 租户类型（枚举）
租户扩展档案值（tenant_profile_value）N ──── 1 租户扩展档案字段定义（按 tenant_type + field_code 匹配）
租户主档（tenant）1 ──── 1 组织树根（org，由组织架构字段清单维护，本清单只引用）
主管理员关系 N ──── 1 账号（account，由平台账号字段清单维护，本清单只引用）
租户模块授权 N ──── 1 功能码目录（用户体系 PRD §5.4.1，本清单只引用）
```

推论：

| # | 推论 |
| :--- | :--- |
| 1 | 账号只有一份，主管理员关系挂账号表主键，不另建账号表 |
| 2 | 租户物理删除时：扩展档案值、模块授权记录、状态变更记录随租户清除；主管理员关系记录与账号记录保留 |
| 3 | 主管理员关系保留历史，同一租户与同一账号各自只有 1 条生效记录 |
| 4 | 租户状态只有启用与停用两个取值，删除不落状态值；「已过期」是按 `valid_to` 计算的展示态，不落状态字段 |
| 5 | 成员数用量由成员关系表实时统计，本清单不覆盖成员关系表 |
| 6 | 扩展档案的字段集由 `tenant_profile_field_def` 按 `tenant_type` 决定，值表只存值不存定义，避免同名字段在四类租户间串用 |
| 7 | 字段的可编辑权由 `tenant_profile_field_def.editable_scope` 决定：`tenant` / `both` 档允许租户端直写值表，`platform` 档只允许平台侧写入，租户改动走 `tenant_field_change_request` |
| 8 | 变更申请审批通过后回写 `tenant`（主档字段）或 `tenant_profile_value`（档案字段），原值快照存申请表的 `old_value`，便于审计对账 |
