## 1. 拟添加的批注清单

### 1.1 整体流程

#### B16-01 功能目录维护整体流程
**拟标注位置**：功能标题「菜单管理」附近（全局说明）
**标记**：已确认

**批注内容**

- **适用场景**：平台侧维护全站功能 / 菜单目录；本目录是菜单渲染与角色功能勾选的唯一数据源，变更即时影响平台与租户两端「看到什么菜单」。
- **流程**：进入菜单管理 → 目录树以单一树形整体展示（一级功能 → 二级功能（分组）→ 三级 / 末级功能）→ 按需查询定位 → 在行上「编辑」维护，或在任意节点上「新增下级」、在页头「新增一级菜单」→ 用「启用 / 停用」控制菜单是否渲染与可被勾选 → 不再使用的菜单「删除」。
- **分支**：新增有两个入口 —— 页头「新增一级菜单」（建立一级节点）、行操作「新增下级」（在任意节点下建立子节点，不限节点类型、不限状态、不限层级）。
- **衔接**：保存 / 启停 / 删除后即时生效，目录树刷新；角色管理的功能勾选树、租户模块授权同步按新配置更新（正式实现为下次请求生效）。
- **结束**：整个流程没有提交、审核、驳回；菜单从目录移除即生命周期终结（删除为直接移除，不提供回收站与恢复入口）。
- **不提供的能力**：本页不提供独立的「查看」详情页（编辑即入口），不提供批量操作、导入 / 导出、拖拽排序。

### 1.2 全局规则说明

#### B16-02 全局规则
**拟标注位置**：功能标题「菜单管理」附近（与整体流程同一全局说明入口）
**标记**：已确认（其中权限为待确认，见 §4）

**批注内容**

1. **适用范围**：本页维护全站功能目录；平台侧功能随版本注册写入，租户侧功能可由后台新建（后台新建的菜单默认适用端为「租户端」）。
2. **结构约束**：目录为树形，由「上级菜单 + 排序」组织；一级菜单没有上级；原型不限制层级深度（层级文案预置到五级，更深显示「N 级功能」）。
3. **分组节点**：路由留空的节点仅作分组（承载下级、不可进入页面）；带路由的节点可进入页面，成为末级功能。
4. **同树双端**：平台端与租户端功能同处一棵目录树，端的差异仅由「适用端（scope）」表达；树不按端拆分，清单不提供适用端列与筛选。
5. **菜单 id**：由系统生成（`M` + 序号），全局唯一，是前后端共用的同一套编码；表单不展示、不可维护。
6. **停用方式**：不再渲染的菜单用「停用」（保留记录与角色引用）；确定不再需要的菜单用「删除」从目录移除。
7. **删除限制**：含下级菜单的节点不可直接删除（操作列「删除」置灰，提示先删除或移出其下级菜单）；任何状态（启用 / 停用）均可删除。
8. **变更不追溯**：编辑为直接覆盖，不保留历史版本；正式实现记业务审计日志（记前后值），原型无日志入口。
9. **无流程节点**：没有提交、审核、驳回，也没有操作日志入口。
10. **统一限制**：功能名称必填（≤ 50 字符）；路由选填（填写时须以 `/` 开头）；排序必填（不小于 0 的整数）；适用端、菜单 id 均不出现在表单中。
11. **权限**：PRD 约定仅超级管理员可进入本模块，原型未做任何权限控制（所有人可进可操作）→ **待确认**（见 §4）。
12. **消费方**：角色管理的功能勾选树、租户模块授权、菜单渲染均以本目录为数据源；停用的菜单不渲染、不出现在勾选树中。

### 1.3 业务状态说明

#### B16-03 功能状态（启用 / 停用）
**拟标注位置**：清单「状态」列旁
**标记**：已确认

**批注内容**

- **含义**：菜单只有「启用」「停用」两个状态，没有「失效」等第三态。
- **进入条件**：新增保存后默认为「启用」；「启用」由停用态经行操作「启用」进入，「停用」由启用态经行操作「停用」进入。
- **可进行的操作**：两种状态下都可以「编辑」「新增下级」「删除」（删除限无下级节点）；启用态多出「停用」，停用态多出「启用」，行操作二者只出现其一。
- **状态变化**：启用与停用双向可达、可反复切换；停用不清除角色引用记录，功能恢复后引用自动生效。
- **对下游的影响**：停用后菜单不渲染、不出现在角色勾选树中，调用其接口被拒绝；已登录会话不追溯，下次请求即失效。
- **表单口径**：新增 / 编辑表单中**不出现状态**（本轮裁决，见 §3 B-01），状态只能通过列表行操作变更，入口唯一。
- **不作为独立状态的说明**：页面加载、查询无结果等属于交互表现，不视为业务状态。

### 1.4 操作功能及对应业务规则

#### B16-04 目录树浏览（展开 / 折叠、分组标识）
**拟标注位置**：清单表格区域与「菜单目录」工具条
**标记**：已确认

**批注内容**

- **操作目的**：按层级纵览全站功能目录，定位要维护的节点。
- **展示规则**：① 单一目录树整体展示，平台端与租户端同树混排；② 节点按层级缩进展示；③ 同级节点按排序号升序、排序号相同按名称排序；④ 有下级的节点显示分组图标与「分组 · N」徽章（N 为直接下级数），路由留空的分组节点仅作层级；⑤ 「层级」列展示「一级功能 / 二级功能 / 三级功能……」。
- **工具条**：显示「共 N 项 · 启用 N 项 · 当前展示 N 项」；右侧「全部展开 / 全部折叠」一键切换整棵树的展开状态。
- **展开 / 折叠**：点击节点前的箭头逐级展开 / 折叠；查询条件变化时自动展开全部命中分支。
- **无内容时**：目录为空时显示「暂无菜单」。

#### B16-05 查询与重置
**拟标注位置**：清单上方查询区
**标记**：已确认（搜索按钮行为为原型已表现·待核对）

**批注内容**

- **查询项**：① 功能名称 / 路由 —— 一个关键词同时按名称与路由模糊匹配（忽略大小写）；② 状态 —— 下拉选择「启用 / 停用」，不选即为全部。
- **过滤规则**：两个条件同时生效（叠加过滤）；命中节点保留其全部祖先，保证树形结构不被打散；条件变化后自动展开全部命中分支；「重置」清空全部条件并恢复完整目录。
- **搜索按钮（待核对）**：原型中点「搜索」只出现一次提示、不产生额外动作（筛选为即时生效）。需确认正式需求是否为「点击后查询」，或保留「即时筛选 + 按钮共存」。

#### B16-06 新增一级菜单
**拟标注位置**：页头「新增一级菜单」按钮旁
**标记**：已确认

**批注内容**

- **操作目的**：建立一个新的顶级功能节点（业务域）。
- **入口**：页头「新增一级菜单」；恒可操作，不限制已有菜单数量。
- **操作过程**：进入新增页，标题为「新增一级菜单」；「上级菜单」预设为「一级菜单（无上级）」；填写功能名称、路由（可留空）、排序（默认排在同级末尾）。
- **结果**：保存成功后返回列表并提示「新增成功」，新节点出现在目录树中，使用状态为「启用」，适用端固定为「租户端」。
- **取消或失败**：点「取消」返回列表，不保存任何内容；校验不通过时行内提示、保留已填内容（见 B16-12）。

#### B16-07 新增下级菜单
**拟标注位置**：行操作「新增下级」旁
**标记**：已确认

**批注内容**

- **操作目的**：在任意节点下建立子节点。
- **入口**：行操作「新增下级」；对分组节点与末级节点均可操作，不限节点状态（启用 / 停用）。
- **操作过程**：进入新增页，标题为「新增下级菜单」；「上级菜单」预设为所点节点，仍可修改；填写其余内容。
- **结果**：保存成功后新节点挂在该节点下，层级自动为「上级层级 + 1」，使用状态为「启用」，适用端固定为「租户端」，目录树刷新。
- **说明**：在下级节点上继续「新增下级」即形成更深层级；原型不限制层级深度。

#### B16-08 编辑菜单
**拟标注位置**：行操作「编辑」旁、编辑页
**标记**：已确认

**批注内容**

- **操作目的**：修改菜单的功能名称、路由、排序、上级菜单。
- **可操作条件**：任何状态的菜单均可编辑，不区分启用与停用。
- **操作过程**：进入编辑页，标题为「编辑菜单 · 功能名称」，带出现有内容；可改功能名称、路由、上级菜单、排序；菜单 id 与适用端不可改（不出现在表单）。
- **上级菜单规则**：候选项排除该菜单自身及其全部子孙（避免成环），不限启用 / 停用、不限适用端；下拉首项为「一级菜单（无上级）」，用于把节点改为一级；变更上级后该菜单及其全部下级随父级整体移动，层级按新位置重算。
- **结果**：保存成功后提示「保存成功」，目录树刷新；角色勾选树中的菜单同步刷新。

#### B16-09 停用菜单
**拟标注位置**：行操作「停用」旁、停用确认弹窗
**标记**：已确认

**批注内容**

- **操作目的**：让菜单不再渲染、不再可被角色勾选，同时保留历史授权关系。
- **可操作条件**：只在该菜单当前为「启用」时，行操作才显示「停用」。
- **操作过程**：点击后弹出二次确认弹窗，标题「停用菜单」，正文为「确认停用菜单『功能名称』？停用后该菜单不渲染、不出现在角色勾选树中。」；底栏为「取消」与「确认」。
- **被引用提示**：若该菜单被启用中的角色引用，弹窗内列出「⚠ 仍有 N 个启用角色引用该菜单」及角色清单（标注平台 / 租户）；**提示不阻断**，确认后照常停用。
- **结果**：确认后该菜单变为「停用」，提示「已停用」，目录树刷新；此时起菜单不渲染、不出现在角色勾选树，接口拒绝，角色引用保留。
- **取消**：点「取消」或关闭弹窗，状态不变。

#### B16-10 启用菜单
**拟标注位置**：行操作「启用」旁、启用确认弹窗
**标记**：已确认

**批注内容**

- **操作目的**：让已停用的菜单重新生效。
- **可操作条件**：只在该菜单当前为「停用」时，行操作才显示「启用」。
- **操作过程**：点击后弹出二次确认弹窗，标题「启用菜单」，正文为「确认启用菜单『功能名称』？」；底栏为「取消」与「确认」。
- **结果**：确认后该菜单变为「启用」，提示「已启用」；角色的历史引用自动恢复生效。
- **取消**：点「取消」或关闭弹窗，状态不变。

#### B16-11 删除菜单
**拟标注位置**：行操作「删除」旁、删除确认弹窗
**标记**：已确认（被角色引用允许删除，见 §3 B-02）

**批注内容**

- **操作目的**：把不再需要的菜单从目录中移除。
- **可操作条件**：该菜单**没有下级**时才可删除；含下级菜单时操作列「删除」置灰（悬停提示「请先删除或移出其下级菜单」），不弹确认框；任何状态（启用 / 停用）均可删除。
- **操作过程**：点击「删除」弹出二次确认弹窗，标题「删除菜单」，正文为「确认删除菜单『功能名称』？删除后该菜单从目录移除，引用它的角色授权关系将在下次保存时清理。」；若被启用中的角色引用，弹窗内同样列出引用角色清单；底栏为「取消」与「确认删除」。
- **被引用不阻断（本轮裁决）**：允许删除被角色引用的菜单，弹窗提示但不阻断；引用关系由角色侧在下次保存授权时清理。
- **结果**：确认后该菜单从目录移除，提示「删除成功」，目录树刷新。
- **不可恢复**：删除为从目录直接移除，不提供回收站与恢复入口。

#### B16-12 表单的保存与取消
**拟标注位置**：新增 / 编辑页底栏「保存」「取消」
**标记**：已确认（表单不含「状态」字段，见 §3 B-01）

**批注内容**

- **保存**：点击后先校验填写内容，通过后保存并返回列表，提示「保存成功 / 新增成功」，目录树刷新；保存过程中按钮暂时不可点击，避免重复提交。
- **校验规则（任一不通过即阻断保存，停留在本页，已填写内容全部保留）**：
  1. 功能名称未填写 → 提示「功能名称必填」；
  2. 功能名称超过 50 字符 → 提示「功能名称最长 50 字符」；
  3. 路由填写了但未以 `/` 开头 → 提示「路由需以 / 开头」；
  4. 排序不是不小于 0 的整数 → 提示「排序须为不小于 0 的整数」。
- **保存失败**：给出失败原因提示，停留在本页、内容保留。
- **取消**：点「取消」返回列表，不保存任何内容。

### 1.5 字段说明

#### B16-13 功能名称
**拟标注位置**：表单「功能名称」旁
**标记**：已确认

**批注内容**

- **业务含义**：菜单与按钮的展示名，也是目录树中用户识别的依据。
- **填写方式**：手工填写。
- **必填**：必填；为空时提示「功能名称必填」并阻断保存。

- **重复限制**：不要求唯一，允许同级与全局重名。

#### B16-14 路由
**拟标注位置**：表单「路由」旁
**标记**：已确认（任意节点均可填路由，以原型为准，见 §4.2 D-03）

**批注内容**

- **业务含义**：页面路由地址；带路由的节点可进入页面，路由留空的节点仅作分组（承载下级、不可进入页面）。
- **填写方式**：手工填写，输入框提示「留空则为菜单分组」，字段说明「前端路由路径，如 /pcf/project」。
- **必填**：选填。
- **格式限制**：填写时须以 `/` 开头，否则提示「路由需以 / 开头」。
- **联动**：留空即成为分组节点（目录树中显示分组图标与「分组 · N」徽章）；补填路由后成为可进入的末级功能。

#### B16-15 上级菜单
**拟标注位置**：表单「上级菜单」旁
**标记**：已确认

**批注内容**

- **业务含义**：该菜单在目录树中的父级；不选（「一级菜单（无上级）」）即为一级菜单。
