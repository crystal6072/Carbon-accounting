# 功能管理字段清单

> **文档定位**：功能管理相关表结构的字段唯一真相源。业务 PRD 只引用字段名，不重复维护类型、必填与枚举。
> **依据**：产品碳足迹核算工具-用户体系 PRD（精简版）v3.5.1 §5.4.1
> **覆盖表**：功能目录、功能同步记录
> **版本**：V0.1
> **更新时间**：2026-10-21

---

## 0. 表定位

功能目录是全站功能的唯一存储，平台端与租户端功能同表，用适用端区分。平台侧功能随版本注册写入目录，租户侧功能可由后台新建；后台提供直接增删改查与启停，不依赖「代码注册 → 发布同步」。

```text
一个功能 = sys_function 表 1 条记录
适用端 = 平台端 / 租户端（注册确定，后台不可改）
所属模块 = 一级功能（系统菜单），注册确定，后台不可增删改
租户端功能不按租户类型建模（原型未实现 tenant_types）：租户端功能对全部租户类型开放
角色勾选与菜单渲染的数据源 = 本表
```

推论：

| # | 推论 |
| :--- | :--- |
| 1 | 功能编码全局唯一，注册后不可改，是前后端共用的同一套编码 |
| 2 | 平台端与租户端功能在同一张表，靠适用端过滤，不拆表 |
| 3 | 后台可新增 / 编辑 / 删除 / 启停：可改名称、路由、排序、父级与状态；scope 注册 / 新建时确定，建后不可改 |
| 4 | 停用不清除角色引用，恢复后自动生效；停用仅标记不删除 |
| 5 | 租户端功能对全部租户类型开放；角色勾选树只按 scope 过滤，不按租户类型过滤 |

## 1. 功能目录

表名：`sys_function`（菜单 / 功能目录；原型实体名 `MenuFunction`，**菜单树即功能目录**，平台端与租户端同树、由 `scope` 区分；`id` 同时作为前后端共用的稳定编码）

| 字段名 | 中文名 | 类型 | 必填 | 默认 | 说明 | 约束 | 写入时机 |
| :--- | :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| id | 功能ID / 编码 | varchar(8) | 是 | 系统生成（M + 序号） | 主键，也是前后端共用的稳定编码 | 全局唯一；形如 `M100` / `M137` | 注册写入、手工新建 |
| name | 显示名称 | varchar(50) | 是 | 无 | 菜单与按钮展示名 | 长度 1 至 50 | 注册写入、后台编辑 |
| parent_id | 上级菜单ID | varchar(8) | 是 | 0 | 树形父节点；0 表示一级功能 | 不可空；为 `0` 或本系统内存在的 id；不可等于自身或自身子孙（成环拦截） | 注册写入、后台编辑 |
| route | 路由 | varchar(200) | 否 | NULL | 页面路由地址；为空表示仅作分组节点（不进入页面） | 以 `/` 开头；末级可进入功能才带路由 | 注册写入、后台编辑 |
| sort | 排序 | int | 是 | 0 | 同级内排序，升序 | 后台可改 | 注册写入、后台编辑 |
| scope | 适用端 | varchar(10) | 是 | 无 | 区分平台端 / 租户端（对应原 `apply_end`） | 取值 `platform` / `tenant`；注册确定，后台不可改 | 注册写入 |
| status | 状态 | varchar(10) | 是 | enabled | 生效闸门 | 取值 `enabled` / `disabled`（原型仅两态，未实现「失效」态） | 注册写入、停用、启用 |
| created_by | 创建人 | varchar(50) | 是 | 无 | 首次写入的操作人或系统标识 | 注册 / 初始化时置系统标识，手工新建置操作人 | 注册写入、手工新建 |
| created_at | 创建时间 | datetime | 是 | 当前时间 | — | 不可改 | 注册写入、手工新建 |
| updated_by | 更新人 | varchar(50) | 是 | 无 | 最近一次操作人名称 | — | 注册写入、后台编辑 |
| updated_at | 更新时间 | datetime | 是 | 当前时间 | — | 每次写操作刷新 | 注册写入、后台编辑 |

**唯一索引**

| 索引名 | 字段 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| uk_function_id | id | 唯一 | 功能ID / 编码全局唯一，前后端同一套编码 |
| idx_function_scope_status | (scope, status) | 普通 | 按适用端与状态查目录 |
| idx_function_parent_sort | (parent_id, sort) | 普通 | 按层加载子节点 |

**外键**

| 字段 | 指向 | 约束 |
| :--- | :--- | :--- |
| updated_by | account.id | 只读引用，不做级联 |

**状态枚举取值（status）**

| 值 | 名称 | 含义 | 菜单渲染 | 可被角色勾选 |
| :---: | :--- | :--- | :---: | :---: |
| enabled | 启用 | 生效 | 是 | 是 |
| disabled | 停用 | 后台手动下线，角色引用保留 | 否 | 否 |

> 原型未实现「失效」态（原 `code` 已取消、代码下线以 `disabled` 表达或由版本发布清理）；本期字段清单按原型收敛为两态。

**适用端枚举取值（scope）**

| 字段 | 值 | 名称 | 说明 |
| :--- | :---: | :--- | :--- |
| scope | platform | 平台端 | 平台后台功能（租户管理 / 平台账号 / 平台角色管理 / 菜单管理 / 数据字典等），只进平台角色勾选树 |
| scope | tenant | 租户端 | 租户端功能，按 role 勾选与租户模块授权过滤 |

**软删字段**

| 项 | 内容 |
| :--- | :--- |
| 是否有软删字段 | 无 |
| 说明 | 删除由 `status = disabled` + 从目录移除表达（原型 `deleteMenu` 直接移除记录），不另建软删列 |

**关联配置（不在本表）**

| 配置项 | 归属 | 作用 |
| :--- | :--- | :--- |
| 角色勾选 | 角色管理（role_function） | 引用本表 id，scope 须与角色归属类型匹配 |
| 已开通模块 | 租户管理（模块授权） | 与本表取交集算成员有效功能 |
| 租户类型适用性 | — | 原型未将「适用租户类型」建模到菜单上（原 `tenant_types` 字段取消）：租户端功能对全部租户类型开放，按租户类型过滤角色勾选树的能力本期不实现 |

## 2. 功能同步记录（原型未实现，暂挂起）

> **原型对齐说明**：原型菜单管理（`菜单管理`，路由 `/system/menu`）对菜单目录提供**直接增删改查**（新增 / 编辑 / 删除 / 启停）；平台侧功能随版本注册、租户侧功能可由后台新建；**不存在「代码注册 → 发布同步」与 `sys_function_sync_log` 同步日志表**。原 §2「功能同步记录」与「同步留痕」口径作废，本条仅作占位，待原型升级同步能力时再启用。

| 配置项 | 原型实际口径 |
| :--- | :--- |
| 目录写入 | 注册写入 + 后台直接 CRUD（createMenu / updateMenu / deleteMenu） |
| 同步日志 | 不建表；目录变更记业务审计日志 |
| 字段级变更留痕 | 由审计日志承接（记前后值） |

## 3. 表间关系

```text
sys_function（菜单 / 功能目录，平台端与租户端同树，由 scope 区分）
  └─ 1:N ─ role_function（角色与功能关联，角色管理清单覆盖，本清单不重复）

menu / button 渲染
  └─ 数据源 = sys_function（按 parent_id + sort 组织成树，status = enabled 才渲染）

角色勾选树
  └─ 数据源 = sys_function（scope 与角色归属类型匹配；租户端功能对全部租户类型开放）
```

关键约束：

1. 功能 `id`（编码）全局唯一，是前后端共用的同一套编码；菜单树不按端拆表，平台侧与租户侧功能同处一棵树，端的差异由 `scope` 表达。
2. `scope`（适用端）由注册确定、后台不可改；`name` / `route` / `sort` / `parent_id` / `status` 后台可改，租户侧新建功能默认 `scope = tenant`。
3. 停用不清除 role_function 引用，恢复后自动生效；原型仅两态，无「失效」残留态。
4. 后台提供直接 CRUD（原型 `createMenu` / `updateMenu` / `deleteMenu`）与启停；含下级菜单的分组节点不可直接删除。
5. 目录变更（编辑、启停、新增、删除）记业务审计日志（记前后值）；原「代码注册 → 发布同步」与同步日志本期不实现。

## 4. 设计决策

| 编号 | 事项 | 决议 | 落点 |
| :--- | :--- | :--- | :--- |
| D01 | 命名 | 模块名「功能管理」（原型菜单命名「菜单管理」，二者同模块，本期统一表述为「菜单管理 / 功能管理」）；实体即「功能」，不使用「功能码」叫法 | §0、原型 |
| D02 | 表名 | 用 `sys_function`（原型实体名 `MenuFunction`），避开保留字并区分于角色关联表 | §1 |
| D03 | 新建入口 | **原型修订**：后台可直接新建菜单（原型 `createMenu`，租户侧新建功能默认 `scope = tenant`）；取消原「无后台新建、接口不提供新建」口径，改为「注册写入 + 后台 CRUD」 | §1、§3 |
| D04 | 适用租户类型存储 | **原型修订**：菜单不再建模「适用租户类型」（原 `tenant_types` 字段取消）；租户端功能对全部租户类型开放，按租户类型过滤角色勾选树的能力本期不实现 | §1 scope、关联配置 |
| D05 | 数据范围标记 | **原型修订**：菜单不单设「是否适用数据范围」（原 `scope_applicable` 字段取消）；数据范围配置在角色授权侧处理，不落在菜单上 | §1 |
| D06 | 停用语义 | 不清引用、不追溯已登录会话，下次请求失效；原型仅两态（enabled / disabled），无「失效」残留态 | §1 状态枚举 |
| D07 | 同步留痕 | **原型修订**：取消「代码注册 → 发布同步」与 `sys_function_sync_log` 同步日志表；目录变更改记业务审计日志（记前后值）。原 §2 降级为挂起占位 | §2 |
| D08 | 模块属性 | **原型修订**：以 `parent_id` 树形结构表达层级（取消原 `module_code` / `module_name` 固定模块与 `group_name` 二级分组）；一级节点即原「模块」，分组节点由树形 `parent_id` 承载，不单建模块表 | §1 parent_id |
