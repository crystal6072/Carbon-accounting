## 1. 需求描述

一个账号一次登录，按租户隔离数据、按角色控功能、按范围控行，替代原五域割裂模型。

---

## 2. 整体业务流程

```mermaid
flowchart TD
  A[平台超管] --> B[建租户并指定主管理员]
  B --> C[勾选模块]
  C --> D[系统出一次性密码]
  D --> E[主管理员首登改密]
  E --> F[建部门与角色]
  F --> G[建成员或关联已有账号]
  G --> H[成员登录]
  H --> I{属于多个租户}
  I -->|是| J[选租户]
  I -->|否| K[直接进入]
  J --> L[校验账号 成员 租户状态]
  K --> L
  L --> M[算有效功能与数据范围]
  M --> N[进入系统]
```

## 5. 系统功能

### 5.1 租户管理

#### 5.1.1 新建与编辑

```mermaid
flowchart TD
  A[填开户信息 名称 类型 成员数上限] --> B{必填齐全且上限在 1 至 1000}
  B -->|否| C[拒绝]
  B -->|是| D[系统生成统一编码 建租户置启用]
  D --> E[开户即指定主管理员 平台账号下拉]
```

1. 必填（开户弹窗）：名称、类型、成员数上限、主管理员账号。统一编码由系统自动生成租户编号，创建后不可改。
2. 属地（省、市、区）本期不在开户表单内，留空待补；取自内置省市区三级数据，本期不可增删改。
3. 类型四选一：企业、政府单位、机构、园区。
4. 成员数上限默认 1000，仅超管改。
5. 下调上限不强制移出，只禁新增。
6. 主管理员在开户弹窗直接指定：从平台账号（不含超级管理员）下拉选择，不自动建号；主管理员关系、成员记录、账号侧租户身份同步写入。模块授权仍在详情页建后配置。
7. 主管理员写定后，系统在该租户内自动创建内置角色「租户管理员」并分配给该账号，默认勾选租户端全部功能点、数据范围读写均「全部」（实际生效仍取「已开通模块 ∩ 角色勾选」）。
8. 平台角色与租户角色完全隔离、不混用：平台角色只授予平台人员，不向租户下发；租户角色由租户自建自管，只在租户内生效，不跨租户复用。

#### 5.1.2 停用与删除

```mermaid
flowchart TD
  A[发起删除 仅停用状态可删] --> B[文本提示 物理删除不可恢复]
  B --> C[输入租户全名]
  C --> D{全名与实时名称匹配}
  D -->|否| E[拒绝]
  D -->|是| F[置全部成员关系失效]
  F --> G[物理删除租户 授权 状态变更记录]
  G --> H[保留账号与成员关系记录]
  H --> I[写审计]
```

1. 停用即全员掉线，数据冻结。
2. 恢复不启用此前单独停用的成员。
3. 删除仅允许「停用」状态租户；确认时输入租户当前全名，须与实时名称一致（无双人复核、无只读导出）。
4. 删除即物理删除，不可恢复。
5. 删除只清除租户、模块授权、状态变更记录，账号与成员关系记录保留。

#### 5.1.3 主管理员

```mermaid
flowchart TD
  A[发起更换] --> B[选接任成员]
  B --> C{原账号去向}
  C -->|降为普通成员| D[选 1 至 5 个角色]
  C -->|移出租户| E[置已移出]
  D --> F[换标记并刷新会话]
  E --> F
```

1. 每租户 1 个主管理员，是成员标记，不是角色。
2. 主管理员不可停用、不可移出，只能更换或指定。
3. 发起方为超管（租户端自助交接列入后置，不本期实现）。
4. 无在任主管理员时可「指定」，有在任主管理员时走「更换」；原账号去向必选，不可跳过。
5. 降级时角色至少 1 个。
6. 转移后原账号立即失权。
7. 主管理员密码重置本期移出操作集（不在平台后台提供）。

#### 5.1.4 模块授权

1. 模块按产品一级功能划分，后台不可自定义。
2. 只授到模块，不到功能点。
3. 授权按「产品碳足迹应用 / 系统管理」两组；系统管理组（成员管理 / 部门管理 / 角色管理 / 审计日志 / 个人设置）纳入授权列表。
4. 取消模块须二次确认，提示影响人数。
5. 取消后功能点下次请求即失效。
6. 变更记前后值。

#### 5.1.5 进入租户

1. 仅超管可进，原因必填。
2. 进入后顶部常驻横幅。
3. 业务数据只读，写操作全禁。
4. 进出均写审计，租户侧可见。

### 5.2 平台账号

#### 5.2.1 账号维护

```mermaid
flowchart TD
  A[停用请求] --> B{是本人}
  B -->|是| C[拒绝]
  B -->|否| D{是最后一个启用超管}
  D -->|是| E[拒绝]
  D -->|否| F[停用并踢下线]
```

1. 登录名、手机号各自全局唯一。
2. 平台账号靠平台角色取权限，不建成员关系，不占租户名额。
3. 建号时至少分配 1 个平台角色。
4. 首登强制改密。
5. 不可停用自己。
6. 不可停用或注销最后一个持有超级管理员角色的账号。
7. 任一超管可重置其他平台账号密码，不可重置自己。
8. 重置须填原因，旧密码立即失效。

#### 5.2.2 应急恢复

```mermaid
flowchart TD
  A[输入恢复码] --> B{码有效}
  B -->|否| C[拒绝并计数]
  B -->|是| D[重置指定超管密码]
  D --> E[码作废]
  E --> F[告警全部超管并写审计]
```

1. 恢复码部署时生成 5 个，一次一用。
2. 恢复码加密存储，实施方与客户方分持。
3. 前两路失效走运维恢复，双人复核加复盘。

### 5.3 角色管理（平台）

角色管理是一个功能，按归属范围分平台与租户两个切片。本节写平台侧，租户侧见 5.7。

1. 角色表加归属类型字段，取值平台 / 租户，不用租户标识为空推断。
2. 两切片互不引用，角色不可跨归属复制或指派。
3. 平台角色只挂平台账号，只给平台端功能码，不产生数据范围。
4. 租户角色的定义、功能码、数据范围、成员绑定属租户数据，超管默认不可见不可改。
5. 超管进入租户时，角色页只读。
6. 功能码同表，用适用端区分，勾选列表互不出现对方条目。
7. 角色成员页签按归属类型查不同对象：平台查平台账号，租户查成员关系。

#### 5.3.1 角色配置

1. 内置 2 个：超级管理员、平台运营人员。其余平台岗位角色不预置，由超级管理员按需新增。内置不可改不可删，可复制。
2. 自定义平台角色上限 20 个。
3. 角色名平台内唯一。
4. 有账号引用时不可删。
5. 超级管理员为保护角色，不可删、不可停用、不可取消。
6. 表单不含数据范围字段。
7. 新建时归属类型固定为平台，不可改。

#### 5.3.2 功能分配

1. 平台功能码范围：租户管理、平台账号、角色管理、系统管理、审计日志；系统管理整组仅超级管理员可勾。
2. 一人可挂多个平台角色，按功能码取并集。
3. 变更立即生效，持有者被踢下线重取权限。
4. 变更记前后值。

#### 5.3.3 角色成员

1. 移除成员即收回该角色，不影响其他角色。
2. 移除最后一个超级管理员时拒绝。

---

### 5.4 系统管理

#### 5.4.1 功能码目录

1. 平台端与租户端功能码同表，用适用端区分。
2. 功能码由代码注册，发布时同步，后台不可手工新建。
3. 后台可改：显示名称、排序、分组、启用、停用。
4. 停用后该功能码对所有角色失效，菜单与接口同时拒绝。
5. 租户端功能码额外带适用租户类型。
6. 代码已删但目录仍在的功能码标记失效，仅可查看。
7. 目录变更记前后值。

#### 5.4.2 系统参数

1. 可配：密码最小长度与字符类型、连续错误锁定次数、锁定时长、会话有效期、成员数默认上限。
2. 改后对新请求生效，已登录会话不追溯。
3. 取值范围设下限保护，不允许配得比默认更宽松。
4. 变更记前后值。

### 5.5 成员管理

#### 5.5.1 成员维护

```mermaid
flowchart TD
  A[填手机号] --> B{已有账号}
  B -->|是| C[走关联流程]
  B -->|否| D[建账号]
  C --> E[建成员关系]
  D --> E
  E --> F{超成员数上限}
  F -->|是| G[拒绝]
  F -->|否| H[出一次性密码]
  H --> I{名下有业务数据}
  I -->|是| J[提示条数与移交入口]
  I -->|否| K[完成]
```

1. 必填：姓名、登录名、手机号、密码、角色；部门可空。
2. 登录名禁 11 位纯数字，创建后不可改。
3. 密码可随机或自填，均标首登改密。
4. 角色 1 至 5 个，至少 1 个。
5. 同账号同租户仅 1 条成员关系，数据库唯一。
6. 关联已有账号不建号、不设密码、立即生效。
7. 被关联方可主动退出该租户。
8. 停用只作用本租户，不影响他租户。
9. 移出后记录保留，不可登录本租户。
10. 停用与移出均计入成员数。
11. 离职只提示数据条数，不阻断、不改业务数据。
12. 账号注销不删记录，责任人可追溯。

#### 5.5.2 批量导入

```mermaid
flowchart TD
  A[下载模板] --> B[上传文件]
  B --> C[逐行校验]
  C --> D{行合法}
  D -->|否| E[该行失败给原因]
  D -->|是| F{名额够}
  F -->|否| G[该行提示超上限]
  F -->|是| H[建号入成员]
  E --> I[出结果文件]
  G --> I
  H --> I
```

1. 模板列：姓名、手机号、部门、角色。
2. 模板无密码列，导入后系统生成随机密码。
3. 部分失败不影响成功行。
4. 结果文件仅可下载一次。
5. 角色超 5 个与角色不存在分别报错。

#### 5.5.3 查看有效权限

1. 展示所持角色、合并功能点数、按功能点分列的数据范围。
2. 只读，不可编辑。
3. 仅持成员查看权限的角色可见。
4. 每次打开写审计。

---

### 5.6 部门管理

1. 三种租户均可建部门树。
2. 同一上级下名称不重复。
3. 层级上限 5 层。
4. 有成员或有下级时不可删。
5. 停用后不可挂新成员，存量成员范围不变。
6. 本部门及下级按树实时算，不用快照。

---

### 5.7 角色管理（租户）

与 5.3 同一功能，差异只在数据范围与成员对象。

#### 5.7.1 角色配置

1. 角色属租户，不跨租户复用；租户角色由租户管理员自建自管，只在租户内生效，平台侧不代建代改。
2. 内置角色 1 个：租户管理员；随租户创建初始化，在开户时自动分配给主管理员并默认勾选租户端全部功能点，不可删除、不可停用。其余岗位角色不预置，由租户管理员按需新增。
3. 内置不可改不可删，可复制。
4. 自定义角色上限 20 个。
5. 角色名租户内唯一。
6. 有成员引用时不可删。
7. 改角色立即生效，须提示影响人数。
8. 归属类型固定为租户，勾选树只出现租户端功能码，表单含数据范围。

#### 5.7.2 功能权限

```mermaid
flowchart TD
  A[请求进入] --> B[取已开通模块]
  B --> C[取成员全部角色]
  C --> D[按功能点取并集]
  D --> E[与已开通模块取交集]
  E --> F{交集为空}
  F -->|是| G[空态页]
  F -->|否| H[渲染菜单与按钮]
```

1. 有效功能等于模块内功能点与角色勾选功能点的交集。
2. 多角色按功能点分别取并集。
3. 功能点由代码注册，后台不可新增。
4. 功能点带适用租户类型，按类型过滤勾选树。
5. 前后端同一套编码，两侧各自校验。

#### 5.7.3 数据权限

1. 五档：全部、本部门及下级、本部门、仅本人、指定部门。
2. 读写各配一档，写范围不宽于读范围。
3. 多角色同一功能点取最宽一档。
4. 仅本人按责任人判定，不按创建人。
5. 成员无部门时按仅本人。
6. 范围条件拼在查询语句，禁止前端过滤。
7. 业务表必备三字段：租户、部门、责任人。
8. 租户标识由服务端注入，不接收前端传值。
9. 部门标识存创建时快照。
10. 指定部门存 ID 列表，部门删除后自动移除。

### 5.8 审计日志

1. 记录范围：登录登出、账号增删改停用、平台角色增删改与功能码分配、租户增删改停用、模块变更、成员增删改移出、租户角色增删改指派、部门增删改、功能码目录变更、系统参数变更、进入租户、密码重置。
2. 审计只增不改不删。
3. 角色与模块变更记前后值。
4. 进入租户记录同步写租户侧，客户可查。
5. 支持按时间、操作人、类型、结果筛选。
6. 导出需二次确认并写审计。

### 5.9 登录

```mermaid
flowchart TD
  A[输登录名或手机号加密码] --> B{账号存在且启用}
  B -->|否| C[拒绝]
  B -->|是| D{密码正确}
  D -->|否| E[错 5 次锁 15 分钟]
  D -->|是| F{有效成员关系多于 1 条}
  F -->|是| G[选租户]
  F -->|否| H[取唯一租户]
  G --> I{账号成员租户均有效}
  H --> I
  I -->|否| J[拒绝]
  I -->|是| K{需首登改密}
  K -->|是| L[强制改密]
  K -->|否| M[进系统]
  L --> M
```

1. 登录名或手机号均可登录，二选一入口。
2. 登录名不区分大小写，输入去空格、转半角。
3. 密码复杂度按系统参数取值，默认不少于 8 位且含三类字符。
4. 连续错误按系统参数锁定，默认连错 5 次锁 15 分钟。
5. 无自助找回，成员由租户管理员重置，主管理员由超管重置。
6. 首登强制改密，随机与自填均适用。
7. 多租户时选完租户再算权限，选完清空缓存。
8. 切换租户后菜单、按钮、范围全部重算。
9. 同账号重复登录，后者生效，前者被踢。
