## 一、结论摘要

1. **主链路闭环成立**：以「平台产品库」产品发起核算，从新建项目 → 步骤①目标与范围 → 步骤②模型与数据 → 步骤③数据检测 → 步骤④核算计算 → 步骤⑤报告生成与确认，全流程可走通；摇篮到大门（gate）与摇篮到坟墓（grave）两种边界均可完成到报告锁定。
2. **核算口径正确**：核算结果为「排放 = 活动量 × 常量 × 因子值」逐行计算后按阶段 / 工序 / 排放源汇总，模拟手算与系统结果完全一致（gate 场景 40.4522 kgCO₂e、grave 场景 46.3202 kgCO₂e）。
3. **数据质量管控有效**：B1 活动量缺失、B2 排放来源未匹配、B3 分配比例不闭合、B4 因子单位不可换算、B5 纳入阶段无工序数据，五类阻断项均能检出并支持修复后重走。
4. **发现 4 项断点**：F-01 我的产品库与核算入口未打通（P0，**当日已按业务裁定修复**）；F-02 表单选项读静态常量、不随后台维护更新（P0）；F-03 三项系统字典无维护入口（P0/P1）；F-04 后台新建因子写死 preset、无法停用/删除（P1）。
5. 总体判断：**平台产品库口径的业务闭环成立、可演示；F-01 修复后前台「我的产品库（自建/引用）」成为核算唯一产品来源，组织级业务闭环成立；仍存 F-02（后台维护数据不进表单下拉）需修复。**

## 四、场景一：标准闭环（摇篮到大门 / 平台产品）

```
创建项目 PCF-20260920-001（ongoing / 步骤1）
  → 步骤① 保存：核算方法 GB/T 24067-2018、功能单位「双」、带出 2 个阶段（原材料获取+生产制造）✓
  → 步骤② 引用即复制 5 道工序（与产品工艺、阶段严格对齐），生成 5 条填报行 ✓
  → 保存三重拦截全部按预期生效：活动量未填 / 投入项未匹配因子 / 分配比例合计 60% 均拒绝保存 ✓
  → 步骤③ 检测通过（阻断 0 / 提示 0）→ 项目 toCalc、步骤4 ✓
  → 步骤④ 核算 V1：合计 40.4522 kgCO₂e；报告 PCF-R-20260920001 生成并确认锁定 ✓
```

**核算口径逐行核对**（系统值 = 手算值）：

| 工序 / 数据项 | 活动量 | 因子 | 排放（kgCO₂e） |
| --- | --- | --- | --- |
| 厂外运输 / 毛竹原竹（厂外运输） | 3.2 t·km | 0.036 kgCO₂e/t·km | 0.1152 |
| 断料 / 毛竹原竹 | 62 kg | 0.18 kgCO₂e/kg | 11.16 |
| 碳化 / 电力 | 42 kWh | 0.581 kgCO₂e/kWh | 24.402 |
| 打磨成型 / 竹屑（回收信用，免因子） | 5 kg × 0.5 | — | 2.5 |
| 包装 / 纸包装材料 | 2.5 kg | 0.91 kgCO₂e/kg | 2.275 |
| **合计** | | | **40.4522** |

汇总维度：阶段（原材料获取 0.1152 / 生产制造 40.337）、工序（5 行）、排放源（transport 0.1152 / material 15.935 / energy 24.402），占比合计 100%。CSV 导出、doc 报告导出均含核算结果。

## 五、场景二：摇篮到坟墓（grave）+ 阶段覆盖拦截

- grave 边界默认带出 5 个阶段（分销/使用/末期处理纳入），产品仅覆盖原材料获取 + 生产制造 → **B5 一次性检出 3 个「已纳入但未匹配工序数据」的阶段**（阻断）。
- 修复路径验证两条：① `addPcfProcess` 从工艺流程库补充「废水处理工艺」（末期处理），填报行自动补生成；② 步骤①取消勾选暂不覆盖的分销/使用阶段 → 检测通过 → 核算 46.3202 kgCO₂e（末期处理 5.868）→ 报告确认锁定。
- **结论： grave 边界的阶段覆盖管控有效；但「默认全勾 + 无工序即阻断」对建模不全的产品打击面大，需依赖用户手工 excluded，建议步骤①对无匹配工艺的阶段给出默认不勾或提示（见建议 S-05）**。

## 六、场景三：数据质量拦截（B1–B4）与修复

追加两道"问题工序"后，一次检测检出 4 类问题（示例）：

```
[blocking/completeness] 数据项「环保胶粘剂」的活动量未填写            ← B1
[blocking/completeness] 投入项「环保胶粘剂」未匹配排放因子            ← B2
[blocking/completeness] 数据项「竹粉」的活动量未填写                  ← B1
[blocking/allocation]   工序「分切」的产出分配比例合计 0%，须为 100%   ← B3
```

- B4 演示：将「毛竹原竹（kg）」误匹配电力因子（kgCO₂e/kWh）→ 检出「活动量单位与因子分母单位不可换算」，修正因子后通过。
- 修复后检测通过并完成核算（44.6122 kgCO₂e）；`removePcfOperation` 删除工序后填报行同步清理。
- **结论：五类检测规则（B1–B5 + W1 质量平衡提示）覆盖完整，问题项均带定位与「去修复」跳转步骤；保存层与检测层双重拦截，口径清晰。**

## 十一、结论

- **能否完成产品碳足迹核算**：以「平台产品库」产品为口径，**可以完整完成**（模拟数据 → 五步流程 → 报告锁定全通，核算数值与手算一致）。
- **前后台功能数据是否串联**：核心建模链路（分类/行业/阶段/单位/物料/能源/工序/工艺/产品/因子/公式 → 项目）与状态机链路**已串联**；但两处断点（F-01 我的产品库、F-02 表单选项数据源）使「前台组织自建产品核算」和「后台维护数据反哺表单」不成立。
- **业务是否闭环**：平台产品口径闭环；组织自建口径已闭环（F-01 于当日修复，我的产品库成为前台唯一产品来源）。剩余待修复：F-02（后台基础数据维护不进表单下拉）、F-04（后台因子无停用/删除生命周期）。
