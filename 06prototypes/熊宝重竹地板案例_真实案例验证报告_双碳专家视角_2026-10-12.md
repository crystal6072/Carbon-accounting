## 一、总结论

**引擎「算得对」，主链路「走得通」；但作为「产品碳足迹核算工具」的业务闭环只完成了企业内部测算层，尚未达到通用 PCF 核算 / 第三方核查级。**

| 判定维度 | 结论 | 依据 |
| --- | :--- | --- |
| 核算数学正确性 | ✅ **通过** | 28 条逐行、A1-A3/A1-C4 化石与净值、kg/m² 归一化全部与案例一致（见 §二） |
| 主流程闭环 | ✅ **通过** | 建档→阶段→数据项→检测→核算→结果→（清册/报告）可端到端走通 |
| 负数流 / 副产品扣减 | ✅ **已支持** | 4 条负数明细通过检测且正确扣减 |
| 生物碳双口径 | ✅ **已支持** | 四分量口径（总量/化石/生物源/土地利用）+ 结果页口径切换 |
| 分模块 A1–C4 核算 | ❌ **不支持** | 阶段库仅 5 个一级 + 10 个二级（`LC-01..LC-15`），无 EN 15804 模块编码、无 A5 阶段 |
| 归一化（kg / m²）落地 | ❌ **产品不可达** | 引擎支持，但步骤① V0.8 已移除换算系数录入、结果页不展示 |
| 数据可追溯（来源/质量/凭证/分配） | ❌ **缺失** | 活动数据模型无对应字段 |
| 审核 / 审批 / 版本锁定 | ❌ **缺失** | 状态机无审核态 |
| 情景分析 / 横向对比 | ❌ **缺失** | 全库无实现 |

> 一句话：**相对 2026-10-09 的走查，负数流、生物碳、口径切换已补齐；但「模块编码缺失 + 归一化入口被移除 + 可追溯字段缺失 + 无审核流」决定了它仍只能用于企业内部测算，不能出具对外/核查级结果。**

## 七、结论与建议

**能否闭环？**
- **企业内部粗颗粒度测算**：可以闭环（当前原型的主价值）。
- **通用产品碳足迹核算 / 对外披露 / 第三方核查**：不能闭环。

**能否满足产品碳核算业务场景？**
- 满足「企业内部快速测算 + 双口径展示」；
- 不满足真实业务中最常见的 **分模块报告（客户/下游要求 A1-A3、A1-C4）、按 kg/m² 交付、数据可追溯、独立审核** 四类硬需求。

**建议补齐顺序（决定熊宝案例能否「合规跑通」）：**

1. **生命周期阶段引入 `stageCode`（A1–A5 / B1–B7 / C1–C4，EN 15804 映射）并补 A5 阶段**，结果与清册按模块边界输出（P0-1）。
2. **恢复归一化入口并支持 kg 与 m² 并存**（净重 + 长/宽自动算面积；换算口径列表化，不再只派生一个）（P0-2）。
3. **活动数据补 `factorSource / dataQuality(DQI) / evidenceId / allocationMethod` 字段**，负数流与校准项强制「流向 + 原因 + 凭证 + 审批」（P0-3、P2-1、P2-2）。
4. **补审核流**（提交审核 / 审核中 / 通过 / 驳回 + 意见 + 日志 + 版本锁定）（P0-4）。
5. **统一热点与总口径**（按口径取数、明细持久化四分量），精度改为内部高精度、仅展示取整（P1-1、P1-2、P1-3）。
6. **导入模板补因子 / 流向 / 生物碳 / 质量 / 凭证列并去重**（P1-4）。
