## 一、摇篮到坟墓验证（本轮新增）

案例：240mm 全竹碳化筷 · 2025 年度 · 摇篮到坟墓（原材料获取 / 生产 / 运输交付 / 使用 / 生命末期）。

### 场景 A：数据挂在一级阶段

```
纳入一级阶段：原材料获取、生产、运输/交付、使用、生命末期
检测：passed（阻断 0）
核算：总量 43.632 kgCO₂e/双（手算 43.6320）
阶段汇总：原材料获取=12.762、生产=30.618、运输/交付=0.18、使用=0、生命末期=0.072
排放源：material=15.33、transport=0.414、energy=27.888
报告 PCF-R-20260920001 → 项目状态 done
[OK] 摇篮到坟墓全链路核算与手算一致
```

> 结论：**摇篮到坟墓（gate → grave 全 5 阶段）可完整闭环**；R-07「阶段覆盖」按你的口径（后台维护阶段 → 应用到前端）不再构成缺陷。

### 场景 B：数据挂在二级阶段 → 发现并修复一个真实缺陷

初跑发现：步骤② 允许把数据项挂在**二级阶段**，但检测 / 核算只认**一级阶段名** → 二级阶段的数据**被排除出核算**，且对应一级阶段被判「无数据项」而阻断（5 项阻断）。

**修复**：检测与核算统一按「数据项 → 归属一级阶段」解析（二级阶段上卷到一级父阶段，取项目 `parentName` 或生命周期阶段库 `parentId`）。

修复后：

```
场景 B：数据全部挂在二级阶段（原材料运输 / 生产过程 / 运输交付 / 使用 / 生命末期…）
检测：passed（阻断 0）
核算：总量 28.302（手算 28.3020）；明细行数 5
阶段汇总（一级阶段）：原材料获取=0.162、生产=27.888、运输/交付=0.18、使用=0、生命末期=0.072
[OK] 二级阶段数据已上卷到一级阶段并纳入核算
```

## 二、本轮三条需求落地

| # | 需求 | 落地方式 | 验证 |
| --- | --- | --- | --- |
| 1 | **支持负数活动量** | 步骤②数量允许负数（页面 / CSV 导入放开 ≥0）；引擎 `排放 = 数量 × 因子值` 支持扣减；检测不拦截负值 | ✅ 含 `-20 kg` 通过检测；`12.6 − 3.6 + 27.888 = 36.888`，负明细 `-3.6` |
| 2 | **报告未完成前可改 + 支持重新核算** | 可编辑状态放宽到 `reportGenerating` / `reportEditing`（仅 `done` 锁定）；回改步骤①/② 即回退「进行中」需重走检测 → 核算；结果按版本递增 | ✅ 回改 → `ongoing/step3`；重算 V1→V2→V3；`done` 后抛「当前状态不可编辑」 |
| 3 | **核算公式必填** | 步骤①「核算公式」必填（前端 + 服务端校验）；PJ01 补公式快照 | ✅ 未选公式保存被拒 |
