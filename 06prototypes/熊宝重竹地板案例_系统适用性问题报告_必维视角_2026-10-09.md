## 一、总结论

**该系统可作为「企业内部粗颗粒度足迹测算 / 演示工具」运行，但尚不满足通用产品碳足迹核算（ISO 14067 / GB/T 24067 / EN 15804）的业务与合规要求，不具备出具第三方核查级结果的条件。**

- 主流程（建档 → 阶段 → 数据项 → 检测 → 核算 → 归一化）**可跑通**，28 条案例数据可全部录入并通过检测，化石口径 **A1–C4 = 11.4295 kgCO₂e/块**，与案例预期 `11.4294699873` 一致（差 0.00003，来自系统把结果四舍五入到 4 位小数）。
- 但案例的**核心口径无法产出**：
  - 生物碳双口径（含 / 不含生物碳）**完全无法计算**，A1–A3 含生物碳净值 `0.3522` 一项也出不来；
  - 生命周期**模块编码（A1–A5 / B1–B7 / C1–C4）缺失**，A2、A5、C2、C4 被并入相邻一级阶段，无法按模块拆分与报告；
  - **单行只能绑 1 个因子**，无法同时承载「化石因子 + 生物碳因子」，C4 木材处置两行做不了；
  - 归一化**只能给一个换算口径**，`kg / m²` 不可并存，且净重、面积均未结构化采集；
  - **负数流、校准项无流向/原因/凭证约束**，第三方核查不可追溯；
  - 活动数据**缺数据来源、数据质量、凭证、分配方法、因子版本/地区/有效期**等可追溯字段。

## 二、评审方法与实测证据

按页面真实调用顺序驱动 mock API：`createPcfProject → updatePcfProjectStepOne → savePcfStageData → submitPcfCheck → startPcfCalc → fetchPcfCalcResult`，共灌入 28 条活动数据。

模块→阶段映射（系统无 A1–C4 编码，只能就近归属）：

| 案例模块 | 系统归属阶段 | 是否可独立报表 |
| --- | --- | --- |
| A1 原材料获取 | 原材料获取（一级） | 与 A2 合并，**不可分** |
| A2 原材料运输 | 原材料运输（二级，上卷至原材料获取） | **不可分** |
| A3 生产 | 生产过程（二级，上卷至生产） | 可（= 生产） |
| A4 运输交付 | 运输/交付（一级） | 可 |
| A5 安装/包材处置 | **无对应阶段**，被迫并入生命末期 | **不可分** |
| B1–B7 使用 | 使用（一级） | 可（无使用年限模型） |
| C1 拆除 / C3 加工 | 生命末期（一级） | **不可分** |
| C2 废弃物运输 / C4 废弃物处置 | 生命末期二级阶段 | **不可分** |

**实测输出：**

```
录入 28 条 → 检测：passed（阻断 0 / 提示 0）
阶段汇总：原材料获取=6.5931  生产=0.8113  运输/交付=0.7027  生命末期=3.3224  使用=0
排放源：material=9.6421  transport=1.0745  energy=0.7128
unitEmission = totalEmission = 11.4295 kgCO₂e/块
口径拆解：设定「kg」→ 2.0668 kgCO₂e/kg；改设「m²」→ 43.892 kgCO₂e/m²（二者不可并存）
```

**与案例预期对照：**

| 案例结果断言 | 预期值 | 系统可否产出 | 说明 |
| --- | ---: | :--- | --- |
| A1–A3 不含生物碳 | 7.4043738139 | ⚠️ 近似 | 需手工把「原材料获取+生产」相加（=7.4044），无 A1–A3 模块边界选择 |
| A1–A3 含生物碳净值 | 0.3522356658 | ❌ | 无生物碳计算 |
| A1–C4 不含生物碳 | 11.4294699873 | ⚠️ 近似 | =11.4295（差 0.00003，精度截断） |
| A1–C4 含生物碳净值 | 11.4294699873 | ❌ | 无生物碳计算 |
| A1–C4 按重量 | 2.0668119326 kgCO₂e/kg | ⚠️ | 可出，但需人工折算换算系数、且与 m² 不可并存 |
| A1–C4 按面积 | 43.8919738376 kgCO₂e/m² | ⚠️ | 同上 |
| 分模块 A1/A2/A3/A4/A5/C1–C4 | — | ❌ | 阶段无模块编码，多模块被合并 |

> 结论：**6 项结果断言中，0 项可完整、规范产出**；仅总量与两个归一化值可「近似」得到。

## 五、是否满足「通用产品碳足迹核算业务要求」的判定

| 业务能力 | 是否满足 | 依据 |
| --- | :--- | --- |
| 摇篮到大门 / 摇篮到坟墓流程闭环 | ✅ | 主链路可跑通 |
| 化石排放量测算（活动量 × 因子） | ✅ | 11.4295 与手算一致 |
| 分模块（A1–C4 / EN 15804）核算 | ❌ | 无模块编码、无 A5 阶段 |
| 生物碳核算与对称性校验 | ❌ | 无字段、无双口径、无 E16 |
| 单位产品 / 面积 / 重量归一化 | ⚠️ | 仅一个换算口径、净重/面积未采集 |
| 分配（质量/经济/能量） | ❌ | 未落地 |
| 数据质量与可追溯（来源/凭证/DQI） | ❌ | 模型缺字段 |
| 因子版本 / 有效期 / 地区电力属性 | ❌ | 无 |
| 审核 / 审批 / 版本锁定 | ❌ | 无审核流 |
| 报告出具（可对外） | ⚠️ | 写死文案、HTML+.doc、无版本 |
| 情景分析 / 热点 / 对比 | ❌ | 无 |

**综合判定：不满足通用产品碳足迹核算要求。** 适用范围应限定为「企业内部快速估算 / 概念演示」，不应作为第三方核查或对外披露结果的出具工具。

## 六、修复优先级建议

**第一批（决定案例能否算对，建议 1–2 个迭代内完成）**

1. 生命周期阶段引入 **`stageCode`（A1–A5 / B1–B7 / C1–C4）与 EN 15804 模块映射**，补齐 A5 阶段；结果页支持 A1–A3 / A1–A4 / A1–A5 / A1–C4 模块边界（BV-P0-02）。
2. 活动数据增加 **`biogenicFactor` / `biogenicUptake` / `biogenicRelease` 字段**，与化石因子并列；结果增加「不含生物碳 / 含生物碳净值」双口径，实现**生物碳对称性校验（E16）**（BV-P0-01、BV-P0-03）。
3. 步骤①补充**净重 + 单位、长/宽 → 自动算面积**；结果支持**块 / kg / m² 三口径并存**并处理除零（BV-P0-04）。
4. `flow_direction` 扩展为「投入 / 产品 / 副产品 / 废弃物 / 回收物 / **校准项**」；负数流改为「数量 + 方向 + 流向说明 + 原因 + 凭证」强制项（BV-P0-05）。
5. 活动数据补齐 **`factor_source` / `data_quality` / `evidence_id` / `allocation_method`** 字段（BV-P0-06）。

**第二批（让流程能规范走完）**

6. 计算精度改为内部 ≥10 位、仅展示层取 4 位（BV-P1-01）。
7. 分配比例接入计算并补齐「分配规则管理」（BV-P1-02）。
8. 因子库补 `version / validFrom / validTo / region / 电力属性`（BV-P1-05）。
9. 导入模板补齐因子、流向、生物碳、数据质量、凭证列，并加**重复明细去重**（BV-P1-06）。

**第三批（管理面与增值）**

10. 审核流（提交审核 / 审核中 / 通过 / 驳回 + 意见 + 日志）（BV-P1-03）。
11. 报告真实 docx 导出、图表渲染、章节按数据生成、报告版本化（BV-P1-04）。
12. 情景分析、热点 Top N、供应商/产品横向对比（BV-P2-04）。
