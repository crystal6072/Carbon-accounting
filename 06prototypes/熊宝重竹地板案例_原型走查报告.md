## 0. 总结论

> **框架级闭环已通，案例级闭环未通。**

原型已经打通了「建档 → 阶段 → 工序 → 活动数据 → 数据检测 → 核算 → 结果 → 报告 → 完成」这条**流程管线**，且核算结果是**真实计算**出来的（`computeRowEmission` / `runPcfCalc`，非写死），这是原型的最大价值。

但把《熊宝》这份**真实业务数据**灌进去时，会在三处硬阻塞上走不通：

| 阻塞层级 | 问题 | 后果 |
| :--- | :--- | :--- |
| **数据结构错配** | 原型按「产品 → 工艺流程 → 工序 → 投入/产出项」组织数据；案例是「生命周期阶段 → 分类 → 项目」的 28 条平铺清单 | 无法自由录入一条非工序明细（如「误差调整」「一般工业垃圾焚烧」），无导入、无批量录入 |
| **负数流向缺失** | 活动量保存校验强制 `≥ 0` | 4 条明细（竹粉 / 前加工边角料 / 后加工边角料 / 误差调整）**直接录不进去** |
| **口径维度缺失** | 无 A1–C4 阶段编码、无含/不含生物碳双口径、无按重量 / 面积归一化 | 案例要求的 6 项结果断言**一项也出不来** |

按文档 §9.6「原型跑通判定」8 条判定：**通过 1 条、部分通过 3 条、不通过 4 条**。
按文档 §9.6 最后一段给出的「核心计算链路最低通过线」（28 条入库 / A1-A3 与 A1-C4 准确 / 标准化结果准确 / 热点排序准确）：**4 项中 3 项不通过，未达标**。

**数值偏差量化**：即使把全部 28 条都强行录入（假设绕开结构限制），仅「负数活动量不支持」这一项就会造成：

- 竹粉行 `-6.1878987381 × 0.04987 = -0.3085905101` 被迫变为 `+0.3085905101`，**单项偏差 +0.6172 kgCO₂e**
- A1-A3：`7.4044 → 8.0216`（**+8.33%**）
- A1-C4：`11.4295 → 12.0467`（**+5.40%**）

远超 §9.4 规定的 `±0.0001` 容差。

**精度口径不符**：§9.4 要求「内部保留 10 位以上小数，页面显示 4 位」，但 `roundCalc` 对**存储值本身**做 `Math.round(v*10000)/10000`（`mock/index.ts:3983`），即内部也只有 4 位；§9.5 第 9 项「后端继续使用原始精度，不使用展示值回算」**不满足**。

## 4. 对照 §9.5「前端必须触发的校验」10 项

| 场景 | 预期反馈 | 结论 | 实际情况 |
| :--- | :--- | :--- | :--- |
| 单位不匹配（kWh 绑 kgCO₂e/kg） | 阻止计算并定位错误字段 | ⚠️ **基本满足** | 检测规则 B4 存在（`unitTypeOf` 比单位**类型**），kWh(能量) vs kg(重量) 会拦截。但①只在「提交检测」时触发，非录入时实时；②只比类型不做量纲换算（`t` 与 `kg` 会通过）；③定位到「数据项」而非字段级 |
| 因子缺失 | 标记「待匹配」，结果不可发布 | ⚠️ **部分** | B2 阻断 ✅；但无「待匹配」标记态，且无「不可发布」概念（本就无发布/审核） |
| 负数活动量 | 提示确认流向或分配规则，允许有依据地保存 | ❌ **不满足** | `mock/index.ts:3446-3458` 直接抛错「活动数据必须为大于等于 0 的数字」，**完全禁止录入** |
| 校准项 | 要求填写原因、依据和审批信息 | ❌ **不满足** | 系统无「校准项 / 质量平衡调整项」对象类型；`flowType` 枚举中无对应类别 |
| 期间不完整 | 阻止提交审核 | ✅ **满足** | 步骤① `startDate/endDate` 必填 + 起止顺序校验；服务端 `updatePcfProjectStepOne` 二次校验 |
| 边界缺项 | 提示与所选边界不一致 | ⚠️ **部分** | 有 B5「阶段已纳入但未匹配工序」；但案例要求的 A1-C4 阶段级缺项检查不存在（无 C4 编码） |
| 重复明细 | 给出重复提示，允许确认合并 | ❌ **不满足** | 无导入功能，因此也无去重机制（行由工序流唯一生成，天然不重复） |
| 除数为零 | 不计算单位重量/面积结果并显示原因 | ❌ **不满足** | 重量/面积根本未采集，无此计算路径 |
| 精度变化 | 后端继续用原始精度 | ❌ **不满足** | 见 §3 精度口径 |
| 版本变化 | 修改已锁定任务 → 创建新版本并保留旧结果 | ❌ **不满足** | 修改已核算数据 → 状态回退 `ongoing` + `currentStep=1`，**不产生新版本**；只有主动点「重新计算」才递增版本 |

## 6. 不同产品碳足迹核算场景支持度矩阵

| 核算场景 | 支持度 | 说明 |
| :--- | :--- | :--- |
| 摇篮到大门（B2B 半成品 / 原材料） | ✅ **支持** | `gate` 边界，排除运输与交付/使用/末期 |
| 摇篮到坟墓（完整 LCA） | ✅ **支持** | `grave` 边界 |
| 分模块 A1/A2/A3/A4/A5/C1-C4 拆分 | ❌ **不支持** | 阶段库为 5 个粗粒度中文阶段，无 ISO/EN 15804 模块编码；不支持二级阶段（种子无 level-2 数据，且 `deriveStages` 写入 `parentName: ''` 会导致二级联动失效） |
| 含 / 不含生物碳双口径 | ❌ **不支持** | 见 §7-A |
| 生物碳吸收与末端释放对称性校验 | ❌ **不支持** | 因子库描述中提及「否则触发 E16」，但 E16 **无实现**（全库仅命中注释） |
| 副产品 / 多产出分配 | ⚠️ **假象** | 有 `allocateRatio` 字段与 B3 校验（合计 100%），但 `computeRowEmission` **完全不引用该字段**，填了不生效 |
| 输入侧分摊（质量/经济/能量分配） | ❌ **不支持** | `allocateRatio` 只挂在多产出工序的产出项；输入侧无分摊基准/方法字段；「分配规则管理」为 **PlaceholderPage 占位** |
| 负数流 / 回收信用 / 系统边界扣减 | ❌ **不支持** | 活动量强制 ≥ 0；类型虽定义 `CalculationDirection = positive/negative/deduction` 与 `supportsNegativeResult`，但计算引擎未使用（FM-007 回收信用法**不会扣减**） |
| 使用阶段（维护/替换/能耗年化，B1-B7） | ⚠️ **弱支持** | 有「使用」阶段可挂工序，但无使用年限、维护频次、替换率等模型要素 |
| 末期回收 / 多种处置路径（C1-C4） | ❌ **不支持** | 单一「生命周期末期」阶段，无法区分处置路径与回收率 |
| 单位产品 / 单位面积 / 单位重量归一化 | ❌ **不支持** | `unitEmission === totalEmission` |
| 情景分析（换胶水 / 改电力 / 改运输 / 提回收率） | ❌ **完全缺失** | 全库搜索「情景 / 减排 / 热点 / 对比」无业务实现 |
| 供应商 / 产品横向对比 | ❌ **缺失** | 仅有 `/pcf/project/product/:id`（按产品聚合项目列表），无足迹对比、无排序 |
| 因子版本 / 有效期 / 地区电力结构追溯 | ❌ **缺失** | 见 §7-C |
| 数据质量等级（DQI / 谱系矩阵） | ❌ **缺失** | 报告「数据质量评价」是写死段落文本 |
| 审核 / 审批 / 驳回 | ❌ **完全缺失** | 11 个项目状态无审核态 |
| 报告出具与导出 | ⚠️ **弱支持** | 4 页报告可生成，可下载；但下载的是 **HTML 内容 + `.doc` 后缀**，非真实 docx；图 2「阶段分布图」为**占位**；分配原则、数据来源、数据质量为**写死文案** |

## 7. 关键缺陷清单（按优先级）

### P0 · 业务无法闭环（必须补）

**A. 生物碳完全不参与计算**
- `PcfActivityData` / `PcfResultDetail` 无 `biogenic` 字段；计算引擎无化石碳/生物碳分离。
- 单行只有 1 个 `factorId`，无法同时绑「化石因子 + 生物碳因子」（案例每行都需要）。
- 生物碳仅作为**因子分类枚举**（`biocarbon`）存在，可建负因子（F-501 毛竹固碳 -1.0083、F-502 生物碳释放），但：
  - 「是否计入由**模型固碳开关**控制」（`FactorFormPage.tsx:345`）→ **该开关无任何实现**；
  - 「摇篮到坟墓末期须对称计入，否则触发 **E16**」→ **E16 无实现**。
- 影响：案例「含生物碳净值」全部断言无法产出。

**B. 生命周期阶段粒度不足以支撑核算口径**
- 5 个粗阶段（原材料获取 / 生产 / 运输与交付 / 使用 / 生命周期末期）无法表达 A1–A5、B1–B7、C1–C4。
- 无 A5（安装 / 包材处置）、无 C1/C2/C3/C4 拆分、无 A2 独立口径。
- 结果页因此**无法输出 A1-A3 / A1-A4 / A1-A5 / A1-C4 四个边界**（文档 §5.2 明确要求"不要只用总碳足迹一个模糊标题"）。
- 生命周期阶段库支持 level 2，但种子无二级数据；且 `ProjectStepOne.deriveStages` 写 `parentName: ''`，`toggleStage` 靠 `parentName` 联动 → 即便补了二级阶段，**勾选一级时二级不会跟随**。

**C. 活动数据模型缺关键结构化字段**
对照文档 §4.1 推荐的稳健字段表：

| 推荐字段 | 原型状态 |
| :--- | :--- |
| `stage_code`（A1…C4） | ❌ 无（用中文阶段名） |
| `flow_direction` | ⚠️ 仅 `input/output` 二值，无「副产品/废弃物/回收物/校准项」 |
| `activity_amount` / `activity_unit` | ✅ 有 |
| `emission_factor` / `emission_factor_unit` | ⚠️ 因子单位分分子/分母两字段，但**无活动量↔因子单位强制配对校验** |
| `biogenic_flow` | ❌ 无 |
| `factor_source`（数据库/实测/经验/缺省） | ❌ 无（`sourceCategory` 为自由文本） |
| `allocation_method` | ❌ 无（分配规则管理为占位页） |
| `data_quality` | ❌ 无 |
| `evidence_id`（凭证/附件） | ❌ 无 |

**D. 归一化缺失 → 「单位产品碳足迹」是假象**
- `unitEmission: roundCalc(total)`（`mock/index.ts:4141`），类型注释自认「本期 = totalEmission」。
- 步骤①不采集净重（`netWeight` 类型有、种子有、校验注释有，但**表单无字段、保存不写入、`fetchPcfWeightUnitOptions` 无调用方**）。
- 无长 / 宽 / 面积概念 → 案例「0.2604 m²」「43.8920 kgCO₂e/m²」完全无法落地。

### P1 · 数值正确性风险

**E. 分配比例校验了但不参与计算**
`allocateRatio` 被 B3 强制校验合计 100%，但 `computeRowEmission` 未引用 → **用户为满足校验填了比例，排放却没分摊**。多产出工序结果与单产出无差别。这是最容易被误认为"已实现"的假象。

**F. 流向不分正负，回收信用不扣减**
`rawTotal += emission` 对投入/产出同号相加；`CalculationDirection('positive'|'negative'|'deduction')` 与 `supportsNegativeResult` 定义了但引擎不用 → FM-007「回收信用法（负项）」不会形成抵扣。

**G. 精度策略与验收要求不符**
`roundCalc` 把**存储值**也压到 4 位小数；案例要求内部 ≥10 位、展示 4 位。多次重算会累积误差。

**H. 注释与实现脱节（会导致后续返工）**
- `mock/index.ts:120` 注释称排放因子库「有版本化 + 有效期」，但 `FactorItem` 无 `version/validFrom/validTo`，`factorMeta.ts:71` 明确「不做版本化」。
- `App.tsx:36` 注释称「模型管理」完整实现，但菜单无此叶子路由，且其下 `allocation` 是占位页。
- 类型注释称活动数据「绑定公式来自模型快照，前台只读」，但页面提供可修改的「绑定公式」下拉。

### P2 · 体验与流程断点

**I. 核算完成后无法从 UI 进入报告**
`runPcfCalc` 置 `currentStep = 4`；`PcfSteps` 对 `seq > reachableStep` 禁用；工作台步骤④无「下一步 / 生成报告」按钮 → **新建项目报告步骤不可达**（仅能手工改 URL）。

**J. 报告能力偏弱**
下载为 HTML + `.doc` 后缀；图 2 占位；分配原则 / 数据来源说明 / 数据质量评价为写死文本（`REPORT_DEFAULT_TEXT`）；报告为单一版本，重新生成覆盖；「在 Word 中打开」按钮只弹提示无逻辑；报告确认人写死 `'李核算'`。

**K. 无导入 / 批量录入**
活动数据侧完全没有；因子库**有**导入（`FactorImportModal`）——这是目前唯一能批量灌数据的入口，可在准备案例数据时利用。

**L. 未实现模块（PlaceholderPage，共 6 个）**
`/basic/standard` 标准文件库、**`/model/allocation` 分配规则管理**、**`/pcf/my-process` 我的工艺库**、`/system/org`、`/system/user`、`/system/dict`。
其中「分配规则管理」与「我的工艺库」是本次案例的直接相关模块。
（注：步骤①「核算标准」必填，但引用的「标准文件库」本身是占位页，靠 Mock 假数据支撑。）

**M. 其他小问题**
- 创建项目时 `startDate/endDate/boundary` 写死（`2026-01-01 / 2026-12-31 / gate`），案例需要 2025 全年 + `grave`，需手工改。
- Mock 全局时间常量 `NOW = '2026-09-20 10:00'`，所有时间戳非真实。
- 步骤①保存后若状态回退，页面 `activeSeq` 依赖 URL 参数，不会自动跳回步骤 1。
- 项目列表「搜索」按钮只弹 `toast('查询完成')`，过滤实际由输入触发。

## 8. 建议补齐顺序

按「先让案例能算对，再让流程能走完，最后补管理面」排序：

**第一批（让案例数字算得出来）**
1. 生命周期阶段引入 `stage_code`（A1–A5 / B1-B7 / C1–C4），支持二级阶段并修复 `parentName` 联动；结果页按 `SUMIFS` 语义输出 A1-A3 / A1-A4 / A1-A5 / A1-C4 四个边界。
2. 活动数据增加 `biogenic_flow`（或 `biogenic_uptake` / `biogenic_release`）字段，与 `fossil_impact` 并列；结果增加「不含生物碳 / 含生物碳净值」双口径；实现「模型固碳开关」与 E16 对称性校验。
3. 步骤①补充：产品净重 + 单位、长 / 宽 → 自动算面积；结果页支持按「块 / kg / m²」切换；`unitEmission` 做真实归一化，并处理除零。
4. `flow_direction` 扩展为「输入 / 产品输出 / 副产品 / 废弃物 / 回收物 / 校准项」；允许有依据的负数活动量（改为「正数数量 + 方向 + 处置路径」，并保留原负值录入兼容）；引擎按方向决定加减号。

**第二批（让流程走得完）**
5. `allocateRatio` 接入 `computeRowEmission`，实现真实分摊；补齐「分配规则管理」页面（分摊法 / 替代法）。
6. 新增「阶段级自由明细 + 导入」能力，允许不依托工序直接录入一条活动数据（案例 28 条中有多条属于此类）。
7. 修复核算后步骤⑤不可达；改为「重新计算/修改 → 生成新结果版本」而非回退 `ongoing`；补结果版本列表与对比。
8. 内部计算精度改为 ≥10 位，仅展示层取 4 位；因子库补 `version / effectiveFrom / expireAt / 地区电力结构 / 数据质量等级 / 来源类型枚举`。

**第三批（管理面与增值功能）**
9. 审核流（提交审核 / 审核中 / 通过 / 驳回 + 审核意见 + 操作日志）。
10. 情景分析（换因子 / 减量 / 改回收率 / 改运输距离）与热点 Top N、供应商与产品横向对比。
11. 报告：真实 docx 导出、图表真实渲染、章节按实际数据生成（替换写死文案）、报告版本化。

## 9. 走查结论一句话

> 原型已经把「核算项目的流程骨架 + 一个真实可重算的简化计算引擎」做出来了，但**数据模型仍然停留在「工艺工序视角」，而产品碳足迹核算的真实数据是「生命周期阶段 + 物料/能源/运输/废弃物清单视角」**。这一层模型错配，加上生物碳、负数流向、归一化三块缺失，导致《熊宝》这份真实案例**无法在现有原型上完整跑通**。补齐第一批 4 项后，案例的 13 项结果断言可望全部产出；补齐第二批后，端到端 UAT 10 步可完整走完。
