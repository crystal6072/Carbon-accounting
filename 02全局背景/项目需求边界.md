# 项目需求边界

> 依据来源：`02全局背景/项目业务背景.md`、`08reference/木竹产品全生命周期碳足迹服务-功能清单-v1.0.xlsx`。  
> 说明：本文用于界定“木竹产品全生命周期碳足迹服务”的需求范围，不替代 PRD、原型说明、字段清单、接口清单和实施计划。

## 0 结论

| 事项 | 结论 |
| :--- | :--- |
| 项目边界定位 | 建设面向木竹产品的全生命周期碳足迹服务系统，覆盖数据归集、核算建模、批次追溯、报告标签、数据分析、知识数据集、移动采集、数据管控、计量采集和外部系统对接。 |
| 与业务背景关系 | 功能清单与业务背景主线一致，均围绕木竹产品、LCA、碳固存、排放因子、数据治理、上报追溯展开。 |
| 是否存在硬冲突 | 未发现功能清单与业务背景存在直接冲突。 |
| 需要确认的边界 | 功能清单新增了移动端、物联计量、实时采集、ERP/MES 对接、南平区域系数、预算/分期等信息，业务背景未明确，应作为待确认边界，不应直接推定为已确认实施范围。 |

## 1 边界原则

| 原则 | 边界说明 |
| :--- | :--- |
| 业务对象优先 | 仅围绕木竹产品及其原料、工艺、批次、运输、使用、废弃、因子、标准、报告、上报和追溯展开。 |
| 生命周期口径优先 | 默认覆盖原料获取/采伐、生产加工、运输仓储、使用阶段、废弃处置/循环利用；允许按标准选择摇篮到坟墓、摇篮到大门、大门到大门等边界。 |
| 核算可追溯 | 所有核算结果必须能追溯到活动数据、排放因子、核算规则、标准依据、计算过程、版本和操作记录。 |
| 标准不内置唯一口径 | 对碳固存抵扣、生物源 CO₂、GWP100 等存在标准差异的事项，系统应支持口径配置和报告列示，不在需求边界中强行确定唯一业务口径。 |
| 功能清单不等于实施承诺 | 功能清单中的模块可作为需求池范围；是否一期交付、是否对接具体系统、是否采购硬件、是否覆盖全部地区，需要项目确认。 |

### 2.5 全生命周期碳足迹核算

| 生命周期阶段 | 纳入内容 | 边界说明 |
| :--- | :--- | :--- |
| 采伐阶段 | 林地信息、采伐量、出材率、集材距离、设备油耗、采伐损耗、采伐排放、碳固存初算 | 纳入原料采伐和生物质流失核算；林权、采伐证审批不在范围内。 |
| 加工阶段 | 能耗台账、辅料投入、工序碳排放、边角料与废品核算 | 纳入工序级排放与分摊；不替代生产排程、质量检验和设备控制。 |
| 运输阶段 | 原料运输、成品运输、调拨运输、运输方式、距离、载重、装载率、油耗、装卸和仓储排放 | 纳入运输仓储排放核算；不替代 TMS 或 WMS。 |
| 使用阶段 | 设计寿命、维护周期、翻新次数、使用能耗、清洁能耗、长期碳固存 | 纳入典型使用场景参数化核算；实际用户行为采集不作为默认范围。 |
| 废弃与循环 | 回收、再生、焚烧、填埋、堆肥、废弃排放、循环利用减排 | 纳入处置情景和减排量计算；不负责废弃物回收交易和处置调度。 |
| 核算规则引擎 | 排放因子库、标准模型配置、边界范围配置、一键核算和重算 | 支持多标准、多因子、多边界配置；不在本文确定碳固存是否抵扣总排放的唯一口径。 |

## 3 项目外边界

| 不纳入范围 | 排除说明 |
| :--- | :--- |
| 通用企业碳盘查平台 | 本项目以木竹产品碳足迹为核心，不默认覆盖企业组织层面的全范围碳盘查。 |
| 标准制定和认证发证 | 系统支撑标准引用、报告、碳标签和第三方核查材料，不直接代表认证机构出具结论。 |
| ERP/MES/TMS/WMS/SRM 替代建设 | 相关系统只作为数据来源或对接对象，不在本项目内重建完整业务系统。 |
| 硬件采购、布线施工、设备检定 | 计量器具、物联设备、通信协议可纳入管理和接入，但硬件工程范围需另行确认。 |
| 真实供应商审计和数据担保 | 系统记录供应商数据和依据文件，不替代线下审计、合同约束和第三方验证。 |
| 工艺改造实施 | 系统提供优化分析、模拟和建议，不直接承担设备改造、产线调试和投资建设。 |
| 碳交易履约业务 | 功能清单提及上报和平台对接，但不默认覆盖碳配额、CCER、交易撮合和履约管理。 |
| 公共政策数据库全量维护 | 系统可维护标准规范和指南文件，不承诺外部政策法规的全量自动采集。 |

## 4 分期边界

功能清单出现一期金额 `179.25` 万元、二期金额 `258.75` 万元、合计 `438` 万元，但未明确每个模块属于一期或二期。本文不据此推定实施阶段，仅给出建议分期口径：

| 阶段 | 建议纳入 | 建议后置 |
| :--- | :--- | :--- |
| 一期建议边界 | 基础支撑、基础库、供应商碳足迹库、全生命周期核算、批次追溯、数据质量控制、标准/因子/知识库、基础报表、必要接口 | 先形成可核算、可追溯、可出报告的业务闭环。 |
| 二期建议边界 | 高阶分析、减排模拟、优势分析、影响因素与优化潜力、移动端 H5、计量采集、集中数据中心、ERP/MES 深度对接、接口安全增强 | 依赖试点数据、现场设备、企业系统和运营规则成熟度。 |

## 5 核算口径边界

| 事项 | 本文边界 |
| :--- | :--- |
| 生命周期边界 | 支持摇篮到坟墓、摇篮到大门、大门到大门和阶段取舍配置。具体产品和报告采用哪种边界，以所选标准、PCR、项目要求为准。 |
| 分摊规则 | 支持重量分摊、产值分摊、数量分摊等方式。默认规则、优先级和例外处理需后续确认。 |
| 排放因子 | 支持国标、行标、IPCC、地方、木竹专用因子及供应商数据，并保留版本和溯源。系统不默认认定某一来源永远优先。 |
| 碳固存 | 支持初始碳固存、使用期长期碳固存和碳流失核算。是否抵扣总碳足迹、是否仅并列展示，应按所选标准确认。 |
| 生物源 CO₂ | 支持单独列示和规则化处理；是否计入总排放不在本文锁定。 |
| 循环利用减排 | 支持再生料替代、资源化利用减排量计算；是否纳入最终结果需标准口径确认。 |
| 缺失数据填充 | 可基于同类产品均值或规则建议填充，但必须保留填充来源、规则、人工确认和质量等级。 |

## 6 数据边界

| 数据类别 | 纳入范围 | 关键边界 |
| :--- | :--- | :--- |
| 主数据 | 产品、品类、工艺、工序、单位、区域、运输方式、燃料类型、供应商、组织、工厂、车间 | 主数据归属、唯一编码和同步机制需确认。 |
| 活动数据 | 采伐、加工能耗、辅料、产量、合格率、运输、仓储、使用、维护、废弃处置、回收利用 | 活动数据应有来源、时间、边界、凭证和质量等级。 |
| 因子数据 | 标准因子、地方因子、木竹专用因子、供应商因子、区域修正系数 | 因子应支持版本、适用条件、来源文件和启停状态。 |
| 计量数据 | 计量器具、物联设备、电碳表、时序采集数据 | 是否真实接入设备、接入协议和采样频率需现场确认。 |
| 结果数据 | 产品碳足迹、阶段排放、工序排放、批次碳足迹、碳固存、减排量、报告、标签、二维码 | 结果数据必须支持重算、版本、报告快照和审计追溯。 |
| 知识数据 | 标准规范、木竹碳专题、典型案例、行业数据集 | 数据集公开范围、授权方式和审核责任需确认。 |

## 7 角色边界

| 角色 | 主要职责 | 边界说明 |
| :--- | :--- | :--- |
| 企业填报人员 | 录入采伐、加工、运输、使用、废弃、供应商等活动数据 | 对录入数据的真实性负责。 |
| 企业核算人员 | 选择产品、批次、边界、因子、模型并发起核算/重算 | 对核算配置和结果解释负责。 |
| 企业审核人员 | 审核异常修正、数据完整性、报告输出和上报材料 | 审核不等同于第三方认证。 |
| 管理员 | 维护基础配置、标准规范、因子、模板、权限和数据集 | 不直接修改企业原始业务事实，修改需留痕。 |
| 行业专家 | 审核知识库、因子、案例、数据集和方法学内容 | 专家审核范围需与项目组织机制匹配。 |
| 第三方核查机构 | 查看核算明细、因子来源、计算过程、上报记录和审计文件包 | 以只读审计视图为主。 |
| 监管/集团/行业平台 | 接收上报数据、回执和报告材料 | 具体对接对象、格式和接口由项目确认。 |

## 8 待确认边界

| 待确认项 | 当前依据 | 影响 |
| :--- | :--- | :--- |
| 项目建设主体 | 建设主体仍不明确；使用主体先按“竹木企业 + 生态环境/政府部门”理解 | 企业主要填报和维护数据，政府部门主要查看汇总数据、核算结果和报告；建设主体仍会影响部署方式、权限开通和运维责任。 |
| 首批产品品类 | 业务背景和功能清单未明确先做哪些产品 | 需要确认先覆盖竹木地板、家具、包装、板材或其他品类；这会影响第一批页面、表单字段、报告样式、核算规则和采集数据。 |
| 一期/二期模块归属 | 功能清单仅给出金额，未明确模块阶段 | 决定 MVP 范围、原型页面和实施排期。 |
| 是否覆盖南平区域 | 功能清单出现“南平及相关核心产区”，业务背景未确认实施地区 | 决定区域基础库和本地化因子的首批范围。 |
| 是否真实接入物联设备 | 功能清单包含计量器具、物联设备、Modbus、MQTT、电碳表 | 决定硬件、协议、数据中心和现场实施边界。 |
| 是否对接 ERP/MES | 功能清单包含 ERP/MES 对接 | 决定接口清单、字段映射、主数据归属和联调计划。 |
| 碳固存是否抵扣总排放 | 业务背景指出存在口径差异 | 决定核算结果、报告展示和标签口径。 |
| 生物源 CO₂ 和循环利用减排口径 | 业务背景指出需按标准确认 | 决定废弃阶段净排放和总碳足迹结果。 |
| 数据贡献是否形成公共数据集 | 功能清单包含企业数据上报、审核入库、公共数据集 | 决定授权、脱敏、审核和数据质量规则。 |
| 碳标签是否只是模板展示 | 业务背景和功能清单均提到碳标签 | 决定是否包含标签审批、发布、撤销和外部查询规则。 |

## 9 差异对照

| 差异项 | 业务背景表述 | 功能清单表述 | 判断 |
| :--- | :--- | :--- | :--- |
| 项目实施地区 | 标记为待核实，未明确地区 | 区域基础库提到“南平及相关核心产区” | 非硬冲突；功能清单新增线索，需确认是否作为首批区域。 |
| 移动端能力 | 背景主要描述业务闭环，未明确移动端 | 包含移动 H5、现场填报、OCR、离线缓存、扫码追溯 | 非硬冲突；属于采集和追溯入口扩展，需确认是否一期。 |
| 物联计量和实时采集 | 背景强调数据归集治理，未明确硬件接入 | 包含计量器具、物联设备、Modbus、MQTT、时序存储 | 非硬冲突；属于数据来源扩展，需确认是否含硬件和现场实施。 |
| 外部系统对接 | 背景提到企业上报和系统对接语境，未列明具体系统 | 明确 ERP、MES、标准 API、接口安全 | 非硬冲突；需确认具体对接对象、字段和频率。 |
| 预算和分期 | 背景标记预算、建设周期待核实 | 功能清单列出合计、一/二期金额，但模块阶段不清晰 | 非硬冲突；不能据此直接拆分实施范围。 |
