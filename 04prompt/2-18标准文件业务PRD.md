## 文档结构（必须包含以下章节）

### 0. 文档基础信息
- 文档属性表（版本 V0.1、状态：草稿）、变更记录

### 1. 需求概述
- 需求背景：标准文件是**核算依据的载体**；方案 §4.2.5 明确它「供核算模型绑定引用」，**标准差异由不同版本的核算模型承载**。决策 **D3** 要求首发模型绑定 `GB/T 24067-2024`
- 需求目标（3～5 条可验证目标）
- In Scope / Out of Scope（明确：无审核流、无版本化；**附件上传 / 组织自建 / 删除 / 导入 / 导出是否支持必须写清**）
- 涉及角色（平台运营管理员维护系统预置标准；组织管理员维护组织自建标准（若采纳）；专业配置人员在核算模型中引用 —— 对齐方案 §7.1 / §7.2）
- 影响范围（下游：**核算模型 A2-3 的标准依据绑定**、报告 P26 的标准引用、项目的核算依据追溯）

### 2. 用户与使用场景
每条含：触发条件、操作流程、预期结果
- S01 维护系统预置标准文件（平台侧）
- S02 上传 / 更新标准文件附件

- S04 将标准状态标记为「被替代 / 作废」
- S05 标准文件被核算模型引用后的编辑 / 删除限制
- S06 在核算模型中引用标准文件（P14 模型管理的联动）
- S07 查看标准文件详情与引用情况

### 3. 功能清单
| 模块 | 功能点 | 功能描述 | 优先级 |

覆盖：列表与查询、新增 / 编辑 / 查看标准文件、附件上传、版本与替代关系维护、状态变更、导出；组织自建与导入按结论。

### 4. 标准文件的结构与版本规则（**核心章节之一**）
- **「一个版本 = 一条记录」**（按字段清单结论）：唯一键 = 「标准编号 + 版本」；用「**被替代标准**」字段表达新旧关系
- 「被替代标准」的引用方向与校验（不许成环、不许自引用）
- **版本年份**的表达（并入标准编号还是独立字段，按字段清单结论）
- 「标准状态」的流转：现行 → 被替代 / 作废；状态变更是否允许回退
- 「生效日期 / 失效日期」与状态的关系（失效日期是否在状态变更时自动带出）
- 标准类型与适用范围的表达（若涉及国际标准，是否需要「采标程度」IDT / MOD / NEQ）

### 5. 附件与版权边界（**核心章节之二**）
- 是否上传标准文件本体（按字段清单结论）
- **版权合规边界**：GB/T 与 ISO 标准文本均受版权保护，内部分发亦受限。需明确：
  | 场景 | 是否允许 |
  | :--- | :--- |
  | 企业内部查阅 | 按结论 |
  | 作为对外交付物（报告附件等） | **一律不允许** |
  | 供租户间共享（SaaS 多租户） | 需确认是否触及分发 |
- 附件与「附件管理（§C6）」的关系：鉴权、审计留痕
- 附件缺失时的降级（只有元数据，不影响模型绑定与报告生成）

### 6. 业务规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- 「标准编号 + 版本」唯一
- 标准状态的流转约束与回退限制
- 「被替代标准」的引用约束（不许自引用 / 成环）
- 系统预置标准只读、组织自建可编辑（按结论）
- **标准文件被核算模型引用后不可编辑、不可删除**（对齐方案 **§4.9 不可变对象**）；如需变更，以**新版本记录**承载
- 删除规则：被引用的标准不可删除；系统预置标准不可删除
- 状态变更的连锁处理：标记「被替代 / 作废」后，已引用该标准的模型与项目如何处理（对齐 **E13**）
- 附件上传 / 替换的约束
- 导出规则
