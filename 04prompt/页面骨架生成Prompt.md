# 页面骨架生成 Prompt

> **适用场景**：在完整 Demo PRD 和前端原型之前，需要先确认页面结构（区域顺序、字段投影、动作位置）时，让 AI 用页面骨架模板生成页面骨架。
> **模板路径**：`04-常用模版/04-前端Demo PRD/标准型页面&模块的PRD文档集/页面骨架模板.md`
> **定位**：页面骨架是**可选**的快速走查中间产物；如果页面结构已清楚（已有 Demo PRD 或原型），可以跳过。

---

## 输入要求

用户需提供：

1. 模块名和本期页面范围（列表页/新增编辑页/详情页/其他容器）
2. 字段清单路径（字段投影的唯一来源）
3. 业务 PRD 路径（动作名称和位置的唯一来源）
4. 如已有页面方案或参考原型，一并提供

## 权威边界

- 字段名称只来自字段清单，动作名称只来自业务 PRD，不自行发明
- 只画结构和字段投影，不写控件细节、枚举、校验时机、反馈文案、Mock 和代码实现
- 不存在的页面和容器直接删除，不为每种容器预建空章节

## 输出要求

1. 先读取字段清单和业务 PRD，再输出骨架
2. 每模块只保留 1 份页面骨架，不按页面拆分文件
3. 严格遵循模板中的「ASCII线框绘制规则」：
   - 字段多时优先放宽到 90~100 字符，最多不超过 120 字符
   - 视觉对齐即可，禁止用大量半角空格或连字符硬拉行尾对齐
   - 表格列按表头最短宽度设定，不统一拉齐到最长列
   - 超宽表格只保留前 4-6 个核心业务字段 + 省略号 + 操作/合计列，其余字段图外一行说明
   - 整页壳层线框画一次，主工作区内部在后续小节独立展开，不重复画导航和顶栏
4. 用 markdown 代码块包裹，语言标记 `text`

## 自检清单

- [ ] §0 写清本期全部页面和容器，不存在的章节已删除
- [ ] 区域顺序与业务使用路径一致
- [ ] 列表、表单、详情字段与字段清单一致
- [ ] 动作名称和位置与业务 PRD 一致，不存在本期不支持的假入口
- [ ] 高风险动作（删除、作废、反审核等）未遗漏原因或精确匹配输入
- [ ] 只包含结构和字段投影，没有写控件、反馈、Mock 或代码实现
- [ ] ASCII 线框符合绘制规则：信息密度优先，禁止硬补空格/连字符拉齐
