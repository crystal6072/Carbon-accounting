## 模块定性（不得偏离）
- 模块名称：**计量单位库**（含「单位字典」+「单位换算关系」两个子对象）
- 业务归属：后台管理 → 基础库 → 计量单位库（方案 §2.3 A1-9、§4.2.3、§八 P11）
- 模块类型：**基础数据维护（系统预置 + 组织自建）**；不是业务单据、无审核流
- 维护形态：列表 + 独立详情页 + 独立新增/编辑页；换算关系在同一模块内维护
- **本模块不是业务功能，而是核算引擎的底层依赖设施**（方案 §4.2.3 原文），四个作用必须体现在字段设计里：
  1. 统一填报口径（单位字典）
  2. **支撑单位换算**（无换算关系则 `活动数据 × 排放因子` 无法计算，直接触发异常 E04）
  3. 统一功能单位与结果口径（gCO₂e / kgCO₂e / tCO₂e、每双 / 每件 / 每千克）
  4. 支撑质量平衡校验（异常 E09 常见原因就是单位不统一）
- 数据来源两档：**系统预置（`PUBLIC`，只读）** / **组织自建（`ORG`，可编辑）**（方案 §3.3.3）
- 状态：启用 / 禁用；**无版本化**（单位与换算关系为基础字典，历史固定，可作废不可改）
- **设计基调（不得偏离）**：本模块定位就是一本「**单位字典**」，**不做复杂设计**。以下内容**不得设为用户字段**，一律作为系统内置规则处理：
  - 单位类型本身（系统内置枚举，**不开放维护**）
  - 「是否可换算」（内置规则：数量类不可换算）
  - 「是否可用于功能单位 / 结果单位」（由单位类型推导）
  - 「换算小数位」「可见性」「单位来源」等扩展字段
  - 目标：字段总数控制在 10 项以内
- 适用模板：`07template/04-前端Demo PRD/标准型页面&模块的PRD文档集/字段清单模板.md`

## ⚠️ 必须先给出结论的设计分歧（不得回避）

### 分歧 1：换算关系的建模方式（Q01）

方案 §4.2.3 的模型设计把「单位换算关系」定义为一个独立对象：

```text
单位换算关系
├── 源单位 → 目标单位
├── 换算系数 / 换算公式
├── 适用对象（通用 / 指定物料 / 指定能源）
└── 数据来源与生效状态
```

| 口径 | 内容 | 代价 |
| :--- | :--- | :--- |
| **A（推荐，简化）** | **不建独立换算关系对象**：每个非基准单位只记录「**对应基准单位 + 换算系数**」，任意单位之间的换算统一经**基准单位**中转（A → 基准 → B）。N 个单位只需 N 条记录 | 无法表达"任意两单位直接换算"的特殊场景；按物料专属换算无法表达（该需求本就在方案待确认事项中） |
| B（方案 v1.2 原文） | 独立「单位换算关系」对象，支持任意两单位直接换算 | 维护量按 N² 增长；同一对单位可能出现矛盾关系（A→B 与 B→A 系数不一致）；需额外的冲突校验 |

**请给出结论或明确标【待确认】并写明推荐口径。** 若采纳口径 A，字段清单需相应调整（换算系数挂到单位主对象上）。

### 分歧 2：换算是否支持「公式」（Q02）

方案 §4.2.3 提到「换算系数 / **换算公式**」。本期是否支持公式（如 `y = ax + b`、含含水率的非线性换算）？

> 参考已决策口径 D4（计算引擎「内置标准公式模板 + 参数级自定义，公式级自定义后置」），**建议本期只支持乘除系数**，公式作为扩展位预留，标【待确认】。
