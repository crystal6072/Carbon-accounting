一、范围要求
1. 一次只梳理这一个功能，以及完成该功能必需的弹窗、提示和跳转。
2. 具体操作以原型实际存在的内容为准，不自行增加功能。
3. 涉及其他功能时，仅说明必要的业务关联和影响，不展开梳理。
4. 本功能完成后停止，等待我指定下一个功能。

二、表达要求
1. 使用产品经理的业务语言，说明设计逻辑、使用条件、业务限制和操作结果。
2. 使用页面上用户能看到的名称。
3. 不涉及代码、接口、技术字段名、数据库表等技术实现内容。
4. 避免“进行相关处理”等含糊表述，把规则说具体。
5. 不重复描述显而易见的页面样式。
6. 不将推测写成已确定的需求。

三、批注内容
按实际情况包含以下内容。有则显示，没有则省略，
不保留空标题，不写“无”或“不适用”，不为凑齐结构而补充内容。

1. 整体流程
- 适用于存在多个业务步骤、处理环节或流转关系的情况。
- 说明从什么条件开始，经过哪些环节，各环节如何衔接，
  是否存在分支，以及在什么情况下结束。
- 简单的单步操作不强行整理为整体流程。

2. 全局规则说明
- 说明适用于整个功能，或多个操作共同遵循的业务规则。
- 例如适用范围、统一限制、通用权限、共同处理原则等。
- 仅影响某个操作的规则，放到对应操作下。
- 全局规则集中说明，局部批注按需引用，避免重复。

3. 业务状态说明
- 若存在业务状态，说明每个状态的含义、进入条件、
  可以进行的操作，以及状态如何变化。
- 页面加载、按钮禁用等交互表现放到相关操作说明中，
  不作为业务状态。
- 没有业务状态时，不展示此部分。

4. 操作功能
- 按原型实际存在的操作逐项说明。
- 说明操作目的、入口、可操作条件、用户操作过程，
  以及成功、失败、取消或关闭后的结果。
- 只说明当前操作实际涉及的情况。

5. 对应业务规则
- 将具体规则归属到相关操作或内容旁，便于对照理解。
- 说明允许和不允许的情况、判断条件、限制、关联影响、
  特殊情况及对应提示。
- 操作功能和对应业务规则可以放在同一条批注中，
  无需为了分类而拆成重复说明。

6. 字段说明
- 使用页面展示的业务名称，说明其业务含义。
- 根据实际情况说明：填写或选择方式、是否必填、默认值、
  可选范围、格式或长度限制、单位、重复限制、可否修改、
  与其他内容的联动关系等。
- 对自动展示的内容，按需说明其业务来源或形成规则。
- 仅保留有实际意义的信息，不逐项机械填写。
- 不涉及技术字段名、数据类型、存储方式等实现细节。

四、标注位置
1. 在当前功能标题附近设置独立的“全局说明”标注入口；
   仅在存在全局说明时显示。
2. 整体流程存在时，在功能入口或标题附近设置对应标注。
3. 业务状态说明放在状态展示或选择位置附近。
4. 操作说明及对应业务规则放在相关按钮或操作区域附近。
5. 字段说明放在对应填写、选择或展示内容附近。
6. 使用编号关联批注，支持查看和收起，不遮挡正常操作。
7. 同一规则只保留一处完整说明，其他位置按需引用。

第一步：先梳理本功能，给出拟添加的批注内容及对应位置。
区分已确认规则、原型已表现但需要核对的行为，以及待确认问题。
“原型无法判断”不等于“没有”，相关问题单独列出供我确认。

第二步：我确认后，再将确认的内容标注到原型上。
