### 5. 模型组成与配置机制（**核心章节之二**）
逐项写清方案 §4.3.1 的 8 项组成在**本版本如何落地**（与字段清单一一对应）：
- **基本信息**：编码 / 名称 / 适用行业 / **使用状态（启用 / 停用）** / 说明（**无版本字段**）
- **边界定义**：**单选**、与项目边界的一致性约束（不一致 → 阻断引用）
- **生命周期阶段规定**：按「行业 + 边界」加载基线的机制（D2）；模型侧**只读展示**；**排除归项目级**
- **计算规则**：**不做「计算规则模板」，以「计算公式」（`/model/calc-engine`）为准**——只写模型侧「公式绑定与命中优先级」边界，细节指向 `08计算引擎配置`
- **因子规定（D4）**：结构化配置段只读 + **3 个开关**；匹配优先级「组织自建 > 系统预置」；**匹配结果人工确认可替换留痕**
- **报告规定（D1）**：固定模板，只读
- **分配规则**：**不落字段**，归 P16；模型只声明遵循 §6.4 层级
- **检测规则（A2-4）**：按字段清单结论（**推荐只读展示**）；**与 E01–E16 的对应关系表**（至少覆盖 E03 / E04 / E05 / E07 / E08 / E09 / E10 / E11 / E12 / E14 / E15 / E16 中模型可控的部分）
- **启用 / 停用**：见 §6

### 6. 业务规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- **唯一性约束**（**模型编码全局唯一**；模型名称不唯一 —— 按 P3 无版本维度）
- **启用规则**：启用前置校验（基本信息完整？边界已选？已绑定公式？因子开关已填？）；**仅「停用」模型可启用**；**启用即冻结**（不可编辑 / 不可删 / 不可维护绑定）；启用后可被项目引用
- **停用规则**：停用后**不可被新项目引用**；**已引用项目的历史快照保留**；停用后可编辑 / 可删 / 可维护绑定；**启用 ⇄ 停用双向可逆，无终态**
- **删除规则**：**仅「停用」可删**；删除前提示是否已被项目引用（不影响历史快照）；删除同时清理绑定行
- **无版本化规则（P3）**：**不产生新版本、不保留模型历史版本**；"当时用的模型配置"由**项目快照**还原；**禁止项目实时引用最新模型**（§4.9 原则不违反）
- **边界一致性规则**：项目边界与模型边界不一致时的拦截
- **阶段加载规则**：项目创建时按「行业 + 边界」自动加载对应基线（§5.1 步骤 3）；模型变更不追溯已建项目
- **检测规则冻结规则**：规则随**项目快照**冻结；同一数据 + 同一规则版本 → 同一结论（可复现，§6.2）
- **因子开关联动规则**：生物碳固碳开关开启 + 因子「生物碳类型 = 吸收」→ 摇篮到坟墓项目末期须对称计入释放或注明长期储存，否则 **E16**（§6.5）
- **因子规定只读规则**：不做配置页（D4）；**开放配置化的触发条件**（接入第二套标准 / 行业间匹配规则冲突 / 客户明确要求改优先级）必须写明
- **标准依据规则**（D3）：绑定标准文件；标准文件被替代 / 作废时，模型**不自动产生新版本**（无版本化），由业务决定是否调整并重算
- **模型变更对已建项目的影响**：**项目快照冻结、模型变更不影响已建项目；需按新模型重算走 E13**（对齐 §4.9 口径 2）——本文必须写清
- **复制 / 另存为规则**（若采纳）：副本为新模型编码、默认「停用」、保留来源标记
