## ⚠️ 必须先给出结论的建模分歧（不得回避）

### 分歧 1：「阶段基线」是否为一个独立对象（Q01，最高优先级）

方案里有两处表述需要对齐：

| 出处 | 表述 |
| :--- | :--- |
| 方案 §4.2.4 | 「系统提供**默认阶段基线**（一级 + 二级），用户可自定义」；阶段字段含「**是否默认纳入（按边界）**」「**适用行业（可选）**」 |
| 方案 **决策 D2** | 「默认阶段基线**按行业预置多套**（一套通用/制造业基线 + 木竹基线 + 后续行业基线），**每套含「一级 + 二级 + 按边界的默认纳入规则」**；项目创建时按「行业 + 边界」自动加载对应基线……**行业基线由行业库承载，与核算模型解耦**」 |

两种建模口径：

| 口径 | 结构 | 取舍 |
| :--- | :--- | :--- |
| **A（推荐，简化）** | **单一对象「生命周期阶段」**，阶段自带「适用行业」与「按边界的纳入规则」；「基线」= 按「行业 + 边界」**查询出来的阶段集合**，不是独立实体 | 简单、少一个对象；能满足 D2「按行业预置多套」的诉求（木竹专属阶段标注适用行业 = 木竹即被隔离出来）。代价：基线无法作为可发布 / 可选中的实体，也无法表达"同一阶段在两个行业基线下顺序不同"（可通过行业专属阶段的不同顺序值变通） |
| B | **两个对象**：① 生命周期阶段（阶段字典：一级/二级、顺序）② 阶段基线（基线名称 + 适用行业 + 阶段清单 × 各阶段纳入规则） | 阶段字典可复用、基线可作为实体被项目选中；符合 D2「每套基线含完整阶段结构」的字面读法。代价：多一个对象与两层维护 |

**请给出结论或明确标【待确认】并写明推荐口径。**

### 分歧 2：「按边界的纳入规则」如何表达（Q02）

| 口径 | 取值 |
| :--- | :--- |
| **A（推荐）** | **三态枚举**：《必须纳入 / 可选纳入 / 不纳入》，摇篮到大门与摇篮到坟墓各一个字段 |
| B | 两态布尔：是否默认纳入 |

依据：方案 **§4.3.1** 明确写「生命周期阶段规定：各边界下**必须纳入 / 可选纳入 / 排除**的阶段」，是三态；而 §4.2.4 写的是「是否默认纳入（按边界）」，是两态。**两处表述不一致，需以本清单结论为准。**

### 分歧 3：阶段是否允许「排除」及排除原因的归属（Q03）

- 方案 §5.1 第 4 步：「按边界默认加载阶段；**排除项必须有原因**」
- 方案 §5.4 **E11**：「阶段不适用无理由」→ 可计算但标风险、阻断报告

请明确：**「排除 + 填原因」这个动作发生在哪里？** 是（a）在本模块的阶段主数据上设置，还是（b）在**项目内的阶段配置**（P20 生命周期模型配置）里按项目设置？

> 推荐 (b)：本模块只提供**默认规则**；「排除 + 原因」是**项目级**行为（不同产品可能有不同理由），不应写回阶段主数据。
