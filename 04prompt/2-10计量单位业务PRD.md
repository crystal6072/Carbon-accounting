## 模块定性（不得偏离）
- 模块名称：计量单位库
- 模块类型：**基础数据维护**（系统预置只读 + 组织自建可编辑），**非业务单据、无审核流、无版本化**
- 维护形态：列表 + 独立详情页 + 独立新增/编辑页；单位与换算关系在同一模块内维护
- 状态：启用 / 禁用；数据来源两档：系统预置（`PUBLIC`，只读）/ 组织自建（`ORG`，可编辑）
- 不适用：审核流、外部系统推送、单据下推、版本化
- **架构定位**：本模块是核算引擎的底层依赖设施（方案 §4.2.3），不是业务功能；它的正确性直接决定计算能否执行
- **设计基调（不得偏离）**：本模块定位就是一本「**单位字典**」，**不做复杂设计**，**业务规则总数控制在 10～12 条以内**。禁止出现下列内容：
  - 「单位类型字典维护」功能（类型为系统内置枚举）
  - 「是否可换算」「是否可用于功能单位 / 结果单位」「换算小数位」「可见性」等用户字段
  - 公式型换算、按物料专属换算、跨类型换算
  - 任何形态的版本化管理

## 文档结构（必须包含以下章节）

### 1. 需求概述

- 需求目标（3～5 条可验证目标）
- In Scope / Out of Scope（明确：无审核流、无版本化；**导入 / 导出 / 删除 / 按物料专属换算是否支持必须写清**）

### 2. 用户与使用场景
每条含：触发条件、操作流程、预期结果

- S05 单位被引用后的编辑 / 禁用 / 删除限制

### 3. 功能清单
| 模块 | 功能点 | 功能描述 | 优先级 |

覆盖：单位列表与查询、新增 / 编辑 / 查看单位、换算关系维护、启停、导出；导入按结论。

### 4. 单位分类与基准单位规则（**核心章节之一**）
- 「单位类型」枚举与各类型的基准单位（重量 / 能量 / 距离 / 体积 / 面积 / 数量 / 时间 / 碳排放量）
- **每个类型下基准单位唯一**，且基准单位不可删除、不可禁用、不可改类型
- 基准单位能否修改（若允许，需说明对已有换算关系的影响）
- 「是否可用于功能单位」「是否可用于结果单位」的判定规则
- 「碳排放量」类型与结果单位（gCO₂e / kgCO₂e / tCO₂e）的口径（方案 §6.1.1 明确本期 CO₂e ≡ CO₂）

### 5. 换算规则（**核心章节之二**）
- 换算建模口径（口径 A 经基准单位中转 / 口径 B 任意两单位直接换算）—— 与字段清单结论保持一致
- 换算方向：单向存储、系统支持反向换算（取倒数）
- 换算系数为正数、不允许为 0；精度与小数位处理
- 是否支持公式型换算（参考已决策 D4 精神，本期建议只支持乘除系数）
- **不可换算的判定与后果**：单位类型不同 → 不可换算 → 触发 E04，**阻断核算与报告**
- 换算在核算链路中的位置：碳排放量 = 活动数据 × 排放因子 × **单位换算系数** × 分配系数（方案 §6.1.1）
- 换算关系缺失时的兜底：是否允许人工指定换算（【待确认】）

### 6. 业务规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- 单位符号 / 名称在同类型下的唯一性
- 基准单位唯一性与保护规则
- 系统预置单位只读、组织自建可编辑
- 单位被引用后的锁定范围（编码 / 符号只读？能否禁用？）
- 禁用规则：禁用后不可被新业务选用，历史引用保留
- 删除规则：被引用的单位不可删除；基准单位不可删除
- 换算关系的新增 / 修改 / 作废规则（修改后是否影响历史核算结果）
- 换算关系冲突校验（若采用口径 B：A→B 与 B→A 必须自洽）
- **历史核算结果的口径保护**：单位或换算关系变更后，已核算项目如何处理（对齐方案 E13 与不可变对象原则，见 §4.9）
