## 文档结构（必须包含以下章节）

### 1. 需求概述
- 需求背景：物料是工序投入项 / 产出项的引用对象，是排放计算的挂载点；物料默认单位是 E04 与质量平衡校验的前提
- 需求目标（3～5 条可验证目标）
- In Scope / Out of Scope（明确：无审核流、无版本化；**导入 / 导出 / 删除 / 批量启停是否支持必须写清**）
- 涉及角色（平台运营管理员维护系统预置；组织管理员维护组织自建 —— 对齐方案 §7.1 / §7.2）
- 影响范围（下游：工序投入项、产品信息、数据填报 P22、因子匹配）

### 2. 用户与使用场景

| 模块 | 功能点 | 功能描述 | 优先级 |

### 4. 物料分类与单位规则
- 物料分类的结构（树 / 扁平字典）与取值来源（【待确认，见字段清单】）
- 物料分类与产品分类、（若采纳）适用行业的关系
- **物料与单位的关系（已确认，不得推翻）**：
  - 物料**不持有单位**（方案 §4.2.1 原列有「默认单位」，此处为**有意偏离**，需同步修订方案）
  - 单位在**工序的投入项 / 产出项**中逐行选择；**E04**（因子单位不匹配）与 **E09**（质量平衡）的校验以**工序行的单位**为准
  - 同一物料在不同工序可选不同单位（只要同类型且可换算）—— 这正是「不预设默认单位」的理由
  - 若需「按物料推荐单位」的便利，应作为**填报页（P22）的辅助推荐**实现，**不得把单位写回物料主数据**

### 5. 「数据来源」的口径（**已确认，不得推翻**）
- 写清本模块的「数据来源」**只有一个含义**：系统预置 / 组织自建，仅用于判定可编辑性与可见范围
- 写清**已移除**的三个内容及理由（不得重新加回）：
  - 「数据获取方式」（实测 / 统计 / 估算 / 供应商 / 数据库）→ 属**活动数据**属性（方案 §4.6 在「活动数据」章节），在数据填报（P22）时记录
  - 「引用资源」→ 竞品做法，不采纳
  - 「可见性」→ 由「数据来源」推导
- 说明 **DQR（数据质量等级）的承载点也在活动数据**（方案 §4.6：DQR 默认随数据来源生成），不在物料主数据

### 6. 业务规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- 物料编码 / 名称的唯一性
- 默认单位必填且必须引用计量单位库
- 系统预置物料只读、组织自建可编辑

- 禁用规则：禁用后不可被新工序 / 产品选用，历史引用保留；已复制到产品版本的副本不受影响
- 删除规则：被引用的物料不可删除；系统预置物料不可删除

- 数据来源类型与引用资源的必填性
