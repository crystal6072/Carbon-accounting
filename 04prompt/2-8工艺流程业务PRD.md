## 文档结构（必须包含以下章节）

### 1. 需求概述

- 需求目标（3～5 条可验证目标）
- In Scope / Out of Scope（明确：无审核流；**导入 / 导出 / 删除 / 版本管理是否支持必须写清**）
- 涉及角色（专业配置人员维护平台级、组织管理员维护组织自建 —— 对齐方案 §7.2）
- 影响范围（下游：产品信息库、核算项目 P20 生命周期模型配置）

### 2. 用户与使用场景
每条含：触发条件、操作流程、预期结果
- S01 新建工艺流程（定义 + 装配工序明细）
- S02 编辑工艺流程（草稿 vs 已发布的可改范围）

### 3. 功能清单
| 模块 | 功能点 | 功能描述 | 优先级 |

### 4. 工艺流程装配规则（**本文核心章节**）
- 工序装配方式：只能引用「启用」状态的工序（与工序侧禁用规则一致）
- 顺序规则：工序顺序连续、不重复；同一工序是否允许重复出现（【待确认】）
- **衔接校验归属**：上游工序产出 = 下游工序投入的校验，在本模块做还是留到产品信息库（与产品信息 PRD §4 C5 划清边界，**不得两处都做或都不做**）
- 首尾规则：首道工序的投入应为原料/能源；末道工序的产出应为成品或中间品
- 「适用产品」口径（按上文推荐口径或【待确认】）
- 明细行数上限（与产品信息 PRD §4 C8 的「工艺 ≤5、每工艺工序 ≤50」对齐）
- 工序侧发生变更（禁用 / 新版本）时，本模块的联动表现

### 5. 版本与状态规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- 工艺流程编码 / 名称唯一性
- 版本号进位规则（结构性变更 vs 说明性变更）
- 已发布版本能否原地修改；被产品引用后是否转为完全只读
- 「启用 / 禁用」与「已发布」的关系（未发布的工艺能否被产品引用）
- 引用口径：产品引用的是「工艺流程 id + 版本号」还是最新版本（须与产品信息 PRD R-013 快照规则一致）
- 禁用 / 删除规则：被引用的工艺流程不可删除，禁用后不可被新产品选用
- 历史版本只读

### 6. 状态与操作矩阵
