# 模块文档套件整体输出 Prompt

> **适用场景**：为一个新业务模块（如采购订单）完整产出文档链路（业务上下文 → 业务流程推演 → 字段清单 → 业务 PRD → 用例数据推演 → 页面骨架 → Demo PRD → 前端原型）。
> **工作流参考**：先读 `06-产品方法论/QS-JXC 产品经理使用AI输出相关产出物的工作流与方法论.md` 和 `04-常用模版/README.md`（模板执行索引）。
> **核心原则**：一次只生成一个层次产物，不要同时输出全部文档。

---

## 任务模板

```
请为 [模块名] 生成文档套件。

按以下顺序，逐步输出，每完成一步等用户确认后再继续：

1. 业务上下文（业务背景、范围、关键决策）
2. 业务流程推演（规则层：场景、状态变化、数量流转、异常收口）
3. 字段清单（TSV）
4. 业务 PRD
5. 用例数据推演（实例验证层：固定数据跑通流程闭环）
6. 页面骨架（可选，页面结构不清楚时才做）
7. 前端 Demo PRD（列表页 / 新增编辑页 / 详情页）
8. 前端原型

输入材料（如有）：
- [业务背景 / 痛点 / 现状描述]
- [涉及角色和系统]
- [相关单据 PRD 路径]
- [字段清单或字段线索]

权威边界：
- 字段名称、类型、来源、枚举以字段清单 TSV 为准（详细稿未确认前，初稿只作临时输入）
- 状态、动作、业务规则以业务 PRD 为准，但不得与全局规则或跨单据流程冲突
- 跨角色流程以业务流程文件为准，跨单据处理以系统单据流程文件为准
- 用例数据推演依赖字段清单和业务 PRD，不得提前到字段清单之前做
- Demo PRD 是生成物，只翻译业务规则为页面表现，不创造新的字段、状态或动作
- 发现缺失或冲突时列出问题，不擅自补全为已确认事实

输出要求：
- 每步输出后暂停，先让用户确认再进入下一步
- 每步只输出该层次的产物，不提前写下游内容
- 完整业务流程、系统流程、字段表和页面细节只建立关联入口，不在当前产物中复制
- 完成后列出受影响的下游文档
```

## 为什么一次只做一个层次

同时生成所有文档看似省时，实际更容易把字段、规则和页面细节混在一起，导致下游文档反向发明业务规则。逐层确认可以让每份文件只承担自己的职责：字段清单管字段事实，业务 PRD 管业务约束，Demo PRD 管页面表现。
