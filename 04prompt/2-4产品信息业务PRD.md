## 文档结构（必须包含以下章节）

### 0. 文档基础信息
- 文档属性表（版本 V0.1、状态：草稿）、变更记录
- 关联链接：字段清单（产品信息 + 产品分类）、整体设计方案 v1.2
- 文档分工表（字段清单 / 业务 PRD / Demo PRD 各管什么）

### 1. 需求概述
- 需求背景：产品 = 产品基本信息 + 工艺 + 工序的组合，是碳足迹核算的对象载体；核算项目引用产品版本快照
- 需求目标（3～5 条可验证目标）
- In Scope / Out of Scope（明确：无审核流；**导入 / 导出 / 删除 / 复制新建版本是否支持必须写清**）
- 涉及角色（专业配置人员维护平台级、组织管理员维护组织自建 —— 对齐方案 §7.2 权限矩阵）
- 影响范围（下游：核算项目 P19 / P20、我的产品库 B2、报告）

### 2. 用户与使用场景
每条含：触发条件、操作流程、预期结果
- S01 新建产品（基本信息 + 组合工艺与工序）
- S02 编辑产品（未上架 vs 已上架的可改范围差异）
- S03 建立新版本（哪些变更触发新版本）
- S04 上架 / 下架
- S05 被核算项目引用后的锁定表现
- S06 查看产品详情与操作日志

### 3. 功能清单
| 模块 | 功能点 | 功能描述 | 优先级 |

覆盖：列表、查询、新增、编辑、查看、版本管理（新建版本、版本列表；版本对比可选并标优先级）、上下架、导入 / 导出（按结论）。

### 4. 产品与工艺、工序的组合规则（**本文核心章节**）
- 组合层级：产品 → 工艺 → 工序 的挂接方式与数量约束
- 工序顺序：同一工艺内是否有序、是否必须首尾相连（上游工序产出 = 下游工序投入）
- 投入产出流的维护归属：**必须与 §2.3 A1-8「工序管理」划清边界**，明确本模块是引用还是维护
- 组合校验：至少 1 个工艺、至少 1 个工序？末道工序的产出必须为成品？
- 组合变更对已引用产品版本的影响

### 5. 版本与上架规则（R-001 起）
每条含：触发条件、处理逻辑、例外策略。至少覆盖：
- 版本号规则与进位条件（V1.0 / V1.1 / V2.0 各对应什么变更）
- 「触发新版本」vs「原地修改」的判定清单
- 上架 / 下架与版本的关系；下架后对下游的影响（不可被新项目选择，历史引用保留）
- 被核算项目引用后锁定哪些字段（对齐方案 §4.9 不可变对象）
- 历史版本只读、不可删除
- 版本快照引用规则：项目引用的是「产品 id + 版本号」，禁止实时引用最新版本

### 6. 状态与操作矩阵
版本状态 × 使用状态 × 可用操作（编辑 / 新建版本 / 上架 / 下架 / 被引用）

### 7. 上下游与引用关系
| 方向 | 关联模块 | 引用字段 | 联动规则 |
至少含：产品分类（上游引用）、计量单位库（功能单位）、工艺流程库、工序管理、核算项目 P19 / P20（下游引用快照）、我的产品库

### 8. 待确认事项
Q01 起编号，与字段清单待确认项**交叉引用**，**不得偷换为已确认事实**
