# 竹木产品碳足迹系统政策合规要求分析

> 依据来源：`02全局背景/竹木_产品碳_政策背景.md`、`02全局背景/项目业务背景.md`、`02全局背景/项目需求边界.md`。  
> 说明：本文用于竹木产品碳足迹系统的政策合规需求分析，不替代正式标准条文、认证机构规则、法律意见或项目实施方案。由于当前材料多为政策和标准背景摘要，涉及标准细则的内容按【资料明确】【合理推断】【待确认】标注。

## 0 结论摘要

| 结论项 | 分析结论 | 判断类型 |
| :--- | :--- | :--- |
| 合规主线 | 竹木产品碳足迹系统应围绕“标准依据可配置、生命周期边界可选择、活动数据可追溯、因子版本可管理、碳固存口径可解释、报告披露可审核”建设。 | 【资料明确】 |
| 标准优先级 | 国内场景建议以 `GB/T 24067-2024` 为通用底座，叠加 `LY/T 3436-2025`、`T/CBIAS 2108-2025` 等木竹/竹木专项规则；认证场景按认监委试点规则和具体认证机构要求执行。 | 【合理推断】 |
| 不能统一口径的事项 | 生物源碳、碳储存抵扣、生命周期边界、回收收益、焚烧/填埋、GWP100、分配规则、报告披露粒度，在不同标准和场景下可能不同，系统不应写死唯一算法。 | 【资料明确】 |
| 对系统的核心影响 | 必须建设规则引擎、标准/PCR 库、因子库、数据质量分级、生命周期模型、证据附件、报告模板、审计追溯和版本快照。 | 【资料明确】 |
| 最大风险 | 若将竹木产品简单宣传为“负碳”，或将碳储存直接抵扣全部排放，可能导致认证不通过、客户不采信或绿色声明争议。 | 【合理推断】 |
| 待确认重点 | 首批产品品类、采用标准优先级、是否申请正式碳足迹标识认证、目标市场、PCR 版本、碳固存抵扣规则、废弃处置情景和因子采信清单仍需确认。 | 【待确认】 |

## 1 政策标准清单

### 1.1 国内政策与认证规则

| 政策或规则 | 发布/主管机构 | 适用范围 | 是否强制 | 对竹木产品适用性 | 对系统的影响 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `《关于加快建立产品碳足迹管理体系的意见》`（发改环资〔2023〕1529号） | 国家发展改革委等部门 | 产品碳足迹核算规则、背景数据库、碳标识认证、应用场景、国际互认 | 非直接强制，属于国家制度建设和政策导向 | 木竹产品已进入专项标准和认证试点语境，适用性高 | 系统需支持标准规则库、背景数据库、碳标签、国际口径扩展和持续更新 |
| `《2030年前碳达峰行动方案》` | 国务院 | 碳达峰行动、重点产品全生命周期碳足迹标准探索 | 非直接强制 | 作为产品碳足迹制度化的上位政策背景 | 系统需支持全生命周期核算，而非仅生产阶段碳排放 |
| `《产品碳足迹标识认证通用实施规则（试行）》` | 国家认监委 | 产品碳足迹标识认证试点 | 对申请认证和使用标识的企业构成约束；不申请时通常不直接强制 | 木制品中人造板、木质地板已进入试点目录，竹木地板、板材类产品需重点关注 | 需支持认证材料包、报告模板、标识数据、第三方核查视图、证据追溯和版本冻结 |
| `《产品碳足迹标识认证试点认证目录（第一批）》` | 市场监管总局、生态环境部、工业和信息化部等相关公开信息 | 试点认证产品目录 | 认证目录约束，非全行业强制 | 人造板、木质地板与竹木建材、地板、板材高度相关；具体产品需按目录和产品定义确认 | 产品主数据需维护认证目录映射、品类适配状态、标识适用范围 |

### 1.2 国内通用标准

| 标准名称 | 发布机构 | 适用范围 | 是否强制 | 对竹木产品适用性 | 对系统的影响 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `GB/T 24067-2024《温室气体 产品碳足迹 量化要求和指南》` | 国家标准化管理相关机构 | 所有产品碳足迹量化的通用要求和指南 | `GB/T` 推荐性国家标准，通常非强制；若被认证、合同、招标或监管引用，则成为项目约束 | 适用性高，是国内产品碳足迹核算底座，但需叠加木竹专项规则 | 需支持目的与范围、功能/声明单位、生命周期清单、结果解释、报告、评审和声明 |
| `GB/T 24040`、`GB/T 24044` | 国家标准化管理相关机构 | 生命周期评价原则、框架、要求和指南 | 推荐性标准；被引用时形成约束 | 适用性高，作为 LCA 方法基础 | 生命周期模型需支持目标范围、系统边界、清单分析、影响评价和结果解释 |
| `GB/T 32150`、`GB/T 32151` 系列 | 国家标准化管理相关机构 | 组织/行业温室气体核算相关要求 | 多为推荐性或行业管理参考，需按具体引用判断 | 可作为企业数据背景参考，不替代产品碳足迹 | 系统可引用企业能耗和组织排放数据，但结果需拆分到产品、批次、工序 |

### 1.3 木竹/竹木专项标准与行业规范

| 标准名称 | 发布机构 | 适用范围 | 是否强制 | 对竹木产品适用性 | 对系统的影响 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `LY/T 3436-2025《木竹产品碳足迹评价指南》` | 国家林业和草原局相关行业标准体系 | 木竹产品碳足迹评价 | `LY/T` 推荐性林草行业标准，通常非强制；被项目、认证或客户引用时构成约束 | 适用性很高，是木竹产品专项评价依据 | 需支持木竹产品生命周期阶段、碳储量、结果解释和报告要求；完整条文需补充核对 |
| `T/CBIAS 2108-2025《温室气体 产品碳足迹量化方法与要求 竹木产品》` | 相关行业协会/团体 | 竹木产品碳足迹量化方法与要求 | 团体标准，通常非强制；被合同、认证或平台规则引用时构成约束 | 适用性很高，特别适合竹木产品核算 | 需支持竹木产品核算步骤、数据质量、生物碳储量计算与报告；完整条文需补充核对 |
| 国家标准计划 `《温室气体 产品碳足迹量化方法与要求 木竹产品》` | 国家标准化管理相关机构 | 木竹产品产品碳足迹量化 | 当前状态需核实；正式发布前不宜作为强制依据 | 若发布，将成为更高优先级的木竹产品专项国家标准 | 标准库需支持“计划中/现行/废止/替代”状态和规则迁移 |
| 标书/行业规范中提及的木竹全生命周期服务规则 | 项目资料/行业服务方案 | 原料采伐、加工、运输、使用、废弃、碳固存、因子、上报、核查 | 项目内约束，是否强制取决于合同和验收 | 与本项目高度适配 | 需转化为系统需求、字段、流程、校验、报告和审计功能 |

### 1.4 国际标准、PCR 与外部规则

| 标准/规则 | 发布机构 | 适用范围 | 是否强制 | 对竹木产品适用性 | 对系统的影响 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `ISO 14067:2018` | ISO | 产品碳足迹量化国际标准 | 自愿性国际标准；国际客户、认证或合同指定时构成约束 | 出口、跨国客户披露、国际认证场景适用性高 | 需支持国际报告口径、功能单位、系统边界、数据质量、结果解释和评审要求 |
| `ISO 14040`、`ISO 14044` | ISO | LCA 原则、框架、要求和指南 | 自愿性国际标准；被引用时构成约束 | 适用性高，是国际 LCA 基础 | 生命周期建模需与国内 LCA 基础标准兼容 |
| `GHG Protocol Product Life Cycle Accounting and Reporting Standard` | WRI/WBCSD | 产品生命周期温室气体核算与报告 | 自愿性方法学；供应链 Scope 3 披露中常被客户指定 | 适合品牌商、供应链客户、跨企业数据交换 | 需支持供应链数据边界、数据质量说明、报告披露、客户数据导出 |
| `PAS 2050` | BSI 等 | 产品与服务生命周期温室气体评价 | 自愿性规范；历史项目或客户指定时适用 | 可能用于既有客户要求 | 需作为可选规则集，不建议作为默认唯一口径 |
| `ISO 14025` | ISO | III 型环境声明、EPD | 自愿性声明标准；进入 EPD 体系时构成约束 | 竹木建材、地板、板材做 EPD 时适用 | 需支持第三方验证、声明模板、数据模块、有效期和公开披露 |
| `EN 15804+A2` | CEN | 建筑产品 EPD 核心规则 | 欧盟建筑产品 EPD 场景强相关；是否强制取决于市场和项目 | 竹地板、木竹板材、建筑装饰材料适用性高 | 需支持 A1-A3、A4-A5、B、C、D 等模块化生命周期阶段和边界外收益单列 |
| `ISO 21930` | ISO | 建筑产品和服务环境声明 | 建筑产品 EPD 国际场景适用 | 竹木建材适用 | 需支持建筑产品生命周期模块、场景假设和报告披露 |
| `EN 15978` | CEN | 建筑全生命周期评价 | 建筑层面评价规则，非单一产品 PCR | 竹木产品作为建筑材料进入建筑整体评价时相关 | 产品数据需能输出给建筑 LCA/EPD 使用 |
| `EUDR` | 欧盟 | 无毁林产品尽责管理 | 欧盟法规；具体适用取决于产品、海关编码、材料构成和市场 | 木材相关产品需重点关注；竹、藤等具体适用需核实 | 原料来源、地块、合法采伐、供应链尽责材料可能需要扩展；不等同产品碳足迹规则 |
| `ESPR`、`PEF`、数字产品护照 | 欧盟 | 可持续产品、环境足迹、产品信息披露 | 适用性和强制程度需按法规进展和产品类别确认 | 出口型竹木产品中长期相关 | 系统需预留产品环境数据结构、规则扩展、数字披露接口 |

## 2 适用性分析

| 场景 | 推荐采用规则 | 适用性判断 | 系统处理建议 |
| :--- | :--- | :--- | :--- |
| 国内企业内部核算 | `GB/T 24067-2024` + `GB/T 24040/24044` + 木竹专项标准 | 适合形成国内通用、可解释的产品碳足迹结果 | 默认提供国内规则集，支持木竹产品生命周期模板和碳固存单独列示 |
| 国内碳足迹标识认证 | 认监委试点规则 + 认证目录 + 对应产品标准/PCR | 适合人造板、木质地板等目录产品；竹木相近产品需确认目录归属 | 增加认证项目类型、认证目录映射、认证材料包、报告冻结和核查视图 |
| 木竹/竹木行业专项核算 | `LY/T 3436-2025`、`T/CBIAS 2108-2025` | 对竹木产品最贴合，特别是生物碳、碳储存、含水率、绝干质量等 | 建立木竹专项规则集和参数库，完整条文补齐后固化字段和公式 |
| 国际客户产品碳足迹披露 | `ISO 14067`、`GHG Protocol Product Standard` | 适合出口、跨国品牌供应链、客户 Scope 3 采集 | 支持中英文报告、客户模板、数据质量声明、因子来源说明 |
| 建筑产品 EPD | `ISO 14025`、`EN 15804+A2`、`ISO 21930`、具体 PCR | 适合竹地板、木竹板材、装饰建材 | 生命周期阶段需按模块化结构配置，D 模块收益不得与 A-C 模块强行合并 |
| 欧盟绿色贸易/可持续披露 | `EUDR`、`ESPR`、`PEF`、数字产品护照 | 与碳足迹不完全等同，但会影响原料溯源、产品信息披露和客户审查 | 系统可扩展原料合规、供应链尽责、数字产品信息字段，不应混同为碳足迹算法 |

## 3 核算规则对比

### 3.1 功能单位要求

| 规则类别 | 要求或倾向 | 对竹木产品的适用性 | 系统配置建议 |
| :--- | :--- | :--- | :--- |
| `GB/T 24067` / `ISO 14067` | 需定义功能单位或声明单位，作为结果归一化基础 | 适用于所有竹木产品；不同产品功能差异大 | 产品品类需配置默认功能单位，如 `1 m2 地板`、`1 m3 板材`、`1 件家具部件`、`1 kg 包装制品` |
| 木竹/竹木专项标准 | 预计更关注竹木产品规格、材质、含水率、密度、绝干质量等 | 适用性高，能反映木竹材料特性 | 功能单位需绑定规格、含水率口径、使用寿命、木竹材料占比 |
| 建筑产品 EPD/PCR | 通常由具体 PCR 定义功能单位或声明单位 | 竹地板、板材、建筑材料适用 | 系统需按 PCR 固化功能单位，禁止用户随意修改已选 PCR 的核心单位 |
| 客户披露/供应链数据 | 可能使用质量、数量、采购金额、产品件数等声明单位 | 适合客户要求的快速披露 | 允许建立客户模板，但报告中必须说明不是完整功能单位评价时的限制 |

### 3.2 系统边界要求

| 边界类型 | 适用场景 | 合规关注点 | 系统配置建议 |
| :--- | :--- | :--- | :--- |
| 摇篮到坟墓 | 完整产品碳足迹、认证、对外披露 | 覆盖原料获取、生产、运输、使用、废弃处置 | 作为完整 LCA 模板，缺失阶段需给出数据质量说明和边界排除理由 |
| 摇篮到大门 | B2B 半成品、材料、供应链数据、建材 A1-A3 | 不覆盖使用和废弃，不能等同完整生命周期 | 报告标题和标签必须明确边界，避免被误读为全生命周期结果 |
| 大门到大门 | 企业内部工序、外协加工、阶段核算 | 只能反映局部过程，不适合作为完整产品碳足迹 | 系统中作为过程模块或工序核算，不应默认生成完整碳标签 |
| 建筑产品模块化边界 | EPD/PCR 场景 | A1-A3、A4-A5、B、C、D 模块需分别披露 | 生命周期阶段模型需支持模块编码、场景假设和边界外收益单列 |

### 3.3 生命周期阶段要求

| 生命周期阶段 | 竹木产品关键数据 | 合规要求 | 系统影响 |
| :--- | :--- | :--- | :--- |
| 原料获取/采伐 | 林地信息、原料类型、采伐量、出材率、集材距离、采伐设备油耗、采伐损耗 | 需明确原料来源、边界和生物质流向 | 建立原料批次、林地/供应商、采伐活动数据和凭证附件 |
| 生产加工 | 工序、能耗、蒸汽、燃料、辅料、胶黏剂、涂料、损耗、边角料 | 需记录工序级活动数据并处理共线分摊 | 建立工艺路线、工序能耗、辅料台账、损耗和分配规则 |
| 运输仓储 | 原料运输、半成品调拨、成品配送、距离、方式、载重、装载率、油耗、仓储能耗 | 运输数据缺口是项目重点痛点 | 建立运输台账、物流批次和距离/装载率校验 |
| 使用阶段 | 设计寿命、维护周期、翻新次数、清洁/养护材料、使用能耗、长期碳储存 | 是否纳入取决于边界和 PCR | 使用阶段需场景化配置，不能默认所有竹木产品都有相同使用排放 |
| 废弃处置/循环 | 回收、再利用、焚烧、填埋、堆肥、能源回收、运输 | 生物源 CO2、CH4、回收收益处理口径差异大 | 建立处置情景库，按标准规则分别计算和列示 |

### 3.4 数据质量要求

| 数据质量维度 | 合规要求 | 系统功能要求 |
| :--- | :--- | :--- |
| 数据来源 | 优先使用实测数据、企业原始台账、供应商数据和权威数据库；使用估算值需说明 | 活动数据需记录来源类型、来源系统、凭证、填报人、审核人 |
| 时间代表性 | 数据需匹配核算期、生产批次或报告周期 | 每条活动数据和因子需维护生效日期、数据期间、适用批次 |
| 地理代表性 | 能源、运输、区域工艺和地方因子需匹配区域 | 因子库需维护国家/地区、省市、适用区域和区域修正系数 |
| 技术代表性 | 因子和数据需匹配实际工艺、设备、材料和能源类型 | 产品工艺库需与活动数据、因子和计算模型关联 |
| 完整性 | 生命周期阶段、投入产出、排放源和排除项需说明 | 核算任务需提供完整性校验、缺失项提示和排除项说明 |
| 不确定性 | 因子和估算数据需说明不确定性或质量等级 | 建立数据质量等级、置信度、不确定性字段和报告披露 |
| 可追溯性 | 结果需追溯至活动数据、因子、规则、版本和操作记录 | 建立审计日志、计算明细、版本快照和只读核查视图 |

### 3.5 排放因子要求

| 因子来源 | 适用场景 | 合规风险 | 系统要求 |
| :--- | :--- | :--- | :--- |
| 国家标准/国家数据库 | 国内核算和认证优先 | 版本过期或适用条件不匹配 | 因子版本、来源文件、适用范围、启停状态必须可追溯 |
| 行业标准/木竹专用因子 | 木竹工艺、原料、碳储存参数 | 完整条文和采信范围需确认 | 设置木竹专用因子分类和专家审核流程 |
| IPCC 指南 | 燃料燃烧、废弃处置、CH4/N2O 等 | GWP100 版本差异会影响结果 | GWP 版本作为规则集参数，不能写死单一值 |
| 地方因子/区域系数 | 区域电力、物流、地方产业数据 | 权威性和更新频率需确认 | 维护区域、来源、有效期、数据质量等级 |
| 供应商碳足迹数据 | 上游物料、胶黏剂、涂料、包装、外协 | 供应商边界、数据质量和第三方认证不清 | 供应商数据需记录边界、报告期、验证状态和依据文件 |
| 商业数据库/公开文献 | 数据缺失补充 | 认证机构可能不采信或要求说明 | 需标记为候选/估算数据，并在报告中披露来源和限制 |

### 3.6 分配规则

| 分配事项 | 常见规则 | 适用风险 | 系统配置建议 |
| :--- | :--- | :--- | :--- |
| 共线生产能耗 | 按质量、产量、面积、体积、产值、工时、设备运行时间分配 | 不同规则导致产品结果差异大 | 核算任务必须记录分配方法、分配基准、分配比例和选择原因 |
| 联产品/副产品 | 物理关系优先，其次经济分配；具体按标准/PCR | 边角料、木屑、竹粉、余热利用归属不清 | 建立联产品与副产品台账，支持多种分配规则和规则优先级 |
| 回收材料与循环收益 | 切断法、替代法、系统扩展、模块 D 单列等 | 不同 PCR 差异很大，不能强行合并 | 回收收益应按规则集配置，并在报告中单列披露 |
| 供应商物料碳足迹 | 按采购量、批次、物料规格引用 | 供应商数据边界不同会影响可比性 | 物料因子需绑定供应商、物料编码、报告边界和有效期 |

### 3.7 生物源碳和碳储存处理要求

| 处理事项 | 可能规则 | 对竹木产品影响 | 系统建议 |
| :--- | :--- | :--- | :--- |
| 生物碳储量计算 | 按木竹材料质量、绝干质量、含碳率、木竹材料占比计算 | 是竹木产品区别于一般工业品的核心 | 建立含碳量检测库、含水率/绝干质量换算、材质占比字段 |
| 碳储存列示 | 单独列示、并列展示、按产品寿命说明 | 有助于表达竹木长期固碳，但不等于自动抵扣 | 默认单独列示碳储存，不默认抵扣总排放 |
| 是否抵扣总碳足迹 | 不同标准和 PCR 可能不同 | 直接影响最终结果和宣传口径 | 作为规则集参数配置：不抵扣、抵扣、延迟排放折算、单列说明 |
| 生物源 CO2 | 焚烧或降解释放时可能不计入总量但需单独列示 | 废弃阶段结果敏感 | 生物源 CO2、化石 CO2、CH4、N2O 分开核算和展示 |
| 负排放表达 | 需谨慎，通常需明确标准依据和边界 | 存在绿色声明风险 | 系统需限制“负碳”标签使用，要求标准依据、审核和披露说明 |

### 3.8 土地利用变化要求

| 事项 | 合规关注点 | 竹木产品适用性 | 系统建议 |
| :--- | :--- | :--- | :--- |
| 直接土地利用变化 | 林地/竹林转化、种植方式变化可能带来碳库变化 | 原料来自林地、竹林时需关注 | 原料来源需预留地块、经营方式、土地利用类型、证明文件字段 |
| 间接土地利用变化 | 多数产品碳足迹标准处理差异较大 | 当前资料未明确要求 | 不作为默认计算项，作为可选规则和待确认事项 |
| 无毁林合规 | `EUDR` 与碳足迹不同，但影响木材类出口产品 | 木材相关产品适用性需按编码和材料确认；竹材需核实 | 原料溯源模块需预留合法来源、地理位置、供应链尽责文件 |
| 土地碳储量变化 | 是否纳入取决于标准/PCR 和数据可得性 | 对原料阶段可能重要 | 标准库中单独配置是否纳入、计算方法、所需字段和默认排除说明 |

### 3.9 回收、焚烧和填埋处理规则

| 处置方式 | 合规处理要点 | 规则差异 | 系统建议 |
| :--- | :--- | :--- | :--- |
| 回收/再利用 | 需明确回收率、再利用路径、替代材料和收益归属 | 有的规则将收益计入系统内，有的规则在边界外单列 | 支持切断法、替代法、模块 D 单列，不强行汇总 |
| 再生材料使用 | 需说明再生料比例、前序负担承担方式 | PCR 差异大 | 产品 BOM 需记录再生料比例和核算方法 |
| 焚烧 | 需区分化石碳、生物源 CO2、CH4、N2O、能源回收 | 生物源 CO2 是否计入总量存在差异 | 废弃模型需分气体、分来源、分能源回收收益列示 |
| 填埋 | 需考虑降解比例、CH4 生成、捕集、氧化、长期储存 | 参数不确定性较高 | 建立填埋情景参数库，记录 GWP 版本和数据质量 |
| 堆肥/生物降解 | 需考虑生物源碳释放、CH4/N2O | 当前资料未明确细则 | 作为处置情景可配置，报告中说明假设 |

## 4 强制要求

> 这里的“强制”不是指所有竹木企业天然必须执行，而是指一旦选择对应合规目标、认证目标、客户合同或项目验收口径，系统必须满足的约束。

| 要求 | 触发条件 | 系统必须支持 |
| :--- | :--- | :--- |
| 标准依据明确 | 任何产品碳足迹核算任务 | 选择标准/规则集/PCR 版本，并随核算结果冻结 |
| 功能单位或声明单位明确 | 出具报告、标签、客户披露 | 产品、规格、单位、结果归一化口径必须完整 |
| 系统边界明确 | 所有核算任务 | 边界类型、纳入阶段、排除项、排除理由必须记录 |
| 生命周期阶段可追溯 | 全生命周期或认证核算 | 每阶段活动数据、因子、计算结果可查看 |
| 数据来源可证明 | 认证、上报、第三方核查 | 原始台账、供应商报告、发票、检测报告、系统接口记录等附件可上传和追溯 |
| 因子来源和版本可追溯 | 所有核算任务 | 因子来源、版本、适用条件、地区、有效期、启停状态必须保存 |
| 分配规则可解释 | 共线、联产、副产品、共享能耗场景 | 分配方法、分配基准、分配比例、计算明细必须记录 |
| 生物碳口径单独披露 | 涉及木竹材料碳储存或废弃释放 | 生物碳、碳储存、生物源 CO2 不得与化石排放混淆 |
| 报告版本冻结 | 对外披露、认证、上报 | 报告生成时冻结活动数据、因子、规则、结果和附件快照 |
| 审核留痕 | 报告发布、上报、认证材料提交 | 审核人、审核意见、驳回/修改记录、时间戳必须保留 |

## 5 可配置要求

| 可配置项 | 为什么不能写死 | 建议配置方式 |
| :--- | :--- | :--- |
| 标准/规则集 | 国内标准、木竹专项、ISO、EPD、客户模板口径不同 | 建立 `rule_set`，包含标准版本、适用品类、边界、因子优先级、报告模板 |
| PCR | 不同产品类别规则定义功能单位、边界、分配和披露不同 | 建立 PCR 库，绑定产品品类、功能单位、生命周期阶段和强制字段 |
| 生命周期边界 | 摇篮到坟墓、摇篮到大门、大门到大门用途不同 | 核算任务选择边界模板，并自动带出必填阶段和排除项 |
| GWP100 版本 | 不同标准可能采用不同 IPCC 版本，甲烷取值存在差异 | GWP 表版本化管理，规则集指定默认 GWP 版本 |
| 因子优先级 | 国家、地方、行业、供应商、商业数据库采信顺序不同 | 规则集配置因子来源优先级和禁用来源 |
| 分配规则 | 共线、联产、副产品适用物理或经济分配不同 | 产品/工序/物料层配置默认分配规则，任务可按权限调整 |
| 碳固存抵扣 | 标准差异和披露风险较大 | 配置为“不抵扣仅列示/抵扣/延迟排放折算/按 PCR” |
| 生物源 CO2 | 是否计入总量差异大 | 分气体、分来源计算，报告模板决定计入或单列 |
| 回收收益 | 不同规则可能系统扩展、替代法或模块 D 单列 | 处置情景配置收益处理方式，报告中单列 |
| 土地利用变化 | 标准/PCR 和数据可得性不确定 | 设置为可选模块，启用时要求地块和土地类型数据 |
| 报告披露模板 | 认证、客户、内部管理、EPD 披露粒度不同 | 模板库按场景配置章节、指标、图表、声明和附件清单 |

## 9 合规风险

| 风险 | 触发原因 | 影响 | 建议控制 |
| :--- | :--- | :--- | :--- |
| 标准口径混用 | 同一报告同时混用国内标准、ISO、EPD、客户模板且未说明 | 结果不可比，认证或客户不采信 | 一个核算任务只能绑定一个主规则集，其他口径作为转换或补充报告 |
| 碳储存抵扣不当 | 将木竹产品碳储量直接抵扣全部排放或宣传为“负碳” | 绿色声明争议、认证风险 | 默认单列碳储存，抵扣必须有标准/PCR依据和审核 |
| 生物源 CO2 与化石排放混淆 | 废弃焚烧、填埋释放未分来源和气体 | 废弃阶段结果失真 | 分气体、分来源、分阶段计算和披露 |
| 因子不被采信 | 使用过期、地区不匹配、来源不明或商业数据库因子 | 第三方核查驳回 | 因子审核、版本管理、来源等级和适用条件校验 |
| 数据质量不足 | 运输、供应商、使用、废弃数据缺失或大量估算 | 报告可信度下降 | 数据质量评分、缺失预警、估算说明和人工确认 |
| PCR 缺失 | 产品品类没有明确 PCR 或认证目录归属不清 | 报告边界、功能单位和分配规则不稳定 | 标记为“无适用 PCR/待确认”，不生成正式认证标签 |
| 回收收益重复计算 | 同时在产品系统内和边界外收益中计算 | 碳足迹被低估 | 规则集限制收益处理方式，模块 D 或边界外收益单列 |
| 供应商数据边界不一致 | 上游报告边界、时间、功能单位不同 | 物料碳足迹不可比 | 供应商数据需记录边界、单位、报告期、验证状态并做换算校验 |
| 对外披露过度 | 二维码或标签公开企业敏感数据或未审核结果 | 商业泄密、合规纠纷 | 披露字段白名单、脱敏、水印、发布审批 |
| 政策变化 | 国家标准、试点目录、欧盟规则、客户要求更新 | 历史模板和规则失效 | 标准状态跟踪、变更预警、规则版本迁移 |

| 是否存在具体 PCR | PCR 决定功能单位、边界、分配、废弃和披露规则 | PCR 库、生命周期模板 |
| 碳固存是否抵扣最终结果 | 直接影响产品碳足迹总量、标签和宣传 | 碳固存模型、报告模板 |
| 生物源 CO2、CH4、N2O 处理口径 | 影响废弃焚烧、填埋和堆肥结果 | 废弃处置模型、GWP 参数 |
| 土地利用变化是否纳入 | 影响原料阶段数据采集和原料溯源深度 | 原料台账、林地信息 |
| 因子采信清单 | 决定国家、行业、地方、供应商、商业数据库的优先级 | 因子库、因子匹配 |
| 是否面向出口或国际客户 | 决定是否兼容 ISO、GHG Protocol、EPD、EN 15804、EUDR、ESPR | 国际模板、披露接口 |
| 供应商数据验证要求 | 决定上游碳足迹数据能否直接引用 | 供应商碳足迹库、审核流程 |
| 废弃处置默认情景 | 回收率、焚烧率、填埋参数直接影响结果 | 处置情景库、报告假设 |
| 报告公开范围 | 决定二维码、碳标签、客户报告展示哪些数据 | 披露控制、权限、脱敏 |
| 第三方核查流程 | 决定核查角色、审计文件包、问题整改闭环 | 审核验证、审计视图 |

## 11 系统建设建议

| 建议 | 说明 |
| :--- | :--- |
| 以规则集驱动核算 | 不把某一标准写死在代码中，所有关键口径由规则集、PCR 和版本控制驱动。 |
| 先做国内通用 + 木竹专项 | MVP 可优先支持 `GB/T 24067-2024`、`GB/T 24040/24044`、`LY/T 3436-2025`、`T/CBIAS 2108-2025` 的结构化规则。 |
| 将碳储存默认单列 | 在未确认抵扣规则前，碳储存、生物源 CO2、循环利用收益默认单独列示，避免披露风险。 |
| 报告与结果快照不可变 | 对外报告、标签、上报材料一旦发布，必须冻结数据、因子、规则和计算过程。 |
| 建立数据质量门槛 | 报告发布或认证材料提交前，应检查关键数据完整性、估算比例、因子等级和附件完整率。 |
| 保留国际扩展位 | 对出口、EPD、建筑产品和欧盟规则，先在数据结构和规则引擎中预留模块，不在一期强行做全量实现。 |
